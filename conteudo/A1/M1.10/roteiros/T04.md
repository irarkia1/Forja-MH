# M1.10.T04 — WebSocket

> O HTTP do T01 tem uma limitação que todo painel de IoT esbarra: **o servidor não fala primeiro**. Para mostrar a temperatura mudando na tela, o navegador teria de perguntar a cada segundo — e pagar, a cada pergunta, centenas de bytes de cabeçalho. O **WebSocket** (RFC 6455) resolve isso aproveitando a própria conexão HTTP: uma requisição pede para "trocar de protocolo", o servidor aceita com **101 Switching Protocols**, e a partir daí o mesmo TCP vira um **canal bidirecional de mensagens**, com quadros de 2 a 14 bytes de cabeçalho. É o que o navegador tem de mais próximo de um socket, e por isso é também o transporte do **MQTT no navegador** (T02, T09). Você vai calcular o aceite do handshake, montar quadros à mão, servir uma página com WebSocket a partir do ESP32 e decidir quando WebSocket, SSE, polling ou MQTT é a escolha certa.

## Ao final você consegue
- Descrever o handshake de abertura do WebSocket da RFC 6455 (Upgrade, Connection, Sec-WebSocket-Key, Sec-WebSocket-Accept, subprotocolos) e calcular o valor de aceitação.
- Decodificar e montar quadros WebSocket (FIN, opcode, bit de máscara, comprimento de 7, 16 e 64 bits, chave de mascaramento) e explicar fragmentação e os quadros de controle ping, pong e close.
- Escrever um servidor WebSocket no ESP32 com esp_http_server e clientes com esp_websocket_client e Python websockets para atualizar uma página em tempo real.
- Usar MQTT sobre WebSocket no navegador e comparar WebSocket, HTTP com polling, long polling, Server-Sent Events e MQTT para empurrar dados ao usuário.

## Resumo
**1. Por que WebSocket.** Para um navegador receber dados "empurrados" pelo servidor havia gambiarras: **polling** (pergunta a cada N segundos: atraso de até N e um ciclo HTTP inteiro por pergunta, mesmo sem novidade), **long polling** (o servidor segura a resposta até ter novidade; cada novidade custa uma nova requisição) e **streaming** HTTP. O WebSocket (2011) dá ao navegador uma conexão **full-duplex** e **orientada a mensagens**, que começa como HTTP — passa por proxies e firewalls nas portas 80/443 — e depois abandona o HTTP. Esquemas: `ws://` (porta 80) e `wss://` (sobre TLS, porta 443; o único aceitável fora do laboratório).

**2. O handshake de abertura** (*Opening Handshake*). O cliente manda um GET comum com cabeçalhos especiais:

```
GET /ws HTTP/1.1
Host: 192.168.0.50
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ==
Sec-WebSocket-Version: 13
Sec-WebSocket-Protocol: mqtt              ← opcional: subprotocolo pedido
```

O servidor responde:

```
HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Accept: s3pPLMBiTxaQ9kYGzzhZRbK+xOo=
Sec-WebSocket-Protocol: mqtt
```

- **Sec-WebSocket-Key**: 16 bytes aleatórios em base64, novos a cada conexão.
- **Sec-WebSocket-Accept** = base64( SHA-1( chave + `258EAFA5-E914-47DA-95CA-C5AB0DC85B11` ) ). O GUID é uma constante fixa da RFC. Não é segurança: é a prova de que o servidor **entende WebSocket** (um servidor HTTP comum, ou um cache, não produziria esse valor).
- **Subprotocolo**: o que vai dentro das mensagens (`mqtt`, por exemplo). O servidor escolhe um dos oferecidos ou nenhum.
- Qualquer resposta diferente de 101 significa que o WebSocket não abriu (um 401 pede autenticação; um 403 recusa a origem).
- O navegador manda o cabeçalho **Origin**: o servidor deve conferi-lo, senão qualquer página da internet pode abrir um WebSocket para o seu dispositivo usando o navegador do usuário (*cross-site WebSocket hijacking*).

**Exemplo resolvido 1 (aceite).** Chave do exemplo da RFC: `dGhlIHNhbXBsZSBub25jZQ==`. Concatena-se o GUID, calcula-se o SHA-1 (20 bytes: `b3 7a 4f 2c c0 62 4f 16 90 f6 46 06 cf 38 59 45 b2 be c4 ea`) e codifica-se em base64: **`s3pPLMBiTxaQ9kYGzzhZRbK+xOo=`** (28 caracteres: 20 bytes em base64 sempre dão 28). Conferido no `ws_quadro.py` da seção 7, que também abre uma conexão real e compara o aceite recebido com o calculado.

**3. O quadro** (*Base Framing Protocol*):

```
byte 0:  FIN(1) RSV1-3(3) opcode(4)
byte 1:  MASK(1) comprimento(7)
         [comprimento estendido: 2 bytes se 126, 8 bytes se 127]
         [chave de máscara: 4 bytes, se MASK = 1]
         payload
```

- **opcode**: 0x0 continuação, **0x1 texto** (UTF-8 obrigatório), **0x2 binário**, **0x8 close**, **0x9 ping**, **0xA pong**.
- **Comprimento**: 0–125 no próprio byte 1; **126** → os 2 bytes seguintes trazem o tamanho (até 65 535); **127** → os 8 bytes seguintes (64 bits). Sempre na menor forma.
- **Máscara** (*Client-to-Server Masking*): **todo quadro do cliente para o servidor é mascarado** com 4 bytes aleatórios (payload[i] XOR chave[i mod 4]); quadros do servidor **não** são. Não é sigilo (a chave vai junto): impede que um atacante faça o navegador emitir bytes previsíveis que envenenem caches e proxies intermediários (*Attacks On Infrastructure*). Um servidor deve fechar a conexão se receber quadro de cliente sem máscara.
- Cabeçalho: **2 bytes** (servidor, até 125 bytes de payload) a **14 bytes** (cliente, payload acima de 64 kB: 2 + 8 + 4).

**Exemplo resolvido 2 (quadros da RFC).** O texto "Hello" do servidor: `81 05 48 65 6C 6C 6F` (FIN + texto, comprimento 5, sem máscara): **7 bytes**. Do cliente, com a chave `37 FA 21 3D`: `81 85 37 FA 21 3D 7F 9F 4D 51 58` — o 0x85 é MASK + 5, e `7F` = `48` XOR `37`: **11 bytes**. Um binário de 256 bytes do servidor: `82 7E 01 00` + 256 bytes = **260 bytes**. Um de 65 536 bytes: `82 7F 00 00 00 00 00 01 00 00` + dados (o comprimento não cabe em 16 bits).

**4. Fragmentação e controle.**
- **Fragmentação** (*Fragmentation*): uma mensagem grande pode ir em vários quadros: o primeiro com o opcode (texto ou binário) e FIN = 0, os do meio com opcode 0 (continuação) e FIN = 0, o último com opcode 0 e FIN = 1. Quadros de controle podem aparecer **entre** os fragmentos.
- **Quadros de controle**: payload de no máximo **125 bytes** e nunca fragmentados.
- **Ping/pong**: quem recebe um ping responde pong com o mesmo payload. Serve de **keepalive** (o mesmo problema de NAT e de conexão morta do T02) e de medida de latência. Um pong não solicitado é permitido (heartbeat unilateral).
- **Close** (*Closing Handshake*): payload com **código de 2 bytes** e motivo em UTF-8; o outro lado responde close e o TCP é fechado. Códigos (*Status Codes*): **1000** normal, **1001** saindo (página fechada, servidor reiniciando), **1002** erro de protocolo, **1003** tipo de dado não aceito, **1008** violação de política, **1009** mensagem grande demais, **1011** erro interno; **1006** nunca vai no fio: é o que a aplicação vê quando a conexão caiu sem close.

**5. O ESP32 como servidor WebSocket.** O `esp_http_server` (T01) aceita WebSocket com `CONFIG_HTTPD_WS_SUPPORT=y` e `.is_websocket = true` na rota. O mesmo servidor entrega a página HTML (em `/`) e o canal (`/ws`): o navegador abre a página e o JavaScript conecta de volta. Pontos de projeto:
- **Receber**: `httpd_ws_recv_frame` com `max_len = 0` lê só o tamanho; depois aloca e lê o payload. Limite o tamanho aceito.
- **Enviar fora do tratador** (a difusão periódica): o envio tem de rodar na tarefa do servidor; use `httpd_queue_work` e, dentro dela, `httpd_ws_send_frame_async`. Para achar os clientes: `httpd_get_client_list` e `httpd_ws_get_fd_info` (só os que são WebSocket).
- **Limites**: `HTTPD_DEFAULT_CONFIG()` tem 7 sockets; cada aba de navegador aberta ocupa um. Para mais, ajuste `max_open_sockets` (e o `CONFIG_LWIP_MAX_SOCKETS`).

Compilado no ESP-IDF v5.5 e **executado no QEMU** (ESP32 emulado com Ethernet `open_eth` e a porta 80 redirecionada para a 8080 do PC):

```c
/* ws_painel.c — página com WebSocket servida pelo ESP32 (esp_http_server):
 * GET / entrega o HTML; /ws recebe comandos e difunde uma leitura por segundo a todos os clientes */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include "esp_http_server.h"
#include "esp_log.h"
#include "esp_timer.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

static const char *TAG = "ws";
static httpd_handle_t srv;
static int rele;

static const char PAGINA[] =
    "<!doctype html><meta charset=utf-8><title>Forja</title>"
    "<h1>Temperatura: <span id=t>--</span> °C</h1>"
    "<button onclick=\"ws.send(JSON.stringify({rele:1}))\">liga</button>"
    "<button onclick=\"ws.send(JSON.stringify({rele:0}))\">desliga</button>"
    "<script>const ws=new WebSocket(`ws://${location.host}/ws`);"
    "ws.onmessage=e=>{document.getElementById('t').textContent=JSON.parse(e.data).t};"
    "ws.onclose=()=>setTimeout(()=>location.reload(),3000);</script>";

static esp_err_t get_pagina(httpd_req_t *req)
{
    httpd_resp_set_type(req, "text/html");
    return httpd_resp_send(req, PAGINA, HTTPD_RESP_USE_STRLEN);
}

/* Chamado no handshake (método GET) e depois a cada quadro recebido. */
static esp_err_t ws_tratar(httpd_req_t *req)
{
    if (req->method == HTTP_GET) {
        ESP_LOGI(TAG, "handshake concluído, socket %d", httpd_req_to_sockfd(req));
        return ESP_OK;
    }
    httpd_ws_frame_t q = { .type = HTTPD_WS_TYPE_TEXT };
    esp_err_t r = httpd_ws_recv_frame(req, &q, 0);          /* max_len 0: só lê o tamanho */
    if (r != ESP_OK || q.len == 0 || q.len > 128) return r;
    uint8_t *buf = calloc(1, q.len + 1);
    if (buf == NULL) return ESP_ERR_NO_MEM;
    q.payload = buf;
    r = httpd_ws_recv_frame(req, &q, q.len);
    if (r == ESP_OK && q.type == HTTPD_WS_TYPE_TEXT) {
        ESP_LOGI(TAG, "comando: %s", (char *)buf);
        if (strstr((char *)buf, "\"rele\":1")) rele = 1;      /* num produto: cJSON e validação (T05) */
        else if (strstr((char *)buf, "\"rele\":0")) rele = 0;
    }
    free(buf);
    return r;
}

/* Difusão: o envio tem de acontecer na tarefa do servidor, por isso httpd_queue_work. */
typedef struct { int fd; char txt[48]; } envio_t;

static void enviar_um(void *arg)
{
    envio_t *e = arg;
    httpd_ws_frame_t q = { .final = true, .type = HTTPD_WS_TYPE_TEXT,
                           .payload = (uint8_t *)e->txt, .len = strlen(e->txt) };
    httpd_ws_send_frame_async(srv, e->fd, &q);
    free(e);
}

static void difundir(const char *txt)
{
    int fds[CONFIG_LWIP_MAX_SOCKETS];
    size_t n = sizeof fds / sizeof fds[0];
    if (httpd_get_client_list(srv, &n, fds) != ESP_OK) return;
    for (size_t i = 0; i < n; i++) {
        if (httpd_ws_get_fd_info(srv, fds[i]) != HTTPD_WS_CLIENT_WEBSOCKET) continue;
        envio_t *e = malloc(sizeof *e);
        if (e == NULL) continue;
        e->fd = fds[i];
        strlcpy(e->txt, txt, sizeof e->txt);
        if (httpd_queue_work(srv, enviar_um, e) != ESP_OK) free(e);
    }
}

static void tarefa_leituras(void *arg)
{
    for (int k = 0;; k++) {
        char txt[48];
        snprintf(txt, sizeof txt, "{\"t\":%.1f,\"rele\":%d}", 23.5 + (k % 5) * 0.1, rele);
        difundir(txt);
        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

void ws_painel_iniciar(void)
{
    httpd_config_t cfg = HTTPD_DEFAULT_CONFIG();
    ESP_ERROR_CHECK(httpd_start(&srv, &cfg));
    const httpd_uri_t pagina = { .uri = "/", .method = HTTP_GET, .handler = get_pagina };
    const httpd_uri_t ws = { .uri = "/ws", .method = HTTP_GET, .handler = ws_tratar, .is_websocket = true };
    httpd_register_uri_handler(srv, &pagina);
    httpd_register_uri_handler(srv, &ws);
    xTaskCreate(tarefa_leituras, "leituras", 3072, NULL, 4, NULL);
}
```

**6. O ESP32 como cliente: esp_websocket_client.** Para o dispositivo **abrir** um WebSocket com um servidor (uma API que só oferece `wss://`, um painel na nuvem), use o componente **espressif/esp_websocket_client** (declarado no `idf_component.yml`, como o CoAP do T03). Ele reconecta sozinho, manda ping no intervalo configurado e entrega eventos. Compilado no ESP-IDF v5.5 (componente 1.x) e **executado no QEMU** contra o servidor de eco em Python da seção 7:

```c
/* cliente_ws.c — cliente WebSocket no ESP32 (componente espressif/esp_websocket_client):
 * conecta, manda leituras em texto e trata o que o servidor manda de volta */
#include <stdio.h>
#include "esp_log.h"
#include "esp_websocket_client.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

static const char *TAG = "cliente_ws";

static void eventos(void *arg, esp_event_base_t base, int32_t id, void *dados)
{
    esp_websocket_event_data_t *d = dados;
    switch (id) {
    case WEBSOCKET_EVENT_CONNECTED:
        ESP_LOGI(TAG, "conectado");
        break;
    case WEBSOCKET_EVENT_DISCONNECTED:
        ESP_LOGW(TAG, "desconectado; o cliente reconecta sozinho");
        break;
    case WEBSOCKET_EVENT_DATA:
        if (d->op_code == 0x1)                              /* texto; 0x9/0xA são ping/pong */
            ESP_LOGI(TAG, "recebido: %.*s", d->data_len, (const char *)d->data_ptr);
        break;
    case WEBSOCKET_EVENT_ERROR:
        ESP_LOGE(TAG, "erro");
        break;
    default:
        break;
    }
}

void cliente_ws_demo(const char *uri)
{
    esp_websocket_client_config_t cfg = {
        .uri = uri,                                         /* "wss://..." com TLS e .cert_pem */
        .reconnect_timeout_ms = 5000,
        .network_timeout_ms = 5000,
        .ping_interval_sec = 20,
    };
    esp_websocket_client_handle_t c = esp_websocket_client_init(&cfg);
    esp_websocket_register_events(c, WEBSOCKET_EVENT_ANY, eventos, NULL);
    esp_websocket_client_start(c);
    for (int k = 0; k < 3; k++) {
        vTaskDelay(pdMS_TO_TICKS(1000));
        if (!esp_websocket_client_is_connected(c)) continue;
        char txt[32];
        int n = snprintf(txt, sizeof txt, "{\"seq\":%d,\"t\":23.%d}", k, k);
        esp_websocket_client_send_text(c, txt, n, pdMS_TO_TICKS(1000));
    }
    vTaskDelay(pdMS_TO_TICKS(1000));
    esp_websocket_client_close(c, pdMS_TO_TICKS(2000));     /* quadro close com código 1000 */
    esp_websocket_client_destroy(c);
}
```

**7. No PC: websockets e os quadros à mão.** O servidor de laboratório (biblioteca `websockets`, API asyncio da versão 15) tem um eco em `/eco` e uma difusão em `/painel` com `broadcast`, que envia a mesma mensagem a todos os conectados sem esperar cada um:

```python
#!/usr/bin/env python3
"""eco_ws.py — servidor WebSocket de laboratório (websockets 15+): /eco devolve; /painel recebe uma leitura por segundo."""
import asyncio, json, random
from websockets.asyncio.server import serve, broadcast

paineis = set()

async def tratar(ws):
    if ws.request.path == "/eco":
        async for msg in ws:
            await ws.send(msg)
    elif ws.request.path == "/painel":
        paineis.add(ws)
        try:
            await ws.wait_closed()
        finally:
            paineis.discard(ws)

async def leituras():
    t = 23.5
    while True:
        await asyncio.sleep(1)
        t = round(t + random.uniform(-0.2, 0.2), 1)
        broadcast(paineis, json.dumps({"t": t}))        # um envio para todos os painéis abertos

async def main():
    async with serve(tratar, "0.0.0.0", 8765, ping_interval=20, ping_timeout=20):
        await leituras()

asyncio.run(main())
```

E o handshake e os quadros feitos à mão, com um socket TCP cru, contra esse servidor:

```python
#!/usr/bin/env python3
"""ws_quadro.py — handshake e quadros WebSocket (RFC 6455) feitos à mão, conferidos com um servidor real."""
import base64, hashlib, os, socket, struct

GUID = "258EAFA5-E914-47DA-95CA-C5AB0DC85B11"          # constante fixa da RFC 6455

def aceitar(chave_b64):
    """Sec-WebSocket-Accept = base64(SHA-1(chave + GUID))."""
    return base64.b64encode(hashlib.sha1((chave_b64 + GUID).encode()).digest()).decode()

def quadro(payload, opcode=0x1, fin=True, mascara=None):
    """Monta um quadro. Cliente → servidor: máscara obrigatória (4 bytes)."""
    b0 = (0x80 if fin else 0) | opcode
    n = len(payload)
    m = 0x80 if mascara else 0
    if n <= 125:      cab = struct.pack("!BB", b0, m | n)
    elif n <= 0xFFFF: cab = struct.pack("!BBH", b0, m | 126, n)
    else:             cab = struct.pack("!BBQ", b0, m | 127, n)
    if mascara:
        payload = bytes(c ^ mascara[i % 4] for i, c in enumerate(payload))
        cab += mascara
    return cab + payload

def ler_quadro(sock):
    b0, b1 = sock.recv(2, socket.MSG_WAITALL)
    n = b1 & 0x7F
    if n == 126: n = struct.unpack("!H", sock.recv(2, socket.MSG_WAITALL))[0]
    elif n == 127: n = struct.unpack("!Q", sock.recv(8, socket.MSG_WAITALL))[0]
    mascara = sock.recv(4, socket.MSG_WAITALL) if b1 & 0x80 else None
    dados = sock.recv(n, socket.MSG_WAITALL) if n else b""
    if mascara:
        dados = bytes(c ^ mascara[i % 4] for i, c in enumerate(dados))
    return b0 >> 7, b0 & 0x0F, dados

if __name__ == "__main__":
    print("exemplo da RFC:", aceitar("dGhlIHNhbXBsZSBub25jZQ=="))
    print("'Hello' do cliente:", quadro(b"Hello", mascara=bytes([0x37, 0xFA, 0x21, 0x3D])).hex(" "))
    print("'Hello' do servidor:", quadro(b"Hello").hex(" "))
    print("256 B binário:", quadro(bytes(256), opcode=0x2)[:4].hex(" "), "...", len(quadro(bytes(256), 0x2)), "B")
    print("65 536 B binário:", quadro(bytes(65536), opcode=0x2)[:10].hex(" "), "...")

    # contra um servidor de verdade (eco_ws.py na porta 8765)
    s = socket.create_connection(("127.0.0.1", 8765))
    chave = base64.b64encode(os.urandom(16)).decode()
    s.sendall((f"GET /eco HTTP/1.1\r\nHost: 127.0.0.1:8765\r\nUpgrade: websocket\r\nConnection: Upgrade\r\n"
               f"Sec-WebSocket-Key: {chave}\r\nSec-WebSocket-Version: 13\r\n\r\n").encode())
    resp = b""
    while b"\r\n\r\n" not in resp: resp += s.recv(1024)
    linhas = resp.decode().split("\r\n")
    print(linhas[0], "| Accept recebido == calculado:",
          any(l.split(": ")[1] == aceitar(chave) for l in linhas if l.lower().startswith("sec-websocket-accept")))
    s.sendall(quadro(b'{"t":23.5}', mascara=os.urandom(4)))
    print("eco:", ler_quadro(s))
    s.sendall(quadro(b"ola", mascara=os.urandom(4), opcode=0x9))          # ping do cliente
    print("pong:", ler_quadro(s))
    s.sendall(quadro(struct.pack("!H", 1000) + b"tchau", mascara=os.urandom(4), opcode=0x8))
    fin, op, d = ler_quadro(s)
    print("close:", fin, op, struct.unpack("!H", d[:2])[0], d[2:])
```

**8. MQTT sobre WebSocket.** O navegador não abre TCP cru, então um painel web que quer falar MQTT usa **MQTT sobre WebSocket**: cada pacote MQTT vai num quadro **binário**, com o subprotocolo `mqtt` (*Using WebSocket as a network transport*). No Mosquitto basta um segundo listener (executado com o Mosquitto 2.0.20 em Docker):

```
# mosquitto.conf — laboratório: MQTT na 1883 e MQTT sobre WebSocket na 9001 (só localhost, sem senha)
listener 1883
protocol mqtt
listener 9001
protocol websockets
allow_anonymous true
persistence true
persistence_location /mosquitto/data/
log_dest stdout
```

Os dois listeners compartilham os mesmos tópicos: o ESP32 publica por TCP na 1883 e o painel assina por WebSocket na 9001. Com o **MQTT.js** (o mesmo código roda no navegador, carregando a biblioteca de um CDN, e no Node; aqui testado no Node 22 com mqtt 5.10):

```js
// painel.mjs — o mesmo código que roda no navegador (mqtt.js), aqui no Node para teste
import mqtt from "mqtt";
const c = mqtt.connect("ws://127.0.0.1:9001", { clientId: "painel-js", clean: true });
c.on("connect", () => {
  c.subscribe("forja/v1/+/tele", { qos: 1 });
  setTimeout(() => c.publish("forja/v1/forja-001/tele", '{"t":24.0}', { qos: 1 }), 300);
});
c.on("message", (topico, msg) => { console.log("mqtt.js recebeu", topico, msg.toString()); c.end(); });
```

```
mqtt.js recebeu forja/v1/forja-001/tele {"t":24.0}
```

No Python, o paho-mqtt faz o mesmo com `transport="websockets"` (`mqtt.Client(..., transport="websockets")` e `connect("127.0.0.1", 9001)`). Em produção, o painel usa `wss://` (o T06 coloca TLS no listener) e **credenciais próprias, com ACL só de leitura**: tudo o que roda no navegador é visível para o usuário, inclusive a senha MQTT do painel.

**9. Qual técnica para empurrar dados?**

| Técnica | Direção | Latência | Custo por atualização | Quando |
|---|---|---|---|---|
| Polling HTTP | cliente pergunta | até o intervalo | uma requisição e uma resposta completas, mesmo sem novidade | dado que muda pouco; simplicidade |
| Long polling (RFC 6202) | servidor responde quando há novidade | baixa | uma requisição nova por novidade | ambientes que só permitem HTTP |
| Server-Sent Events | só servidor → navegador | baixa | poucas dezenas de bytes por evento, numa resposta HTTP aberta | painéis só de leitura; reconexão automática do `EventSource` |
| WebSocket | dois sentidos | baixa | 2–14 bytes de cabeçalho por mensagem | painel com comandos; jogos; chat |
| MQTT sobre WebSocket | dois sentidos, pub/sub | baixa | quadro WebSocket + pacote MQTT | painel ligado ao broker da frota (T09) |

**Exemplo resolvido 3 (polling × WebSocket).** Um painel quer a temperatura a cada segundo. Por polling, cada ciclo custa ~300 bytes de requisição e ~200 de resposta (T01): **500 B/s = 1,8 MB por hora** por aba aberta, em camada de aplicação. Por WebSocket, o servidor manda um quadro de 2 bytes de cabeçalho com 20 bytes de JSON: **22 B/s = 79,2 kB por hora**, mais um ping/pong de vez em quando — cerca de **23 vezes menos**, e só quando há dado novo. Para o **dispositivo**, porém, nada disso substitui o MQTT: WebSocket é um canal ponto a ponto, sem broker, sem QoS, sem retain e sem testamento; um ESP32 com WebSocket aberto para a nuvem precisa reinventar tudo isso.

## Armadilhas comuns
- `ws://` fora do laboratório: tudo em texto claro, inclusive o token.
- Não conferir o `Origin` no servidor e deixar qualquer página abrir um WebSocket para o seu equipamento.
- Esquecer que todo quadro do cliente é mascarado (e escrever um cliente embarcado sem máscara, que o servidor fecha).
- Mandar texto que não é UTF-8 válido em quadro de texto (o outro lado fecha com 1007): use binário.
- Ler só o primeiro fragmento e tratar como a mensagem inteira.
- Chamar `httpd_ws_send_frame_async` de outra tarefa sem `httpd_queue_work`.
- Não ter ping/pong e só descobrir horas depois que a conexão morreu atrás de um NAT.
- Deixar o servidor do ESP32 aceitar mais clientes do que tem sockets e memória.
- Senha MQTT de escrita no JavaScript do painel.
- Usar WebSocket como protocolo do dispositivo para a nuvem e reinventar QoS, retain e testamento.

## Gabarito
1. `HSmrc0sMlYUkAGmm5OPpG2HaGWk=`.
2. Servidor: `81 0A` + 10 bytes = 12 bytes. Cliente: `81 8A 01 02 03 04` + 10 bytes mascarados = 16 bytes.
3. 1000 bytes: `82 FE 03 E8` + 4 bytes de máscara (8 bytes de cabeçalho). 70 000 bytes: `82 FF 00 00 00 00 00 01 11 70` + 4 de máscara (14 bytes).
4. A máscara aleatória impede que um script malicioso no navegador controle os bytes exatos que passam por proxies e caches intermediários, o que permitiria envenená-los. Não protege o conteúdo: a chave vai no próprio quadro; sigilo é o papel do TLS (`wss://`). O servidor não é controlado por páginas de terceiros, por isso não precisa mascarar.
5. `01` (FIN 0, texto), `00` (FIN 0, continuação), `80` (FIN 1, continuação).
6. Sim: quadros de controle podem ser intercalados entre fragmentos, justamente para o keepalive não esperar uma mensagem longa.
7. A conexão caiu sem o fechamento (sem quadro close): queda de rede, processo morto, NAT. O 1006 é reservado para a aplicação indicar isso localmente; não pode ser enviado porque, por definição, ninguém mandou close.
8. A configuração padrão do `esp_http_server` tem 7 sockets; com todos ocupados, a conexão nova é recusada (ou o servidor fecha a menos usada, se `lru_purge_enable` estiver ligado). É preciso aumentar `max_open_sockets` (e a memória) ou limitar as abas.
9. Polling: 720 ciclos × 500 B = 360 000 B = 360 kB por hora. WebSocket: 720 × (2 + 30) = 23 040 B ≈ 23 kB por hora.
10. MQTT sobre WebSocket direto no broker reaproveita tópicos, retain (estado imediato ao abrir), QoS e a ACL do broker (T06), com um usuário de painel só de leitura e comandos limitados por tópico. Um WebSocket próprio exige escrever e proteger um servidor intermediário, mas permite esconder o broker e aplicar regras de negócio antes de cada comando. Com 200 dispositivos e uma equipe pequena, MQTT sobre WSS com ACL é o caminho mais curto; com usuários externos e regras complexas, um backend próprio (ou a plataforma do T07) é mais seguro.

# M1.6.T04 — Wi-Fi (station, AP, provisionamento)

> Tópico de **elite** (laboratório). Tempo previsto: ~27,7 h — ≈ 6 h de estudo (guia do driver de Wi-Fi, biblioteca de eventos, esp_netif, provisionamento), ≈ 4 h de exemplos resolvidos, ≈ 14 h de laboratório (station com reconexão, AP+STA com página web, provisionamento pelo celular, medições de tempo e de falhas), ≈ 3,7 h de relatório e revisão. Até aqui o ESP32 foi um microcontrolador rápido. Agora ele entra na rede. O Wi-Fi do ESP-IDF não é uma função `conectar()` que bloqueia até dar certo: é um **driver assíncrono** que conversa com a aplicação por **eventos**. Quem entende o modelo de eventos escreve firmware que sobrevive a roteador reiniciado, senha trocada e sinal fraco; quem não entende escreve o firmware que "funciona na bancada". O Wi-Fi a fundo (802.11, segurança, roaming, desempenho) é o M1.9; aqui fica o necessário para pôr um produto no ar: station, AP e provisionamento. O código foi compilado com o ESP-IDF v5.3.2 para o ESP32.

## Ao final você consegue

- Conectar em modo station com espera por IP via event group, reconexão com recuo e tratamento dos motivos de desconexão.
- Configurar os modos AP e AP+STA e servir uma página com o esp_http_server, respeitando os limites de canal, de clientes e de segurança.
- Provisionar as credenciais de Wi-Fi sem gravá-las no código (wifi_provisioning por BLE ou SoftAP, SmartConfig, portal próprio) e comparar os métodos em segurança e experiência do usuário.

## Resumo
**1. O modelo de eventos.** O driver de Wi-Fi roda numa tarefa própria (a *Wi-Fi task*) e avisa a aplicação de tudo o que acontece **postando eventos** num **loop de eventos** (*Event Loop Library*). Um evento tem uma **base** (família) e um **id**:
- `WIFI_EVENT`: `WIFI_EVENT_STA_START`, `WIFI_EVENT_STA_CONNECTED`, `WIFI_EVENT_STA_DISCONNECTED` (com o **motivo**), `WIFI_EVENT_AP_STACONNECTED`, `WIFI_EVENT_SCAN_DONE`…
- `IP_EVENT`: `IP_EVENT_STA_GOT_IP` (o DHCP entregou um endereço), `IP_EVENT_STA_LOST_IP`.

A aplicação registra **handlers** (`esp_event_handler_instance_register(base, id, função, arg, &instância)`), que rodam na tarefa do **loop padrão** (`sys_evt`), criada por `esp_event_loop_create_default()`. Consequências:
- O handler deve ser **curto**: nada de esperar, bloquear ou fazer HTTP dentro dele. Ele sinaliza (event group, fila) e a sua tarefa trabalha.
- Conectar não é síncrono: `esp_wifi_connect()` só **inicia** a tentativa; o resultado chega depois, como `IP_EVENT_STA_GOT_IP` ou `WIFI_EVENT_STA_DISCONNECTED`.
- Você pode criar eventos e loops próprios (`ESP_EVENT_DECLARE_BASE`, `esp_event_post`) para desacoplar módulos do seu firmware.

**2. A sequência de inicialização** (*Wi-Fi Station General Scenario*):
1. `nvs_flash_init()` — o driver guarda calibração de RF e, se você deixar, a última configuração na NVS (T03).
2. `esp_netif_init()` — inicializa a pilha TCP/IP (lwIP).
3. `esp_event_loop_create_default()` — o loop padrão.
4. `esp_netif_create_default_wifi_sta()` (e/ou `_ap()`) — cria a interface de rede e liga o cliente DHCP (ou o servidor, no AP).
5. `esp_wifi_init(&cfg)` com `WIFI_INIT_CONFIG_DEFAULT()` — aloca buffers e cria a tarefa do Wi-Fi.
6. Registrar os handlers.
7. `esp_wifi_set_mode()`, `esp_wifi_set_config()`.
8. `esp_wifi_start()` — liga o rádio; gera `WIFI_EVENT_STA_START`, no qual se chama `esp_wifi_connect()`.

Os passos 2, 3 e 5 são **uma vez por boot**: chamar de novo devolve `ESP_ERR_INVALID_STATE`. Num firmware com vários módulos, crie o loop e o netif num lugar só.

**3. Station: conectar e não desistir.** Exemplo resolvido, baseado em `examples/wifi/getting_started/station`, com duas melhorias de produto: reconexão com **recuo exponencial** (1 s, 2 s, 4 s… até 60 s, por um timer, sem bloquear o handler) e registro do **motivo** da desconexão.
```c
#include <string.h>
#include "freertos/FreeRTOS.h"
#include "freertos/event_groups.h"
#include "freertos/timers.h"
#include "esp_wifi.h"
#include "esp_event.h"
#include "esp_netif.h"
#include "esp_log.h"

static const char *TAG = "wifi";
static EventGroupHandle_t eventos;
#define BIT_CONECTADO BIT0

static TimerHandle_t timer_reconexao;
static uint32_t recuo_ms = 1000;                 /* recuo exponencial: 1, 2, 4 ... 60 s */

static void reconectar(TimerHandle_t t)
{
    esp_wifi_connect();
}

static void ao_evento(void *arg, esp_event_base_t base, int32_t id, void *dados)
{
    if (base == WIFI_EVENT && id == WIFI_EVENT_STA_START) {
        esp_wifi_connect();
    } else if (base == WIFI_EVENT && id == WIFI_EVENT_STA_DISCONNECTED) {
        wifi_event_sta_disconnected_t *d = dados;
        xEventGroupClearBits(eventos, BIT_CONECTADO);
        ESP_LOGW(TAG, "desconectado, motivo %d; nova tentativa em %lu ms",
                 d->reason, (unsigned long)recuo_ms);
        xTimerChangePeriod(timer_reconexao, pdMS_TO_TICKS(recuo_ms), 0);   /* também inicia */
        recuo_ms = recuo_ms * 2 > 60000 ? 60000 : recuo_ms * 2;
    } else if (base == IP_EVENT && id == IP_EVENT_STA_GOT_IP) {
        ip_event_got_ip_t *e = dados;
        ESP_LOGI(TAG, "IP " IPSTR ", gateway " IPSTR,
                 IP2STR(&e->ip_info.ip), IP2STR(&e->ip_info.gw));
        recuo_ms = 1000;
        xEventGroupSetBits(eventos, BIT_CONECTADO);
    }
}

esp_err_t wifi_sta_conectar(const char *ssid, const char *senha, int espera_ms)
{
    eventos = xEventGroupCreate();
    timer_reconexao = xTimerCreate("reconexao", pdMS_TO_TICKS(1000), pdFALSE, NULL, reconectar);

    ESP_ERROR_CHECK(esp_netif_init());                       /* pilha TCP/IP (lwIP) */
    ESP_ERROR_CHECK(esp_event_loop_create_default());        /* loop de eventos padrão */
    esp_netif_create_default_wifi_sta();

    wifi_init_config_t cfg = WIFI_INIT_CONFIG_DEFAULT();
    ESP_ERROR_CHECK(esp_wifi_init(&cfg));
    ESP_ERROR_CHECK(esp_event_handler_instance_register(WIFI_EVENT, ESP_EVENT_ANY_ID,
                                                        ao_evento, NULL, NULL));
    ESP_ERROR_CHECK(esp_event_handler_instance_register(IP_EVENT, IP_EVENT_STA_GOT_IP,
                                                        ao_evento, NULL, NULL));

    wifi_config_t wc = {
        .sta = {
            .threshold.authmode = WIFI_AUTH_WPA2_PSK,   /* recusa redes abertas e WEP/WPA */
            .sae_pwe_h2e = WPA3_SAE_PWE_BOTH,          /* aceita WPA3-SAE também */
        },
    };
    strlcpy((char *)wc.sta.ssid, ssid, sizeof wc.sta.ssid);
    strlcpy((char *)wc.sta.password, senha, sizeof wc.sta.password);
    if (senha[0] == '\0')                                   /* rede aberta (ex.: Wokwi-GUEST) */
        wc.sta.threshold.authmode = WIFI_AUTH_OPEN;
    ESP_ERROR_CHECK(esp_wifi_set_mode(WIFI_MODE_STA));
    ESP_ERROR_CHECK(esp_wifi_set_config(WIFI_IF_STA, &wc));
    ESP_ERROR_CHECK(esp_wifi_start());                       /* gera WIFI_EVENT_STA_START */

    EventBits_t b = xEventGroupWaitBits(eventos, BIT_CONECTADO, pdFALSE, pdTRUE,
                                        pdMS_TO_TICKS(espera_ms));
    return (b & BIT_CONECTADO) ? ESP_OK : ESP_ERR_TIMEOUT;
}
```
E no `app_main`, antes de tudo, a NVS (o padrão do T03):
```c
void app_main(void)
{
    esp_err_t err = nvs_flash_init();            /* o Wi-Fi guarda calibração e credenciais aqui */
    if (err == ESP_ERR_NVS_NO_FREE_PAGES || err == ESP_ERR_NVS_NEW_VERSION_FOUND) {
        ESP_ERROR_CHECK(nvs_flash_erase());
        err = nvs_flash_init();
    }
    ESP_ERROR_CHECK(err);
    if (wifi_sta_conectar("Wokwi-GUEST", "", 15000) != ESP_OK) {
        ESP_LOGW("main", "sem rede em 15 s");    /* segue: as medidas vão para a fila */
    }
}
```
Pontos a notar:
- O **event group** é a ponte entre o handler (que só põe um bit) e a tarefa que espera (`xEventGroupWaitBits` com tempo limite). Esperar para sempre (`portMAX_DELAY`), como no exemplo oficial, é aceitável numa demonstração; num produto, defina o que fazer sem rede (guardar medidas, tentar depois, entrar em provisionamento).
- O **limiar de autenticação** (`threshold.authmode`) faz o ESP32 recusar uma rede falsa aberta com o mesmo nome. Para a rede aberta `Wokwi-GUEST` do simulador, é preciso baixá-lo para `WIFI_AUTH_OPEN`, como no trecho.
- O SSID tem até **32 bytes** e a senha WPA2 de **8 a 63** caracteres (`wifi_sta_config_t`).
- O **recuo exponencial** evita que cem aparelhos martelem o roteador ao mesmo tempo quando ele volta. Um sorteio de alguns segundos (*jitter*) somado ao recuo espalha ainda mais.

**Motivos de desconexão** (`wifi_event_sta_disconnected_t.reason`, *Wi-Fi Reason Code*; valores do `esp_wifi_types_generic.h` da v5.3):

| Código | Nome | O que fazer |
|---|---|---|
| 201 | `WIFI_REASON_NO_AP_FOUND` | rede fora do ar ou fora de alcance: recuo e nova tentativa |
| 202 | `WIFI_REASON_AUTH_FAIL` | autenticação recusada |
| 15 | `WIFI_REASON_4WAY_HANDSHAKE_TIMEOUT` | quase sempre **senha errada** no WPA2-PSK |
| 204 | `WIFI_REASON_HANDSHAKE_TIMEOUT` | idem, por tempo esgotado |
| 200 | `WIFI_REASON_BEACON_TIMEOUT` | perdeu o sinal do AP depois de conectado |
| 8 | `WIFI_REASON_ASSOC_LEAVE` | a própria aplicação desconectou |
| 210 / 211 | `..._NO_AP_FOUND_W_COMPATIBLE_SECURITY` / `..._IN_AUTHMODE_THRESHOLD` | a rede existe, mas a segurança não bate com o limiar configurado |

Uma senha errada não se resolve tentando para sempre: depois de algumas falhas de handshake seguidas, o firmware deve voltar ao provisionamento ou avisar o usuário.

**4. AP e AP+STA.** No modo **AP** (*SoftAP*), o ESP32 cria a própria rede, com servidor DHCP: ele fica em **192.168.4.1** e entrega endereços aos clientes. No modo **AP+STA** (`WIFI_MODE_APSTA`), faz as duas coisas ao mesmo tempo, com **um único rádio**: por isso o AP é obrigado a usar o **mesmo canal** da rede externa à qual a station se conectou (a documentação diz que o canal do AP externo tem prioridade sobre o canal do AP do ESP). Se a station conectar num roteador no canal 11, o AP configurado no canal 6 muda para o 11 e os clientes do AP podem cair.

Limites: o ESP32, o S2 e o S3 aceitam até **15** clientes no AP; o C3 e o C6, até **10** (`ESP_WIFI_MAX_CONN_NUM`); o padrão de `max_connection` nos exemplos é bem menor. Use WPA2 (ou WPA3) com senha de no mínimo 8 caracteres; AP aberto só para provisionamento rápido, e mesmo assim com a segurança na camada de cima.

**Exemplo resolvido (AP+STA com página web).** Base: `examples/wifi/softap_sta` e `examples/protocols/http_server/simple`.
```c
#include <string.h>
#include "esp_wifi.h"
#include "esp_event.h"
#include "esp_netif.h"
#include "esp_http_server.h"
#include "esp_log.h"
#include "esp_mac.h"

static const char *TAG = "ap";

static esp_err_t pagina_inicial(httpd_req_t *req)
{
    static const char html[] =
        "<!doctype html><meta charset=utf-8><title>Forja</title>"
        "<h1>Vila da Forja</h1><p>Sensor no ar.</p>";
    httpd_resp_set_type(req, "text/html");
    return httpd_resp_send(req, html, HTTPD_RESP_USE_STRLEN);
}

static void ao_evento_ap(void *arg, esp_event_base_t base, int32_t id, void *dados)
{
    if (id == WIFI_EVENT_AP_STACONNECTED) {
        wifi_event_ap_staconnected_t *e = dados;
        ESP_LOGI(TAG, "cliente " MACSTR " entrou (AID %d)", MAC2STR(e->mac), e->aid);
    } else if (id == WIFI_EVENT_AP_STADISCONNECTED) {
        wifi_event_ap_stadisconnected_t *e = dados;
        ESP_LOGI(TAG, "cliente " MACSTR " saiu", MAC2STR(e->mac));
    }
}

void ap_sta_iniciar(void)
{
    ESP_ERROR_CHECK(esp_netif_init());
    ESP_ERROR_CHECK(esp_event_loop_create_default());
    esp_netif_create_default_wifi_ap();          /* 192.168.4.1, com servidor DHCP */
    esp_netif_create_default_wifi_sta();

    wifi_init_config_t cfg = WIFI_INIT_CONFIG_DEFAULT();
    ESP_ERROR_CHECK(esp_wifi_init(&cfg));
    ESP_ERROR_CHECK(esp_event_handler_instance_register(WIFI_EVENT, ESP_EVENT_ANY_ID,
                                                        ao_evento_ap, NULL, NULL));
    wifi_config_t ap = {
        .ap = {
            .ssid = "Forja-Sensor",
            .ssid_len = 0,                       /* 0: usa o tamanho da string */
            .channel = 6,                        /* ignorado se a STA conectar em outro canal */
            .password = "ferreiro123",           /* mínimo de 8 caracteres para WPA2 */
            .max_connection = 4,
            .authmode = WIFI_AUTH_WPA2_PSK,
            .pmf_cfg = { .required = false },
        },
    };
    ESP_ERROR_CHECK(esp_wifi_set_mode(WIFI_MODE_APSTA));
    ESP_ERROR_CHECK(esp_wifi_set_config(WIFI_IF_AP, &ap));
    ESP_ERROR_CHECK(esp_wifi_start());

    httpd_handle_t srv = NULL;
    httpd_config_t hc = HTTPD_DEFAULT_CONFIG();  /* porta 80 */
    ESP_ERROR_CHECK(httpd_start(&srv, &hc));
    httpd_uri_t raiz = { .uri = "/", .method = HTTP_GET, .handler = pagina_inicial };
    ESP_ERROR_CHECK(httpd_register_uri_handler(srv, &raiz));
    ESP_LOGI(TAG, "AP Forja-Sensor no ar: http://192.168.4.1/");
}
```
Para a parte STA desse modo, configure `WIFI_IF_STA` como no exemplo anterior. Note o `#include "esp_mac.h"`: é ele que define `MACSTR` e `MAC2STR` na v5 (sem ele, o build falha com `expected ')' before 'MACSTR'`).

**Tamanho.** O projeto com station, AP+STA, servidor HTTP e provisionamento compilou para uma imagem de **~733 KB** (0xB7490 bytes) no ESP32, contra ~185 KB do projeto sem rede do T02: o Wi-Fi, o lwIP e o mbedTLS dominam. Ainda cabe na partição de 1 MB, com 28% livres. Para OTA (T09), conte com duas partições desse tamanho e margem de crescimento.

**5. Provisionamento: a senha não vai no código.** Um produto não sai da fábrica sabendo a senha do Wi-Fi da sua casa. Gravar `"minha_senha"` no firmware serve para bancada; em produto, as credenciais chegam depois, pelo usuário. Opções:

| Método | Como funciona | Prós | Contras |
|---|---|---|---|
| `wifi_provisioning` por **BLE** | o app (*ESP BLE Provisioning*, Android/iOS) se conecta por BLE e envia SSID e senha cifrados | o celular não sai da rede dele; dá para listar redes vistas pelo ESP32 | precisa do Bluetooth (memória, ~centenas de KB de flash); C3/S3/C6/ESP32 têm |
| `wifi_provisioning` por **SoftAP** | o ESP32 cria um AP; o app (*ESP SoftAP Provisioning*) entra nele e envia as credenciais | funciona em chips sem BLE (S2) | o usuário troca de rede no celular; mais passos |
| **Portal próprio** (AP + HTTP) | página web em 192.168.4.1 com um formulário | qualquer navegador, sem app | segurança é com você (HTTPS no ESP32 é pesado; HTTP em AP aberto expõe a senha) |
| **SmartConfig** (ESPTouch) | o app codifica SSID e senha no tamanho de pacotes enviados na rede; o ESP32 escuta em modo promíscuo | sem trocar de rede | não funciona em toda rede (5 GHz no celular, isolamento), segurança fraca na versão básica |

O `wifi_provisioning` (componente do ESP-IDF, sobre o *protocomm*) oferece **níveis de segurança** (*Wi-Fi Provisioning*, *Security*):
- **Security 0**: texto aberto. Só para testes.
- **Security 1**: troca de chaves X25519, prova de posse (**PoP**, uma senha curta impressa na etiqueta do produto) e AES-CTR.
- **Security 2**: SRP6a (usuário e senha) e AES-GCM.

**Exemplo resolvido (provisionamento por SoftAP, segurança 1).** Base: `examples/provisioning/wifi_prov_mgr`.
```c
#include "freertos/FreeRTOS.h"
#include "freertos/event_groups.h"
#include "esp_wifi.h"
#include "esp_event.h"
#include "esp_netif.h"
#include "esp_log.h"
#include "esp_mac.h"
#include "wifi_provisioning/manager.h"
#include "wifi_provisioning/scheme_softap.h"

static const char *TAG = "prov";
static EventGroupHandle_t ev;
#define BIT_IP BIT0

static void ao_evento(void *arg, esp_event_base_t base, int32_t id, void *dados)
{
    if (base == WIFI_PROV_EVENT) {
        switch (id) {
        case WIFI_PROV_CRED_RECV: {
            wifi_sta_config_t *c = dados;
            ESP_LOGI(TAG, "credenciais recebidas para a rede %s", (const char *)c->ssid);
            break;
        }
        case WIFI_PROV_CRED_FAIL:
            ESP_LOGE(TAG, "falha: senha errada ou rede não encontrada");
            wifi_prov_mgr_reset_sm_state_on_failure();   /* deixa tentar de novo */
            break;
        case WIFI_PROV_END:
            wifi_prov_mgr_deinit();                       /* libera memória do provisionamento */
            break;
        }
    } else if (base == WIFI_EVENT && id == WIFI_EVENT_STA_START) {
        esp_wifi_connect();
    } else if (base == WIFI_EVENT && id == WIFI_EVENT_STA_DISCONNECTED) {
        esp_wifi_connect();                               /* no produto: o recuo da seção 3 */
    } else if (base == IP_EVENT && id == IP_EVENT_STA_GOT_IP) {
        xEventGroupSetBits(ev, BIT_IP);
    }
}

void provisionar_ou_conectar(void)
{
    /* nvs_flash_init() já foi chamado em app_main: as credenciais ficam na NVS */
    ev = xEventGroupCreate();
    ESP_ERROR_CHECK(esp_netif_init());
    ESP_ERROR_CHECK(esp_event_loop_create_default());
    ESP_ERROR_CHECK(esp_event_handler_register(WIFI_PROV_EVENT, ESP_EVENT_ANY_ID, ao_evento, NULL));
    ESP_ERROR_CHECK(esp_event_handler_register(WIFI_EVENT, ESP_EVENT_ANY_ID, ao_evento, NULL));
    ESP_ERROR_CHECK(esp_event_handler_register(IP_EVENT, IP_EVENT_STA_GOT_IP, ao_evento, NULL));
    esp_netif_create_default_wifi_sta();
    esp_netif_create_default_wifi_ap();          /* o esquema SoftAP precisa da interface AP */
    wifi_init_config_t cfg = WIFI_INIT_CONFIG_DEFAULT();
    ESP_ERROR_CHECK(esp_wifi_init(&cfg));

    wifi_prov_mgr_config_t pc = {
        .scheme = wifi_prov_scheme_softap,       /* ou wifi_prov_scheme_ble */
        .scheme_event_handler = WIFI_PROV_EVENT_HANDLER_NONE,
    };
    ESP_ERROR_CHECK(wifi_prov_mgr_init(pc));

    bool provisionado = false;
    ESP_ERROR_CHECK(wifi_prov_mgr_is_provisioned(&provisionado));
    if (!provisionado) {
        uint8_t mac[6];
        char nome[16];
        esp_read_mac(mac, ESP_MAC_WIFI_STA);
        snprintf(nome, sizeof nome, "FORJA_%02X%02X%02X", mac[3], mac[4], mac[5]);
        const char *pop = "forja-1234";          /* prova de posse: impressa na etiqueta */
        ESP_LOGI(TAG, "provisionando: rede %s, PoP %s", nome, pop);
        ESP_ERROR_CHECK(wifi_prov_mgr_start_provisioning(WIFI_PROV_SECURITY_1, pop, nome, NULL));
    } else {
        wifi_prov_mgr_deinit();
        ESP_ERROR_CHECK(esp_wifi_set_mode(WIFI_MODE_STA));
        ESP_ERROR_CHECK(esp_wifi_start());       /* usa a configuração salva na NVS */
    }
    xEventGroupWaitBits(ev, BIT_IP, pdFALSE, pdTRUE, portMAX_DELAY);
    ESP_LOGI(TAG, "conectado");
}
```
Como funciona: no primeiro boot, `wifi_prov_mgr_is_provisioned` diz que não há credenciais na NVS; o ESP32 cria o AP `FORJA_xxxxxx` (os três últimos bytes do MAC: nome único por aparelho) e espera o app. O usuário digita a PoP (ou lê o QR code da etiqueta), escolhe a rede e a senha; o ESP32 testa a conexão, grava na NVS e encerra o provisionamento. Nos boots seguintes, conecta direto. Para **refazer** o provisionamento (troca de roteador), o produto precisa de um gesto do usuário — segurar um botão por 5 s, por exemplo — que chame `wifi_prov_mgr_reset_provisioning()` ou apague as credenciais. Para o esquema BLE, troque para `wifi_prov_scheme_ble` com `WIFI_PROV_SCHEME_BLE_EVENT_HANDLER_FREE_BTDM` e habilite o Bluetooth no menuconfig (o exemplo oficial mostra as duas variantes). Nas versões mais novas do ESP-IDF, o provisionamento está migrando para um componente do registro (`network_provisioning`); confira a documentação da sua versão.

**6. Energia e o modem sleep.** Conectado, o ESP32 entra por padrão em **modem sleep mínimo** (`WIFI_PS_MIN_MODEM`): o rádio dorme entre os *beacons* do roteador e acorda a cada DTIM para ver se há dados. Com `WIFI_PS_NONE`, o rádio fica sempre ligado (menor latência, consumo de ~100 mA ou mais). Com `WIFI_PS_MAX_MODEM` e um *listen interval* maior, consome menos e responde mais devagar. Para sensores com bateria, o caminho é outro: conectar, enviar e entrar em **deep sleep** (T06), e a conexão rápida passa a importar (IP fixo e canal conhecido economizam centenas de ms por despertar).

## Laboratório

### Material
- **Placa com ESP32**: ESP32-DevKitC (ou clone com CP2102/CH340) ou uma placa ESP32-C3 (ESP32-C3-DevKitM-1 ou uma "C3 SuperMini" barata), cabo USB **de dados**.
- Um roteador Wi-Fi de 2,4 GHz onde você possa mudar senha e desligar a energia (ou o ponto de acesso do celular, em 2,4 GHz).
- Um celular com os apps **ESP SoftAP Provisioning** e **ESP BLE Provisioning** (Espressif, gratuitos) e um app de análise Wi-Fi (para ver canais e RSSI).
- PC com ESP-IDF v5.x instalado (T02). Opcional: Wireshark.
- **Alternativas sem placa**:
  - **Wokwi** (wokwi.com ou a extensão *Wokwi for VS Code*): simula o ESP32 (e o C3, S3, C6) rodando o **binário do ESP-IDF** que você compilou, com a rede aberta **`Wokwi-GUEST`** e acesso à internet. Serve para os Experimentos 1, 2 e parte do 5. Na extensão do VS Code, crie na raiz do projeto um `wokwi.toml` apontando para o build (`[wokwi]`, `version = 1`, `firmware = 'build/flasher_args.json'`, `elf = 'build/<projeto>.elf'`) e um `diagram.json` com a placa. Para acessar o servidor HTTP do ESP32 simulado a partir do PC, use o redirecionamento de portas do `wokwi.toml` descrito na documentação da extensão. O modo AP e o provisionamento **não** são cobertos pelo simulador até onde este roteiro pôde verificar: faça os Experimentos 3 e 4 com placa ou registre-os como não realizados.
  - **QEMU da Espressif** (`idf.py qemu`, T08): **não** emula Wi-Fi. Só serve para testar a lógica de NVS e de eventos próprios.

### Passo a passo
**Experimento 1 — Station e a anatomia de uma conexão (≈ 3 h).**
1. Monte o projeto com o código da seção 3 (`wifi_sta_conectar`). Ponha SSID e senha num `Kconfig.projbuild` (T02), não no `.c`. No Wokwi, use `Wokwi-GUEST` sem senha.
2. Rode com `idf.py flash monitor` e ponha o nível de log do `wifi` em Debug para ver as fases (`esp_log_level_set("wifi", ESP_LOG_DEBUG)`; T08). Copie o log do boot até o `IP ...`.
3. Meça o tempo entre `esp_wifi_start()` e `IP_EVENT_STA_GOT_IP` com `esp_timer_get_time()`, 10 vezes. Anote média, mínimo e máximo. Repita configurando IP fixo (`esp_netif_dhcpc_stop` + `esp_netif_set_ip_info`) e compare.
4. Imprima o RSSI (`esp_wifi_sta_get_ap_info`) e o canal. Afaste a placa do roteador e anote o RSSI em três posições.

**Experimento 2 — Chuva: falhas provocadas (≈ 3 h).**
1. **Roteador desligado**: com a placa conectada, desligue o roteador por 2 minutos e religue. Registre a sequência de motivos e os tempos de cada nova tentativa (o recuo deve aparecer: 1 s, 2 s, 4 s…). Quanto tempo depois de o roteador voltar a placa reconectou?
2. **Senha errada**: grave uma senha errada. Qual motivo aparece (15? 202? 204?) e quantas vezes? Implemente: depois de 5 falhas de autenticação seguidas, parar de tentar e acender um LED de erro.
3. **Rede inexistente**: SSID que não existe. Anote o motivo (201 ou 211).
4. **Limiar**: crie no celular um ponto de acesso **aberto** com o mesmo SSID do seu roteador e desligue o roteador. Com `threshold.authmode = WIFI_AUTH_WPA2_PSK`, a placa conecta no falso? E com `WIFI_AUTH_OPEN`?
5. No Wokwi, faça o item 1 do jeito possível: chame `esp_wifi_disconnect()` por um comando (botão) e observe o recuo.

**Experimento 3 — AP+STA com página web (≈ 3 h).**
1. Grave o exemplo da seção 4. Conecte o celular ao `Forja-Sensor` e abra `http://192.168.4.1/`. Registre os eventos `AP_STACONNECTED`.
2. Acrescente à página o RSSI e o IP da station, e um segundo URI `/estado` que devolve JSON (`{"temp":23.5,"rssi":-61}`).
3. **Canal**: com o AP configurado no canal 6, faça a station conectar no roteador num canal diferente (veja no app de análise). Em que canal o `Forja-Sensor` fica? O celular conectado ao AP caiu?
4. Conecte três aparelhos ao AP com `max_connection = 2`. O que acontece com o terceiro?

**Experimento 4 — Provisionamento (≈ 3 h).**
1. Grave o exemplo da seção 5 (SoftAP, segurança 1). Pelo app **ESP SoftAP Provisioning**, provisione a placa e registre cada evento (`WIFI_PROV_CRED_RECV`, `..._SUCCESS` ou `..._FAIL`, `WIFI_PROV_END`).
2. Erre a senha de propósito no app. A placa volta a aceitar uma nova tentativa?
3. Implemente o "segurar o botão BOOT por 5 s apaga as credenciais e reinicia". Teste.
4. Troque para o esquema BLE (`wifi_prov_scheme_ble`; habilite Bluetooth e NimBLE no menuconfig) e provisione pelo **ESP BLE Provisioning**. Compare tamanho do binário (`idf.py size`), tempo total do provisionamento e passos do usuário.
5. Com a segurança 0, capture o tráfego do provisionamento SoftAP com o Wireshark (no PC conectado ao AP do ESP32, se o seu app permitir, ou faça o provisionamento pelo `esp_prov.py` do ESP-IDF no próprio PC). A senha aparece em texto? E com a segurança 1?

**Experimento 5 — Consumo e tempo (≈ 2 h).**
1. Com um multímetro em série na alimentação de 3,3 V (ou 5 V da USB, sabendo que inclui o regulador e o conversor da placa), meça a corrente média com `WIFI_PS_NONE` e com `WIFI_PS_MIN_MODEM`, conectado e ocioso.
2. Calcule a carga gasta numa conexão (corrente média × tempo do Experimento 1) e quantas conexões por dia caberiam numa bateria de 1000 mAh só com esse gasto (o T06 completa a conta).

## Armadilhas comuns
- Esquecer o `nvs_flash_init()` antes do `esp_wifi_init()`.
- Chamar `esp_netif_init()` ou `esp_event_loop_create_default()` duas vezes (em dois módulos) e abortar com `ESP_ERR_INVALID_STATE`.
- Trabalho pesado ou bloqueante dentro do handler de eventos.
- Reconectar em laço sem recuo; ou tentar para sempre com a senha errada.
- Esperar o IP com `portMAX_DELAY` num produto e travar sem rede.
- Senha no código-fonte e no repositório.
- Esquecer que AP+STA compartilham o canal.
- Limiar de autenticação aberto em produção (aceita a rede falsa) ou fechado demais no Wokwi (não conecta na `Wokwi-GUEST`).
- Achar que o simulador cobre AP e provisionamento.
- Esquecer o `#include "esp_mac.h"` para `MACSTR`.
- Não prever um jeito de o usuário refazer o provisionamento.

## Gabarito
1. `nvs_flash_init` → `esp_netif_init` → `esp_event_loop_create_default` → `esp_netif_create_default_wifi_sta` → `esp_wifi_init` → registrar handlers → `esp_wifi_set_mode` → `esp_wifi_set_config` → `esp_wifi_start` (→ `esp_wifi_connect` no `STA_START`). Uma vez por boot: `esp_netif_init`, `esp_event_loop_create_default`, `esp_wifi_init` (e a criação do netif).
2. O handler roda na tarefa do loop padrão; bloquear nele atrasa todos os outros eventos (inclusive os do Wi-Fi). Sinalize uma tarefa e faça o HTTP nela.
3. Esperas antes das tentativas 2 a 8: 1 + 2 + 4 + 8 + 16 + 32 + 60 = 123 s.
4. `WIFI_REASON_4WAY_HANDSHAKE_TIMEOUT` (15), às vezes 204 ou 202.
5. No canal 11: o canal da rede externa da station tem prioridade.
6. 10 (`ESP_WIFI_MAX_CONN_NUM` do C3).
7. Provar que quem está provisionando tem o aparelho em mãos (a PoP está na etiqueta ou dentro da caixa), impedindo que um vizinho provisione ou leia as credenciais.
8. Para que cada aparelho tenha um nome único e o usuário ache o seu quando há vários por perto.
9. `esp_wifi_set_ps(WIFI_PS_MIN_MODEM)` (o padrão) ou `WIFI_PS_MAX_MODEM` com *listen interval* maior.

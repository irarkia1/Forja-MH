# M1.12.T03 — Rádio e nuvem

> Tópico de **elite** (projeto). Tempo previsto: ~25 h — ≈ 4 h de estudo (documentação do Mosquitto, *ESP-MQTT* e *Wi-Fi Driver* do ESP-IDF, a especificação do MQTT nas partes de QoS e autorização), ≈ 3 h de projeto (contrato de mensagens, escolha de QoS e retain, PKI), ≈ 14 h de laboratório (broker com TLS e ACL, testes negativos, firmware de rede, reenvio, medida de 200 ciclos), ≈ 4 h de verificação e relatório. Terceira etapa: o nó passa a **falar**. O caminho é Wi-Fi → TCP → TLS → MQTT até um **broker próprio** (M1.10.T06), com uma credencial por estação e uma ACL que prende cada uma ao próprio ramo de tópicos. Três ideias guiam a etapa: **segurança se prova com testes negativos** (o que deve ser recusado, é?), **"enviado" não é "entregue"** (a estação só apaga uma medida depois do PUBACK) e **o rádio é a maior conta de energia e de latência** do projeto (cada fase da conexão é medida). O broker, a PKI e a ACL foram executados no Mosquitto 2.0.20 em Docker, e os testes negativos da tabela foram rodados de verdade; o firmware de rede compilou no ESP-IDF 5.5; o contrato de mensagens foi testado no PC com gcc; a estação simulada em Python (paho-mqtt 2.1) foi executada contra esse broker, inclusive com o broker desligado no meio.

## Ao final você consegue
- Configurar o broker próprio (Mosquitto com TLS, usuário por dispositivo e ACL) e provar com testes negativos que conexões sem certificado válido, sem senha ou fora do ramo de tópicos do dispositivo são recusadas.
- Implementar no ESP32 a conexão Wi-Fi rápida e o cliente MQTT sobre TLS (verificação do certificado, QoS, retain, espera da confirmação antes de dormir) e escolher o QoS e o retain de cada tipo de mensagem.
- Definir o contrato das mensagens (árvore de tópicos, payload com identificador, número de sequência, lote e carimbo de tempo, configuração retida) e implementar o armazenamento e reenvio quando a rede ou o broker falham.
- Medir a duração de cada fase da conexão, a taxa de entrega e os bytes por mensagem em centenas de ciclos e confrontar os resultados com os requisitos de latência, entrega e energia.

## Resumo
**1. O broker: TLS, uma senha por estação e ACL.** A configuração de referência tem **dois listeners**: o **8883**, o único publicado para fora, só com TLS; e o **1883**, sem TLS, que só existe dentro da rede do Docker para os serviços do servidor (o Telegraf do T04). As regras de autenticação valem para os dois.
```
# mosquitto.conf — broker da estação (Mosquitto 2.0)
persistence true
persistence_location /mosquitto/data/
log_dest stdout
log_type error
log_type warning
log_type notice
log_type information
connection_messages true

# Porta externa: só TLS
listener 8883
cafile /mosquitto/config/certs/ca.crt
certfile /mosquitto/config/certs/broker.crt
keyfile /mosquitto/config/certs/broker.key
tls_version tlsv1.2

# Porta interna, sem TLS: só para os serviços da rede do Docker (não publicada no host)
listener 1883

# Valem para os dois listeners (per_listener_settings é false por padrão)
allow_anonymous false
password_file /mosquitto/config/passwd
acl_file /mosquitto/config/acl
```
A **PKI** é sua: uma CA própria (chave guardada **fora** do servidor) assina o certificado do broker, com o nome que a estação vai usar (`broker.local`) e, se ela conectar por IP, o IP no *subjectAltName*. Chaves ECDSA P-256 deixam o certificado e o handshake menores que RSA 2048 — meça a diferença na sua placa.
```sh
#!/bin/sh
# pki.sh — CA própria e certificado do broker (ECDSA P-256). Rode uma vez, guarde ca.key fora do servidor.
set -e
cd mosquitto/config/certs
openssl ecparam -name prime256v1 -genkey -noout -out ca.key
openssl req -x509 -new -key ca.key -sha256 -days 3650 -subj "/CN=CA da Forja" -out ca.crt
openssl ecparam -name prime256v1 -genkey -noout -out broker.key
openssl req -new -key broker.key -subj "/CN=broker.local" -out broker.csr
printf "subjectAltName=DNS:broker.local,DNS:localhost,IP:127.0.0.1\nextendedKeyUsage=serverAuth\n" > ext.cnf
openssl x509 -req -in broker.csr -CA ca.crt -CAkey ca.key -CAcreateserial -days 825 -sha256 -extfile ext.cnf -out broker.crt
chmod 644 broker.key    # o processo do container precisa ler; no servidor real, ajuste o dono
openssl verify -CAfile ca.crt broker.crt
```
**ACL**: sem uma linha que permita, é negado. O `pattern` com `%u` (nome de usuário) prende cada estação ao próprio ramo com uma regra só; o usuário de cada estação é o próprio id (`est-01`).
```
# acl — quem pode o quê. Sem linha que permita, é negado.
# Telegraf: só lê os dados das estações
user telegraf
topic read forja/estacao/+/lote
topic read forja/estacao/+/alerta

# Administrador: publica as configurações (retidas) e lê tudo
user admin
topic readwrite forja/#

# Cada estação, só no próprio ramo (%u = nome de usuário = id da estação)
pattern write forja/estacao/%u/lote
pattern write forja/estacao/%u/alerta
pattern write forja/estacao/%u/estado
pattern read forja/estacao/%u/config
```
Usuários e senhas: `mosquitto_passwd -b passwd est-01 <senha>` (o arquivo guarda só o hash). O Mosquitto 2.0.20 já **avisa** quando o arquivo de senhas é legível por todos ou não pertence ao root: "*Future versions will refuse to load this file*". Ajuste dono e permissões no servidor.

**2. Segurança se prova com testes negativos.** Executados no broker acima (Mosquitto 2.0.20, clientes `mosquitto_pub` e `openssl s_client`):

| Teste | Resultado observado | Conclusão |
|---|---|---|
| est-01, CA certa, senha certa, no próprio ramo, QoS 1 | `PUBACK (Mid: 1, RC:0)`; o assinante recebe | caminho feliz |
| cliente sem TLS na porta 8883 | `Error: Protocol error` | não há texto puro na porta externa |
| TLS com as CAs do sistema (sem a sua CA) | o cliente recusa; o broker registra `tlsv1 alert unknown ca` | sem a CA certa, não conecta |
| TLS com a CA certa, mas conectando por um nome que não está no certificado | o cliente recusa | a verificação do nome funciona |
| senha errada | `Connection Refused: not authorised` | autenticação |
| est-01 publica em `forja/estacao/est-02/lote`, **MQTT 3.1.1**, QoS 1 | `PUBACK (RC:0)`, mas a mensagem **não chega** ao assinante | a ACL barra **em silêncio** |
| o mesmo, **MQTT 5** | `PUBACK (RC:135)` = 0x87, *Not authorized* | no MQTT 5 o cliente fica sabendo |
| telegraf publica configuração retida | não chega a ninguém | o leitor não escreve |
| `openssl s_client -tls1_2` e `-tls1_3` com `tls_version tlsv1.2` | os dois negociam | no Mosquitto 2.0, `tls_version` é a versão **mínima** |

Duas lições que só os testes mostram:
- No **MQTT 3.1.1**, uma publicação negada pela ACL recebe **PUBACK normal** e é descartada. A estação acha que entregou e **apaga o buffer**. Um erro de ACL (um id digitado errado) vira perda silenciosa de dados — que só o contador de sequência do T04 descobre. O MQTT 5 devolve o *reason code* 0x87 (o esp-mqtt suporta MQTT 5 com `CONFIG_MQTT_PROTOCOL_5`): é um bom ADR.
- **Verificar o certificado** é o que faz o TLS proteger contra um broker falso. Um cliente com a verificação desligada (`--insecure`, ou `skip_cert_common_name_check` no esp-mqtt) cifra o tráfego para **qualquer um** que responda.

**3. Wi-Fi rápido.** O tempo de rádio é quase todo **associação, DHCP e TLS**, não o dado. Alavancas, em ordem de ganho típico:
- **Canal e BSSID salvos** na RTC (`wc.sta.channel`, `wc.sta.bssid`, `bssid_set`): sem varredura de todos os canais. Se o AP mudar, a conexão falha, a estação zera o canal salvo e a próxima vez faz varredura completa.
- **IP estático** (reserva no roteador, `esp_netif_dhcpc_stop` + `esp_netif_set_ip_info`): elimina o DHCP, de centenas de ms a alguns segundos em roteadores lentos. Custa uma configuração por instalação: registre no README.
- `esp_wifi_set_storage(WIFI_STORAGE_RAM)`: não regrava a configuração na flash a cada boot.
- **SNTP só quando o relógio nunca foi acertado** (power-on): o ESP-IDF mantém a hora do sistema durante o deep sleep; acerte de novo uma vez por dia, no envio que tiver folga.
- **TLS**: certificado ECDSA pequeno, uma cadeia curta (só a CA própria). Retomar a sessão TLS depois de um deep sleep exige guardar o estado da sessão na RTC — avançado; meça antes de tentar.

**4. QoS, retain e sessão para cada mensagem.**

| Mensagem | Tópico | QoS | Retain | Por quê |
|---|---|---|---|---|
| lote de medidas | `forja/estacao/<id>/lote` | **1** | não | precisa do PUBACK para apagar o buffer; duplicatas são inofensivas porque cada medida tem `seq` e carimbo de tempo (no InfluxDB, o mesmo ponto escrito duas vezes é sobrescrito) |
| alerta | `forja/estacao/<id>/alerta` | **1** | não | precisa chegar; um alerta retido seria entregue de novo a todo assinante novo, como se fosse atual |
| estado (versão, último boot) | `forja/estacao/<id>/estado` | 1 | **sim** | quem assina depois recebe o último estado conhecido |
| configuração | `forja/estacao/<id>/config` | 1 | **sim** | a estação dorme 99,9 % do tempo: a configuração retida a espera e é entregue logo após o SUBSCRIBE |

- **QoS 0** num nó que apaga o buffer depois de "publicar" perde dados sempre que a conexão cai entre o `publish` e o `disconnect`. **QoS 2** garante "exatamente uma vez" com mais duas mensagens (PUBREC, PUBREL, PUBCOMP): mais tempo acordado para resolver um problema que o `seq` já resolve.
- **LWT** não serve a um nó que dorme: ele desconecta **limpo** a cada ciclo (DISCONNECT), e o broker só publica o testamento em desconexões anormais. "Estação fora do ar" se detecta pela **ausência de dados** (alerta "estação muda" do T04).
- **Sessão**: com sessão limpa e configuração retida, a estação não depende de o broker guardar nada para ela. Uma sessão persistente com assinatura QoS 1 também entregaria mensagens enfileiradas durante o sono — à custa de estado no broker e de uma decisão a mais (ADR).

**5. O contrato das mensagens.** O contrato é o que o firmware, o Telegraf, o dashboard e quem ler o README precisam concordar. Ele vai para `docs/mensagens.md` com exemplos reais:
- **Lote** (as medidas mais antigas primeiro, até 12 por mensagem): `id`, `fw`, `boot`, `rst` (causa do último reset), `vbat` (mV), `rssi` (dBm), `perd` (medidas perdidas desde o power-on) e `m`, a lista de medidas, cada uma com `s` (sequência), `t` (Unix, s), `T` (°C) e `U` (%UR). Um lote de 6 tem **354 bytes**; um de 12, **624 bytes** (medidos pelo teste abaixo).
- **Alerta**: `id`, `s`, `t`, `T`, `ativo` (entrou ou saiu), `alto`, `baixo`.
- **Configuração** (do servidor para a estação): `{"alto":31.5,"baixo":8,"hist":0.5,"lote":6}`; chaves ausentes mantêm o valor; uma configuração inválida (limiar alto abaixo do baixo, lote fora de 1–12) é **rejeitada inteira**.
- **Sequência**: `seq` cresce a cada medida e só volta a zero num power-on (o `boot` e o `rst` mostram quando). Lacunas na sequência que não estão em `perd` são **perda não explicada** — o que o RNF-05 conta.
- **Tempo**: o carimbo é da **medida**, não do envio; o servidor grava a medida no instante em que ela aconteceu, não 30 min depois.

```c
/* mensagem.h — contrato das mensagens (T03): JSON montado sem alocação dinâmica. */
#pragma once
#include <stddef.h>
#include "ciclo.h"

#define FW_VERSAO   "1.0.0"
#define LOTE_MAX_MSG 12                 /* medidas por mensagem: ~640 B de JSON */

typedef struct {
    uint32_t boots;
    uint8_t  causa_reset;               /* esp_reset_reason() */
    uint16_t vbat_mv;
    int8_t   rssi;
    uint32_t perdidas;
} saude_t;

int  msg_lote(char *b, size_t tam, const char *id, const medida_t *m, uint16_t n, const saude_t *s);
int  msg_alerta(char *b, size_t tam, const char *id, const medida_t *m, bool ativo, const config_t *c);
```

```c
#include "mensagem.h"
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/* centésimos → "-0.50", "23.41": o %d.%02d ingênuo perde o sinal entre −1 e 0 °C */
static void fmt_cc(char *o, size_t tam, int32_t v)
{
    snprintf(o, tam, "%s%ld.%02ld", v < 0 ? "-" : "", labs(v) / 100, labs(v) % 100);
}

int msg_lote(char *b, size_t tam, const char *id, const medida_t *m, uint16_t n, const saude_t *s)
{
    int k = snprintf(b, tam, "{\"id\":\"%s\",\"fw\":\"%s\",\"boot\":%lu,\"rst\":%u,\"vbat\":%u,"
                     "\"rssi\":%d,\"perd\":%lu,\"m\":[", id, FW_VERSAO, (unsigned long)s->boots,
                     s->causa_reset, s->vbat_mv, s->rssi, (unsigned long)s->perdidas);
    for (uint16_t j = 0; j < n && k > 0 && (size_t)k < tam; j++) {
        char t[12];
        fmt_cc(t, sizeof t, m[j].temp_cc);
        k += snprintf(b + k, tam - k, "%s{\"s\":%lu,\"t\":%lu,\"T\":%s,\"U\":%u.%u}", j ? "," : "",
                      (unsigned long)m[j].seq, (unsigned long)m[j].t, t, m[j].ur_dp / 10, m[j].ur_dp % 10);
    }
    if (k > 0 && (size_t)k < tam) k += snprintf(b + k, tam - k, "]}");
    return (k > 0 && (size_t)k < tam) ? k : -1;          /* -1: não coube */
}

int msg_alerta(char *b, size_t tam, const char *id, const medida_t *m, bool ativo, const config_t *c)
{
    char t[12], la[12], lb[12];
    fmt_cc(t, sizeof t, m->temp_cc);
    fmt_cc(la, sizeof la, c->alto_cc);
    fmt_cc(lb, sizeof lb, c->baixo_cc);
    int k = snprintf(b, tam, "{\"id\":\"%s\",\"s\":%lu,\"t\":%lu,\"T\":%s,\"ativo\":%s,\"alto\":%s,\"baixo\":%s}",
                     id, (unsigned long)m->seq, (unsigned long)m->t, t, ativo ? "true" : "false", la, lb);
    return (k > 0 && (size_t)k < tam) ? k : -1;
}

/* Lê {"alto":31.5,"baixo":8,"hist":0.5,"lote":6}; chaves ausentes mantêm o valor atual.
   Valores fora da faixa invalidam a mensagem inteira (configuração ruim não entra). */
static bool num(const char *j, const char *chave, float *v)
{
    char pad[16];
    snprintf(pad, sizeof pad, "\"%s\":", chave);
    const char *p = strstr(j, pad);
    if (!p) return false;
    char *fim;
    *v = strtof(p + strlen(pad), &fim);
    return fim != p + strlen(pad);
}

bool msg_config(const char *json, config_t *c)
{
    config_t n = *c;
    float v;
    if (num(json, "alto", &v))  n.alto_cc  = (int16_t)(v * 100.0f + (v >= 0 ? 0.5f : -0.5f));
    if (num(json, "baixo", &v)) n.baixo_cc = (int16_t)(v * 100.0f + (v >= 0 ? 0.5f : -0.5f));
    if (num(json, "hist", &v))  n.hist_cc  = (int16_t)(v * 100.0f + 0.5f);
    if (num(json, "lote", &v))  n.lote     = (uint8_t)v;
    if (n.alto_cc <= n.baixo_cc + 2 * n.hist_cc || n.hist_cc < 0 || n.lote < 1 || n.lote > LOTE_MAX_MSG) return false;
    *c = n;
    return true;
}
```

**6. Armazenar e reenviar.** O `main.c` do T02 já faz a parte da estação: publica o alerta, depois o buffer em mensagens de até 12 medidas, e **só descarta cada mensagem depois do PUBACK dela**; se uma falhar, as seguintes ficam para o próximo envio, com o recuo exponencial do T02. O que falta é a rede de verdade, abaixo. Do lado do servidor, o reenvio aparece como medidas antigas chegando com o carimbo certo — por isso o banco usa o tempo da medida.

```c
/* Conexão rápida: o canal e o BSSID do último AP ficam na RTC; sem eles, varredura completa. */
static RTC_DATA_ATTR uint8_t ap_canal;
static RTC_DATA_ATTR uint8_t ap_bssid[6];

static uint32_t ms(void) { return (uint32_t)(esp_timer_get_time() / 1000); }

static void ao_wifi(void *a, esp_event_base_t base, int32_t id, void *dados)
{
    if (base == WIFI_EVENT && id == WIFI_EVENT_STA_START) {
        esp_wifi_connect();
    } else if (base == WIFI_EVENT && id == WIFI_EVENT_STA_CONNECTED) {
        wifi_event_sta_connected_t *c = dados;
        ap_canal = c->channel;
        memcpy(ap_bssid, c->bssid, 6);
    } else if (base == WIFI_EVENT && id == WIFI_EVENT_STA_DISCONNECTED) {
        /* Falhou antes de ter IP: o AP salvo pode ter mudado; na próxima vez, varredura completa.
           Desconexões depois do IP (inclusive a do esp_wifi_stop no fim do ciclo) não apagam o canal. */
        if (!(xEventGroupGetBits(ev) & B_IP)) ap_canal = 0;
        xEventGroupSetBits(ev, B_ERRO);
    } else if (base == IP_EVENT && id == IP_EVENT_STA_GOT_IP) {
        tempos.ip_ms = ms();
        xEventGroupSetBits(ev, B_IP);
    }
}

static void ao_mqtt(void *a, esp_event_base_t base, int32_t id, void *dados)
{
    esp_mqtt_event_handle_t e = dados;
    switch ((esp_mqtt_event_id_t)id) {
    case MQTT_EVENT_CONNECTED:
        esp_mqtt_client_subscribe(cli, "forja/estacao/" ESTACAO_ID "/config", 1);
        tempos.mqtt_ms = ms();
        xEventGroupSetBits(ev, B_MQTT);
        break;
    case MQTT_EVENT_PUBLISHED:                   /* PUBACK (QoS 1) ou PUBCOMP (QoS 2) */
        ultimo_puback = e->msg_id;
        xEventGroupSetBits(ev, B_PUBACK);
        break;
    case MQTT_EVENT_DATA:                        /* a config retida chega logo após o SUBACK */
        if (e->data_len < (int)sizeof config_json) {
            memcpy(config_json, e->data, e->data_len);
            config_json[e->data_len] = '\0';
            xEventGroupSetBits(ev, B_CONFIG);
        }
        break;
    case MQTT_EVENT_ERROR:
    case MQTT_EVENT_DISCONNECTED:
        xEventGroupSetBits(ev, B_ERRO);
        break;
    default:
        break;
    }
}

void rede_iniciar(void)
{
    ev = xEventGroupCreate();
    esp_netif_init();
    esp_event_loop_create_default();
    esp_netif_create_default_wifi_sta();
    wifi_init_config_t ci = WIFI_INIT_CONFIG_DEFAULT();
    esp_wifi_init(&ci);
    esp_event_handler_register(WIFI_EVENT, ESP_EVENT_ANY_ID, ao_wifi, NULL);
    esp_event_handler_register(IP_EVENT, IP_EVENT_STA_GOT_IP, ao_wifi, NULL);

    wifi_config_t wc = {0};
    strncpy((char *)wc.sta.ssid, WIFI_SSID, sizeof wc.sta.ssid);
    strncpy((char *)wc.sta.password, WIFI_SENHA, sizeof wc.sta.password);
    wc.sta.threshold.authmode = WIFI_AUTH_WPA2_PSK;
    wc.sta.scan_method = WIFI_FAST_SCAN;
    if (ap_canal) {                              /* pula a varredura: vai direto ao AP conhecido */
        wc.sta.channel = ap_canal;
        memcpy(wc.sta.bssid, ap_bssid, 6);
        wc.sta.bssid_set = true;
    }
    esp_wifi_set_storage(WIFI_STORAGE_RAM);      /* não grava a config na flash a cada boot */
    esp_wifi_set_mode(WIFI_MODE_STA);
    esp_wifi_set_config(WIFI_IF_STA, &wc);
    esp_wifi_start();
}

bool rede_conectar(uint32_t prazo_ms)
{
    uint32_t fim = ms() + prazo_ms;
    EventBits_t b = xEventGroupWaitBits(ev, B_IP | B_ERRO, pdFALSE, pdFALSE, pdMS_TO_TICKS(prazo_ms));
    if (!(b & B_IP)) return false;

    if (time(NULL) < 1700000000) {               /* relógio nunca acertado (power-on): SNTP */
        esp_sntp_config_t sc = ESP_NETIF_SNTP_DEFAULT_CONFIG("pool.ntp.org");
        esp_netif_sntp_init(&sc);
        esp_netif_sntp_sync_wait(pdMS_TO_TICKS(3000));
        esp_netif_sntp_deinit();
    }

    xEventGroupClearBits(ev, B_ERRO);
    esp_mqtt_client_config_t mc = {
        .broker.address.uri = MQTT_URI,
        .broker.verification.certificate = ca_crt_inicio,    /* sem isto, não há TLS de verdade */
        .credentials.client_id = ESTACAO_ID,
        .credentials.username = ESTACAO_ID,
        .credentials.authentication.password = MQTT_SENHA,
        .session.keepalive = 30,
        .network.timeout_ms = 5000,
        .network.disable_auto_reconnect = true,  /* quem decide tentar de novo é o ciclo */
    };
    cli = esp_mqtt_client_init(&mc);
    esp_mqtt_client_register_event(cli, ESP_EVENT_ANY_ID, ao_mqtt, NULL);
    esp_mqtt_client_start(cli);
    uint32_t agora = ms();
    b = xEventGroupWaitBits(ev, B_MQTT | B_ERRO, pdFALSE, pdFALSE,
                            pdMS_TO_TICKS(fim > agora ? fim - agora : 1));
    return (b & B_MQTT) != 0;
}

bool rede_publicar(const char *topico, const char *dados, int qos, bool retain, uint32_t prazo_ms)
{
    xEventGroupClearBits(ev, B_PUBACK);
    int id = esp_mqtt_client_publish(cli, topico, dados, 0, qos, retain);
    if (id < 0) return false;
    if (qos == 0) return true;                   /* QoS 0: "enviado" não quer dizer "recebido" */
    uint32_t fim = ms() + prazo_ms;
    while (ms() < fim) {                         /* espera o PUBACK DESTA mensagem */
        EventBits_t b = xEventGroupWaitBits(ev, B_PUBACK | B_ERRO, pdTRUE, pdFALSE,
                                            pdMS_TO_TICKS(fim - ms() + 1));
        if (b & B_ERRO) return false;
        if ((b & B_PUBACK) && ultimo_puback == id) {
            tempos.puback_ms = ms();
            return true;
        }
    }
    return false;
}

bool rede_config(config_t *c)
{
    EventBits_t b = xEventGroupWaitBits(ev, B_CONFIG, pdTRUE, pdFALSE, pdMS_TO_TICKS(200));
    return (b & B_CONFIG) && msg_config(config_json, c);
}

int rede_rssi(void)
{
    wifi_ap_record_t ap;
    return esp_wifi_sta_get_ap_info(&ap) == ESP_OK ? ap.rssi : 0;
}

void rede_encerrar(void)
{
    if (cli) {
        esp_mqtt_client_disconnect(cli);         /* DISCONNECT limpo: o broker não publica o LWT */
        esp_mqtt_client_stop(cli);
        esp_mqtt_client_destroy(cli);
        cli = NULL;
    }
    esp_event_handler_unregister(WIFI_EVENT, ESP_EVENT_ANY_ID, ao_wifi);
    esp_wifi_stop();
    ESP_LOGI(TAG, "FASES,ip=%lu,mqtt=%lu,puback=%lu", (unsigned long)tempos.ip_ms,
             (unsigned long)tempos.mqtt_ms, (unsigned long)tempos.puback_ms);
}

const rede_tempos_t *rede_tempos(void) { return &tempos; }
```

Pontos do código ligados aos requisitos:
- **Espera do PUBACK da mensagem certa**: o evento `MQTT_EVENT_PUBLISHED` traz o `msg_id`; o código só considera entregue a mensagem cujo id foi devolvido pelo `publish`. O bit é limpo **antes** de publicar, então um PUBACK que chegue antes da espera não se perde.
- **Canal salvo só se apaga numa falha antes do IP**: o `esp_wifi_stop()` do fim de cada ciclo também gera `WIFI_EVENT_STA_DISCONNECTED`; apagar o canal ali anularia a conexão rápida em todos os ciclos (o código ainda remove o tratador antes de parar o Wi-Fi).
- `disable_auto_reconnect = true`: quem decide tentar de novo é o ciclo (com recuo), não a biblioteca, que tentaria até a bateria acabar.
- O `ca.crt` entra no binário por `EMBED_TXTFILES` (ou `board_build.embed_txtfiles` no PlatformIO). **Segredos** (`segredos.h`: SSID, senhas) ficam fora do git; o repositório leva um `segredos.exemplo.h`.
- A linha `FASES,ip=…,mqtt=…,puback=…` (milissegundos desde o boot) é o dado bruto da medida da seção 8.

**8. Medir: fases, entrega e bytes.** Para cada ciclo de envio, o log tem os instantes (desde o boot) de IP obtido, MQTT conectado e PUBACK do último lote. Em 200 ciclos, calcule para cada fase a **mediana** e o **percentil 95** (p95) e a **taxa de sucesso na primeira tentativa**. Exemplo de formato (números ilustrativos, não medidos):

| Fase | Mediana | p95 |
|---|---|---|
| boot → IP (associação + DHCP) | 0,85 s | 1,60 s |
| IP → MQTT conectado (DNS, TCP, TLS, CONNECT) | 0,55 s | 0,90 s |
| MQTT → último PUBACK | 0,06 s | 0,15 s |
| **total do ciclo de envio** | **1,6 s** | **2,7 s** |

Critérios do projeto: p95 do ciclo de envio ≤ 3 s (RNF-07) e ≥ 99 % de sucesso na primeira tentativa com RSSI ≥ −75 dBm. Repita com o canal/BSSID salvos e sem eles, com IP fixo e com DHCP: a diferença entre as colunas é a justificativa medida de cada otimização (e alimenta o T05).

**Bytes**: um PUBLISH de lote de 6 leva cabeçalho fixo (1 byte + 2 de *remaining length*, porque passa de 127), tópico (2 + 25 bytes para `forja/estacao/est-01/lote`), identificador do pacote (2) e os 354 de payload: **386 bytes**, mais o *overhead* do registro TLS (no TLS 1.2 com AES-GCM, 29 bytes por registro). O handshake TLS, com certificados, custa alguns kB e domina o tráfego de uma conexão curta. Confira com `tcpdump`/Wireshark no servidor: é a medida que decide se vale a pena retomar sessão TLS ou trocar JSON por CBOR (M1.10.T05) — quase sempre, o JSON não é o problema.

```python
# estacao_sim.py — estação simulada com o mesmo contrato de mensagens do firmware (sem hardware).
# Mede a cada --periodo s (tempo acelerado), envia em lotes, alerta com histerese, guarda e
# reenvia quando o broker falha, espera o PUBACK. NÃO substitui o hardware: não há rádio,
# nem deep sleep, nem consumo. Uso:
#   python3 estacao_sim.py --host localhost --porta 8883 --ca ca.crt --id est-01 --senha ... \
#          --periodo 5 --aquecer 60
import argparse, json, math, random, ssl, time
import paho.mqtt.client as mqtt

a = argparse.ArgumentParser()
a.add_argument('--host', default='localhost'); a.add_argument('--porta', type=int, default=8883)
a.add_argument('--ca', default='ca.crt'); a.add_argument('--id', default='est-01')
a.add_argument('--senha', required=True); a.add_argument('--periodo', type=float, default=5.0)
a.add_argument('--lote', type=int, default=6); a.add_argument('--ciclos', type=int, default=0)
a.add_argument('--aquecer', type=float, default=0, help='s após o início para subir a 32 °C por 1 min')
a.add_argument('--alto', type=float, default=30.0); a.add_argument('--hist', type=float, default=0.5)
o = a.parse_args()

buf, seq, em_alerta, perdidas, falhas, inicio = [], 0, False, 0, 0, time.time()

def temperatura(t):
    base = 24 + 2 * math.sin(2 * math.pi * t / 600) + random.gauss(0, 0.05)
    if o.aquecer and o.aquecer <= t < o.aquecer + 60:
        base = 32.0 + random.gauss(0, 0.05)
    return round(base, 2)

def enviar(mensagens):
    """Conecta, publica cada (tópico, payload) com QoS 1, espera os PUBACKs e desconecta."""
    c = mqtt.Client(mqtt.CallbackAPIVersion.VERSION2, client_id=o.id, protocol=mqtt.MQTTv311)
    c.username_pw_set(o.id, o.senha)
    c.tls_set(ca_certs=o.ca, tls_version=ssl.PROTOCOL_TLS_CLIENT)
    t0 = time.time()
    try:
        c.connect(o.host, o.porta, keepalive=30)
    except OSError as e:
        print(f'# falha ao conectar: {e}')
        return 0
    c.loop_start()
    ok = 0
    for topico, carga in mensagens:
        info = c.publish(topico, carga, qos=1)
        info.wait_for_publish(timeout=3)
        if not info.is_published():
            break
        ok += 1
    c.disconnect(); c.loop_stop()
    print(f'# envio: {ok}/{len(mensagens)} mensagens em {1000 * (time.time() - t0):.0f} ms')
    return ok

while o.ciclos == 0 or seq < o.ciclos:
    t = time.time() - inicio
    temp = temperatura(t)
    agora = int(time.time())
    if len(buf) == 48:
        buf.pop(0); perdidas += 1
    buf.append({'s': seq, 't': agora, 'T': temp, 'U': 50.0})
    seq += 1
    msgs = []
    if not em_alerta and temp > o.alto:
        em_alerta = True
        msgs.append((f'forja/estacao/{o.id}/alerta', json.dumps({'id': o.id, 's': seq - 1, 't': agora, 'T': temp, 'ativo': True})))
        print(f'ALERTA,{time.time():.3f},seq={seq - 1},T={temp}')
    elif em_alerta and temp <= o.alto - o.hist:
        em_alerta = False
        msgs.append((f'forja/estacao/{o.id}/alerta', json.dumps({'id': o.id, 's': seq - 1, 't': agora, 'T': temp, 'ativo': False})))
    if msgs or len(buf) >= o.lote * (1 << min(falhas, 3)):
        lotes = [buf[k:k + 12] for k in range(0, len(buf), 12)]
        for m in lotes:
            msgs.append((f'forja/estacao/{o.id}/lote', json.dumps({'id': o.id, 'fw': 'sim', 'boot': 1, 'rst': 1, 'vbat': 3900,
                                                                    'rssi': -60, 'perd': perdidas, 'm': m}, separators=(',', ':'))))
        n_alerta = len(msgs) - len(lotes)
        ok = enviar(msgs)
        if ok == len(msgs):
            buf.clear(); falhas = 0
        else:
            del buf[:12 * max(0, ok - n_alerta)]     # só apaga os lotes confirmados
            falhas += 1
    time.sleep(o.periodo)
```

## Gabarito
1. `publish` com QoS 1 só põe a mensagem na saída; a conexão pode cair antes de o broker recebê-la. O PUBACK é a única prova de que o broker a aceitou. Apagar antes transforma qualquer queda em perda.
2. Não: no 3.1.1 o Mosquitto confirma e descarta a mensagem negada pela ACL. No servidor, o assinante não recebe nada e a contagem de `seq` da est-01 no banco mostra uma lacuna (ou nenhum dado); com MQTT 5, o PUBACK traria 0x87 (*Not authorized*).
3. O LWT só é publicado quando a conexão termina sem DISCONNECT (queda, keepalive vencido). A estação desconecta limpo a cada ciclo; quando a bateria acaba, ela simplesmente não conecta mais — não há conexão para cair. Detecta-se pela ausência de dados.
4. Lote: QoS 1, sem retain. Alerta: QoS 1, sem retain — retido, seria reentregue como atual a cada assinante novo. Estado: QoS 1, retido. Configuração: QoS 1, retida (a estação dorme e a recebe ao assinar).
5. Payload 354 + identificador 2 + tópico (2 + 25) = 383 bytes de *remaining length*, que precisa de 2 bytes para ser codificado (> 127); cabeçalho fixo = 1 + 2 = 3 → **386 bytes**.
6. 197/200 = 98,5 %: **não** atende. Investigue o RSSI, o canal salvo e o tempo limite.
7. A cauda (p95), porque é ela que quebra o RNF-07 e a latência do alerta. Separe por fase: se a associação domina a cauda, provável varredura completa (canal salvo perdido) ou AP sobrecarregado; se o TLS domina, servidor lento ou DNS.
8. No InfluxDB, um ponto é identificado por medição, conjunto de tags e carimbo de tempo; escrever de novo o mesmo ponto sobrescreve os campos. A medida reenviada tem o mesmo carimbo e os mesmos valores: o resultado é idêntico.
9. Sem hora acertada, o relógio marca perto de 1970: a medida sai com um carimbo absurdo (trate no servidor ou marque a medida como "sem hora" até o primeiro SNTP). No TLS, por padrão o mbedTLS do ESP-IDF não confere as datas de validade; com a verificação ligada, o certificado pareceria "ainda não válido" e o handshake falharia. Por isso o `rede_conectar` acerta a hora antes de conectar ao broker no primeiro boot.

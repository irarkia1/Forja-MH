# M1.2.T06 — Timers

> Um timer é um contador que anda sozinho, no ritmo do clock dividido por um prescaler. Com ele você mede tempo sem gastar CPU, gera eventos periódicos exatos, acorda uma ISR a cada milissegundo e — no T03 — gera PWM. É também o que está por baixo do `millis()` e o que permite trocar `delay()` (que congela tudo) por código que faz várias coisas "ao mesmo tempo". Pré-requisito: interrupções (T05).

## Ao final você consegue
- Descrever os Timer/Counter0, 1 e 2 (largura, prescalers e registradores TCNTn, OCRnx, TCCRnx, TIMSKn e TIFRn) e os modos Normal e CTC.
- Calcular o prescaler e o valor de OCR para gerar um evento periódico, e o período e o erro resultantes.
- Implementar uma base de tempo de 1 ms com CTC e ISR e explicar como o millis() do Arduino usa o estouro do Timer0.
- Comparar código bloqueante (delay, _delay_ms) com código não bloqueante baseado em millis e máquina de estados, incluindo o estouro do contador.

## Resumo
**1. Os três timers.**

| | Timer/Counter0 | Timer/Counter1 | Timer/Counter2 |
|---|---|---|---|
| Largura | 8 bits (0–255) | 16 bits (0–65 535) | 8 bits |
| Prescalers N | 1, 8, 64, 256, 1024 | 1, 8, 64, 256, 1024 | 1, 8, 32, 64, 128, 256, 1024 |
| Extras | entrada de contagem externa T0 (PD4) | captura de entrada (ICP1, PB0), entrada T1 (PD5), TOP em ICR1 | modo assíncrono com cristal de 32 768 Hz |
| No Arduino | `millis`, `micros`, `delay`, PWM de D5/D6 | PWM de D9/D10, biblioteca Servo | PWM de D3/D11, `tone()` |

Registradores (troque *n* pelo número do timer e *x* por A ou B):
- **TCNTn**: o contador. **OCRnA/OCRnB**: valores de comparação. Quando TCNTn = OCRnx, liga a flag **OCFnx** e pode mexer no pino OCnx.
- **TCCRnA/TCCRnB**: modo (bits **WGMn**), ação no pino (**COMnx**, T03) e clock (**CSn2:0**: 0 = parado, 1 = /1, 2 = /8, 3 = /64, 4 = /256, 5 = /1024 nos timers 0 e 1; o Timer2 tem codificação própria por causa do /32 e do /128).
- **TIMSKn**: habilitação das interrupções (**TOIEn** estouro, **OCIEnA/B** comparação). **TIFRn**: as flags (limpas escrevendo 1, ou ao entrar na ISR).
- O timer começa a contar **quando os bits CS saem de 0**. Configure tudo antes e ligue o clock por último.
- Registradores de 16 bits do Timer1 (TCNT1, OCR1A, ICR1) são acessados por um registrador temporário: escrita do byte alto primeiro, leitura do baixo primeiro. O avr-gcc faz isso na ordem certa quando você escreve `OCR1A = 62499;`, mas uma ISR que mexa no Timer1 entre os dois acessos corrompe o valor: proteja com ATOMIC_BLOCK se houver ISR mexendo no mesmo timer.

**2. Modos Normal e CTC.**
- **Normal**: conta de 0 até o máximo (255 ou 65 535), estoura para 0 e liga **TOVn**. Período do estouro = N × 2^bits/f_clk. **Exemplo 1.** Timer0 com N = 64 a 16 MHz: 64 × 256/16 MHz = **1,024 ms** — é o estouro que o `millis()` usa.
- **CTC** (*Clear Timer on Compare Match*): conta de 0 até **OCRnA** e volta a 0. Período = N × (1 + OCRnA)/f_clk, ou seja, f_evento = f_clk/(N·(1 + OCRnA)). Com COMnA0 = 1, o pino OCnA **inverte** a cada comparação: onda quadrada de f = f_clk/(2·N·(1 + OCRnA)), sem nenhuma instrução da CPU.

**3. Escolhendo N e OCR.** Contagens necessárias: C = f_clk/(N·f_alvo). Escolha o **menor N** que deixe C ≤ 256 (8 bits) ou ≤ 65 536 (16 bits) — o menor N dá a maior resolução. Arredonde C para inteiro; OCR = C − 1. Período real = N·C/f_clk; erro = (f_real − f_alvo)/f_alvo.

**Exemplo 2 (1 ms com o Timer0).** C = 16 × 10⁶/(N × 1000): N = 8 → 2000 (não cabe em 8 bits); N = 64 → **250** → OCR0A = **249**, exato.

**Exemplo 3 (1 Hz com o Timer1).** N = 64 → 250 000 (não cabe em 16 bits); N = 256 → 62 500 → OCR1A = **62 499**, exato.

**Exemplo 4 (3 kHz com o Timer0, inexato).** N = 8 → 666,7 (não cabe); N = 64 → 83,33 → C = 83, OCR0A = 82 → f = 16 × 10⁶/(64 × 83) = **3012,0 Hz**, erro de **+0,40 %**. O Timer1 com N = 1 faria C = 5333 → 3000,2 Hz (erro de 0,006 %): o timer de 16 bits compensa quando a precisão importa.

**Exemplo 5 (pisca de 1 Hz por ISR, Timer1 em CTC).**
```c
#include <avr/io.h>
#include <avr/interrupt.h>

ISR(TIMER1_COMPA_vect)
{
    PINB = (1 << PINB5);                 /* inverte o LED a cada 1 s */
}

int main(void)
{
    DDRB  |= (1 << DDB5);
    TCCR1A = 0;
    TCCR1B = (1 << WGM12);               /* modo 4: CTC com TOP em OCR1A */
    OCR1A  = 62499;                      /* 16 MHz/256/62 500 = 1 Hz */
    TIMSK1 = (1 << OCIE1A);
    TCCR1B |= (1 << CS12);               /* N = 256: o timer parte agora */
    sei();
    for (;;) {
        /* CPU livre para outra coisa */
    }
}
```
O LED fica 1 s aceso e 1 s apagado (0,5 Hz de pisca). Se quiser 1 Hz de pisca, a ISR precisa rodar a 2 Hz: OCR1A = 31 249.

**Exemplo 6 (onda quadrada por hardware no OC0A, D6).**
```c
#include <avr/io.h>

int main(void)
{
    DDRD  |= (1 << DDD6);                /* OC0A precisa ser saída */
    TCCR0A = (1 << COM0A0) | (1 << WGM01); /* toggle na comparação, CTC */
    OCR0A  = 124;                        /* 16 MHz/(2·64·125) = 1000 Hz */
    TCCR0B = (1 << CS01) | (1 << CS00);  /* N = 64 */
    for (;;) {
    }
}
```

**4. A base de tempo de 1 ms (o seu `millis`).**
```c
#include <avr/io.h>
#include <avr/interrupt.h>
#include <util/atomic.h>

static volatile uint32_t ms_contador;

ISR(TIMER0_COMPA_vect)
{
    ms_contador++;                       /* uma vez por milissegundo */
}

void tempo_inicia(void)
{
    TCCR0A = (1 << WGM01);               /* CTC */
    OCR0A  = 249;                        /* 250 contagens de 4 µs = 1 ms */
    TIMSK0 = (1 << OCIE0A);
    TCCR0B = (1 << CS01) | (1 << CS00);  /* N = 64 */
    sei();
}

uint32_t tempo_ms(void)
{
    uint32_t copia;
    ATOMIC_BLOCK(ATOMIC_RESTORESTATE) {  /* 32 bits = 4 leituras: atômico */
        copia = ms_contador;
    }
    return copia;
}
```
Conferido no simavr: depois de `_delay_ms(500)`, `tempo_ms()` devolve 501, e depois de mais `_delay_ms(1500)`, 2007. Os milissegundos a mais não são erro do timer: são o tempo que as próprias ISRs roubam do laço de espera do `_delay_ms`, que não sabe que foi interrompido (seção 5). O timer é a referência; o `_delay_ms`, não.

**Como o `millis()` do Arduino faz.** O núcleo configura o Timer0 em Fast PWM (para servir também o `analogWrite` de D5 e D6), com N = 64, e usa a interrupção de **estouro**, que acontece a cada 1,024 ms (Exemplo 1), e não a cada 1 ms. Em `wiring.c`, a ISR `TIMER0_OVF_vect` soma 1 ms (`MILLIS_INC`) e acumula a sobra de 24 µs numa fração em unidades de 8 µs (`FRACT_INC` = 3, `FRACT_MAX` = 125). Quando a fração passa de 125 (1000 µs), soma 1 ms extra. Resultado: o `millis()` não erra no longo prazo, mas de vez em quando **pula** um valor (a cada ~42 estouros) — `if (millis() == 5000)` pode nunca ser verdadeiro. Ele é um `unsigned long` (32 bits) e volta a 0 depois de 2³² ms ≈ **49,7 dias**. O `micros()` lê o TCNT0 e tem resolução de 4 µs.

**5. Bloqueante × não bloqueante.**
- `delay(500)` e `_delay_ms(500)` **prendem a CPU** num laço: durante esse tempo, nenhum botão é lido, nenhum byte da serial é tratado no laço principal (só as ISRs rodam). Dois LEDs em ritmos diferentes, um botão e uma serial ao mesmo tempo ficam impossíveis.
- `_delay_ms` ainda tem limites: o argumento precisa ser constante em tempo de compilação, depende do `F_CPU` e fica mais longo se ISRs roubarem tempo.
- **Não bloqueante**: o laço principal roda sem parar; cada tarefa guarda o instante da última ação e age quando passou o intervalo. É o padrão *BlinkWithoutDelay*. Quando a tarefa tem etapas (botão → espera → ação), use uma **máquina de estados**: uma variável `estado` e um `switch`.

**O estouro do contador.** Compare sempre **intervalos**, com subtração sem sinal: `if (agora - anterior >= intervalo)`. A aritmética sem sinal é módulo 2^n, e a diferença sai certa mesmo depois de o contador voltar a 0. Já `if (agora >= anterior + intervalo)` falha perto do estouro. **Exemplo 7** (contador de 16 bits para os números ficarem pequenos): anterior = 65 000, intervalo = 1000. Com agora = 65 100 (só 100 ms depois), anterior + intervalo = 66 000 → vira **464** em 16 bits, e 65 100 ≥ 464 dispara **cedo**. A subtração dá 65 100 − 65 000 = 100 < 1000, correto. Depois do estouro, com agora = 464: (464 − 65 000) mod 65 536 = **1000**, também correto.

**Exemplo 8 (duas tarefas e um botão, sem bloquear).** Usa o `tempo_ms()` acima:
```c
#include <avr/io.h>
#include <stdint.h>

uint32_t tempo_ms(void);                 /* da seção 4 */

enum estado_botao { SOLTO, CONFIRMANDO, APERTADO };

void tarefas(void)                       /* chamada sem parar no laço principal */
{
    static uint32_t t_led1, t_led2, t_botao;
    static enum estado_botao est = SOLTO;
    uint32_t agora = tempo_ms();

    if (agora - t_led1 >= 500) {         /* LED em PB5 a cada 500 ms */
        t_led1 += 500;                   /* += mantém o ritmo sem acumular atraso */
        PINB = (1 << PINB5);
    }
    if (agora - t_led2 >= 130) {         /* LED em PB4 a cada 130 ms */
        t_led2 += 130;
        PINB = (1 << PINB4);
    }

    uint8_t apertado = !(PIND & (1 << PIND2));
    switch (est) {                       /* debounce como máquina de estados */
    case SOLTO:
        if (apertado) { est = CONFIRMANDO; t_botao = agora; }
        break;
    case CONFIRMANDO:
        if (!apertado) est = SOLTO;      /* foi quique */
        else if (agora - t_botao >= 20) { est = APERTADO; PINB = (1 << PINB0); }
        break;
    case APERTADO:
        if (!apertado) est = SOLTO;      /* (a soltura também poderia ser confirmada) */
        break;
    }
}
```

## Pratique
1. Calcule o período de estouro do Timer2 com N = 1024 a 16 MHz. E do Timer1 com N = 1?
2. Encontre N e OCR para uma ISR a 250 Hz com o Timer0 e com o Timer1. Algum é exato?
3. Qual OCR0A, com N = 8, gera uma onda quadrada de 40 kHz no OC0A (modo toggle)? Qual a frequência real?
4. Reescreva o Exemplo 5 para piscar com período de 200 ms usando o Timer2.
5. Por que `if (millis() == 5000)` é uma má ideia? Proponha a versão correta.
6. Num contador de 8 bits, anterior = 250 e agora = 4. Quanto vale `(uint8_t)(agora - anterior)`?
7. Implemente um semáforo (verde 5 s, amarelo 2 s, vermelho 5 s) como máquina de estados, sem `delay`, e um botão de pedestre que encurta o verde.
8. Leia a ISR `TIMER0_OVF_vect` em `wiring.c` e calcule depois de quantos estouros o `millis()` ganha o primeiro ms extra.

## Armadilhas comuns
- Ligar o clock do timer (bits CS) antes de terminar a configuração.
- Esquecer o "+1" (o CTC conta de 0 a OCR: são OCR + 1 contagens).
- Confundir a frequência da ISR com a frequência da onda no pino em modo toggle (metade).
- Escolher prescaler grande demais e perder resolução.
- Ler o contador de ms de 32 bits sem ATOMIC_BLOCK.
- Testar `millis() == valor` ou `agora >= anterior + intervalo`.
- Usar o Timer0 por registrador num sketch Arduino e quebrar `millis`, `delay` e o PWM de D5/D6 (T08).
- Fazer `t_anterior = agora` quando o ritmo importa: o atraso de cada volta se acumula; `t_anterior += intervalo` não acumula.

## Gabarito
1. 1024 × 256/16 MHz = 16,384 ms; 65 536/16 MHz = 4,096 ms.
2. Timer0: C = 16 × 10⁶/(N × 250) → N = 256 → 250 → OCR0A = 249, exato. Timer1: N = 1 → 64 000 → OCR1A = 63 999, exato.
3. f = 16 × 10⁶/(2 × 8 × (1 + OCR)) = 40 000 → 1 + OCR = 25 → OCR0A = 24; 40 000 Hz exatos.
4. Com o Timer2, N = 1024 e OCR2A = 155: 16 × 10⁶/(1024 × 156) = 100,16 Hz de ISR; conte 10 ISRs para inverter o LED a cada ~100 ms (período de ~200 ms). Os bits CS do Timer2 para /1024 são CS22, CS21 e CS20.
5. O `millis()` pode pular o 5000, e o laço pode não passar pela comparação no ms exato. Use `if (millis() - inicio >= 5000)`.
6. (4 − 250) mod 256 = 10.
8. Cada estouro acumula 3 unidades de fração; 125/3 = 41,7 → no 42º estouro.

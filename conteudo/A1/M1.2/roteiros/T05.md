# M1.2.T05 — Interrupções

> Até agora o programa perguntava ao botão "e aí, mudou?" milhões de vezes por segundo (polling). Com interrupção, o hardware avisa: a CPU para o que está fazendo, roda uma função curta (a ISR) e volta. É o mecanismo de todos os periféricos seguintes — timer (T06), UART (T07), ADC (T04). O M1.3 já mostrou exceções e vetores no Cortex-M (T06) e a tabela de vetores do AVR em assembly (T09); aqui você programa as interrupções do ATmega328P em C e aprende a dividir dados entre a ISR e o `main` sem corromper nada.

## Ao final você consegue
- Explicar o caminho de uma interrupção no AVR (flag, habilitação local, bit I do SREG, vetor, ISR e RETI) e escrever ISRs com a macro ISR do avr-libc.
- Configurar as interrupções externas INT0 e INT1 (EICRA, EIMSK) e as interrupções de mudança de pino (PCICR, PCMSKx) e escolher entre elas.
- Compartilhar dados entre ISR e laço principal com volatile e acesso atômico (ATOMIC_BLOCK) e reconhecer condições de corrida.
- Calcular a latência e a carga de CPU das ISRs e aplicar as regras de ISR curta (sem espera, sem Serial, só sinalizar ao laço principal).

## Resumo
**1. O caminho de uma interrupção.** Cada fonte tem três chaves em série:
1. A **flag** do evento (ex.: INTF0 no EIFR) — o hardware liga quando o evento acontece, esteja a interrupção habilitada ou não.
2. A **habilitação local** (ex.: INT0 no EIMSK).
3. A **habilitação global**: o bit **I** do SREG (`sei()` liga, `cli()` desliga).

Com as três em 1, a CPU termina a instrução atual, **empilha o PC** (2 bytes), **zera o bit I** (por isso uma ISR não é interrompida por outra) e salta para o **vetor**: uma tabela no início da flash, com um `jmp` de 4 bytes por fonte. A ISR termina com **`reti`**, que desempilha o PC e religa o I. A flag é zerada pelo hardware ao entrar no vetor (para a maioria das fontes) ou escrevendo **1** nela. Se várias estão pendentes, vence a de **endereço de vetor menor** (RESET, INT0, INT1, PCINT0…). Uma flag que liga com I = 0 fica **pendente** e é atendida quando o I voltar a 1 — mas só uma vez: dois eventos durante o bloqueio viram um.

Trecho da tabela de vetores (numeração do datasheet; o endereço é de palavra; no `avr-objdump` aparece o endereço de byte, o dobro):

| Nº | Endereço (palavra) | Fonte | Nome no avr-libc |
|---|---|---|---|
| 1 | 0x0000 | RESET | — |
| 2 | 0x0002 | INT0 | `INT0_vect` |
| 3 | 0x0004 | INT1 | `INT1_vect` |
| 4–6 | 0x0006–0x000A | PCINT0, PCINT1, PCINT2 | `PCINT0_vect`… |
| 12 | 0x0016 | TIMER1 COMPA | `TIMER1_COMPA_vect` |
| 15 | 0x001C | TIMER0 COMPA | `TIMER0_COMPA_vect` |
| 17 | 0x0020 | TIMER0 OVF | `TIMER0_OVF_vect` |
| 19 | 0x0024 | USART RX | `USART_RX_vect` |
| 22 | 0x002A | ADC | `ADC_vect` |

Em C, a macro `ISR(nome_vect)` gera a função, o prólogo que salva os registradores e o `reti`. **Interrupção habilitada sem ISR** cai no `__bad_interrupt` do avr-libc, que salta para o endereço 0: o chip parece "resetar sozinho". Erro de digitação no nome do vetor gera só um aviso do compilador — leia os avisos.

**2. INT0/INT1 e PCINT.**
- **INT0 (PD2, D2) e INT1 (PD3, D3)**: cada uma com vetor próprio e sensibilidade escolhida no **EICRA** (bits ISCn1:ISCn0): 00 = nível baixo, 01 = qualquer mudança, 10 = borda de descida, 11 = borda de subida. Habilitação no **EIMSK**, flags no **EIFR**. A interrupção por **nível baixo** fica disparando enquanto o pino estiver baixo; o seu uso típico é acordar o chip do sono profundo.
- **PCINT (mudança de pino)**: qualquer um dos 23 pinos. Três vetores, um por porta (PCINT0 = porta B, PCINT1 = porta C, PCINT2 = porta D), ligados no **PCICR**; dentro da porta, cada pino é escolhido no **PCMSK0/1/2**. Dispara em **qualquer mudança** e não diz qual pino mudou: a ISR lê o PINx e compara com a leitura anterior.
- **Escolha**: INT0/INT1 quando você precisa de borda específica e de uma ISR por sinal (encoder rápido, sinal de sincronismo); PCINT quando faltam pinos INT ou para vários botões (um vetor para a porta inteira). As duas acordam o chip do modo *power-down* (INT0/INT1 só por nível nesse modo; veja a tabela de fontes de despertar em *Power Management and Sleep Modes*).

**Exemplo 1 (INT0 por borda de descida).** Botão em D2 com pull-up; a ISR só conta; o `main` decide o que fazer:
```c
#include <avr/io.h>
#include <avr/interrupt.h>
#include <util/atomic.h>

static volatile uint16_t apertos;          /* compartilhada: volatile */

ISR(INT0_vect)
{
    apertos++;                             /* curta: só registra o evento */
}

int main(void)
{
    DDRB  |= (1 << DDB5);
    PORTD |= (1 << PORTD2);                /* pull-up no INT0 (PD2) */
    EICRA  = (1 << ISC01);                 /* ISC01:ISC00 = 10: borda de descida */
    EIFR   = (1 << INTF0);                 /* limpa flag antiga (escrevendo 1) */
    EIMSK  = (1 << INT0);                  /* habilitação local */
    sei();                                 /* habilitação global */

    uint16_t visto = 0;
    for (;;) {
        uint16_t agora;
        ATOMIC_BLOCK(ATOMIC_RESTORESTATE) { /* leitura de 16 bits sem rasgo */
            agora = apertos;
        }
        if (agora != visto) {
            visto = agora;
            PINB = (1 << PINB5);           /* reage no laço principal */
        }
    }
}
```
Rodado no simavr com cinco bordas de descida no PD2 (arquivo VCD, como no T02), o contador termina em 5. Com um botão real, sem debounce, ele conta os quiques também: interrupção não resolve bounce (combine com o T02, ou desabilite o INT0 por 20 ms depois de cada borda usando o timer do T06).

**Exemplo 2 (PCINT em três pinos da porta B).** Botões em D8, D9 e D10 (PB0–PB2), um só vetor:
```c
#include <avr/io.h>
#include <avr/interrupt.h>

static volatile uint8_t eventos;           /* bit n = 1: PBn foi apertado */

ISR(PCINT0_vect)
{
    static uint8_t anterior = 0x07;        /* todos soltos (pull-up) */
    uint8_t agora = PINB & 0x07;
    uint8_t desceram = anterior & (uint8_t)~agora;  /* 1 → 0 */
    eventos |= desceram;
    anterior = agora;
}

void pcint_inicia(void)
{
    DDRB  &= ~0x07;
    PORTB |= 0x07;                         /* pull-ups em PB0..PB2 */
    PCMSK0 = (1 << PCINT0) | (1 << PCINT1) | (1 << PCINT2);
    PCIFR  = (1 << PCIF0);
    PCICR  = (1 << PCIE0);                 /* liga o vetor da porta B */
    sei();
}
```

No Arduino, `attachInterrupt(digitalPinToInterrupt(2), funcao, FALLING)` configura o EICRA e o EIMSK e guarda um ponteiro: a ISR do núcleo chama a sua função. Funciona só em D2 e D3 no Uno; para PCINT não há função no núcleo.

**3. Dados compartilhados.**
- **`volatile`**: sem ele, o compilador pode ler a variável uma vez, guardá-la num registrador e nunca mais olhar a memória. `while (!flag);` vira laço infinito. Toda variável escrita numa ISR e lida fora dela (ou o contrário) é `volatile`.
- **Atomicidade**: o AVR é de 8 bits. Ler um `uint16_t` são duas instruções `lds` (byte baixo, depois alto); se a ISR muda a variável entre as duas, você lê um valor **rasgado**. Exemplo: o contador vai de 0x00FF para 0x0100 entre as leituras → o `main` lê o byte baixo 0xFF (antigo) e o alto 0x01 (novo) = **0x01FF = 511**, um valor que nunca existiu. `ATOMIC_BLOCK(ATOMIC_RESTORESTATE)` desliga as interrupções durante o bloco e restaura o estado anterior do bit I no fim.
- **Leitura-modificação-escrita**: `contador--` no `main` (lê, decrementa, escreve) com `contador++` na ISR perde incrementos se a ISR cair no meio. O mesmo vale para `PORTB ^=` com vários bits (T02). `volatile` **não** resolve isso; só a seção atômica resolve.
- Variáveis de **8 bits** são lidas e escritas atomicamente; o `++` delas, não.

**4. Latência e carga.** Pelo datasheet, a resposta mínima é de **4 ciclos** (termina a instrução, empilha o PC, zera o I) + **3 ciclos** do `jmp` do vetor; do sono, mais 4 ciclos (mais o tempo de partida do oscilador, conforme o modo). Uma instrução de vários ciclos em execução termina antes. Depois vem o **prólogo** que o avr-gcc gera. Para a ISR `n8++` (variável de 8 bits), compilada com `-Os`:

| Trecho | Instruções | Ciclos |
|---|---|---|
| resposta + `jmp` | — | 4 + 3 = 7 |
| prólogo | push r1, push r0, in r0 SREG, push r0, eor r1, push r24 | 10 |
| corpo | lds, subi, sts | 5 |
| epílogo + retorno | pop r24, pop r0, out SREG, pop r0, pop r1, reti | 9 + 4 = 13 |
| **total** | | **35 ciclos ≈ 2,19 µs a 16 MHz** |

Confira com `avr-objdump -d` (é o padrão de prólogo do M1.3.T08). A primeira instrução útil sai 17 ciclos (≈ 1,06 µs) depois do evento, **se** nada mais estiver rodando: se outra ISR estiver em execução, a nova espera ela terminar (sem aninhamento) — a latência real é a **pior** ISR mais a sua.

**Carga de CPU** = frequência das interrupções × ciclos por ISR ÷ f_clk. **Exemplo 3.** Uma ISR de 35 ciclos a 20 kHz: 20 000 × 35/16 × 10⁶ = **4,4 %** da CPU. A 200 kHz seriam 44 % — e uma ISR de 100 ciclos a 160 kHz ocupa a CPU inteira.

**Regras de ISR curta.**
- Nada de `_delay_ms`/`delay()`: com I = 0, nada mais roda (e no Arduino o `millis()` para).
- Nada de `Serial.print`/`printf`: a transmissão do Arduino depende da interrupção da UART, que está bloqueada dentro da ISR. Versões antigas do núcleo travavam de vez com o buffer cheio; as atuais (`HardwareSerial.cpp`) detectam o I = 0 e transmitem byte a byte por polling — sem travar, mas segurando a CPU ~1 ms por caractere a 9600 baud, com todas as outras interrupções esperando.
- Faça o mínimo: leia o registrador que precisa, guarde o dado, ligue uma flag (`volatile`) e saia. O laço principal processa.
- Não chame funções pesadas: cada registrador a mais usado vira `push`/`pop`.

```c
#include <avr/io.h>
#include <avr/interrupt.h>

static volatile uint8_t tem_evento;        /* padrão "sinaliza e sai" */

ISR(INT1_vect)
{
    tem_evento = 1;
}

void trata_eventos(void)                   /* chamada no laço principal */
{
    if (tem_evento) {
        tem_evento = 0;                    /* 8 bits: atômico */
        PINB = (1 << PINB5);               /* o trabalho pesado iria aqui */
    }
}
```

## Armadilhas comuns
- Esquecer o `sei()` (ou o bit no EIMSK/PCICR): nada acontece.
- Esquecer o `volatile` e ver o `main` nunca perceber a mudança.
- Ler variáveis de 16 ou 32 bits fora de `ATOMIC_BLOCK`.
- Usar `delay`, `Serial.print` ou laços de espera dentro da ISR.
- Achar que a interrupção resolve o bounce.
- Errar o nome do vetor (`INT0_vector`, `TIMER0_COMPA`) e cair no `__bad_interrupt`, que reinicia o chip.
- Limpar uma flag escrevendo 0 nela: as flags do AVR se limpam escrevendo **1**.
- Esquecer que o PCINT dispara nas duas bordas e não diz qual pino mudou.

## Gabarito
1. `EICRA |= (1 << ISC11) | (1 << ISC10); EIMSK |= (1 << INT1); sei();`
2. (19 − 1) × 4 = 72 = 0x48.
3. O vetor aponta para `__bad_interrupt`, que salta para o endereço 0: o programa recomeça como num reset (mas sem zerar os registradores de periférico).
5. O contador passa de 0x03FF (1023) para 0x0400 (1024) entre as duas leituras: o `main` lê o byte baixo antigo (0xFF) e o alto novo (0x04) = 0x04FF = 1279 > 1100, embora o contador real nunca tenha passado de 1024.
6. 50 000 × 50/16 000 000 = 15,6 %.
7. Se o timer disparar logo depois de a ISR da UART começar, ele espera até 8 µs mais a sua própria latência: o prazo de 5 µs estoura. Encurte a ISR da UART (só copiar o byte) ou, com cuidado, use `ISR_NOBLOCK` nela.
8. A variável de 16 bits usa dois registradores (r24 e r25), e cada registrador usado pela ISR é salvo e restaurado.

# M1.2.T07 — UART serial

> A serial é o primeiro canal entre o seu firmware e o mundo: depuração com `printf`, comandos vindos do PC, GPS, módulos Bluetooth, modems celulares. O `Serial.begin(9600)` do Arduino esconde um periférico simples — o **USART0** — e uma conta que, errada, transforma texto em lixo. Aqui você monta o seu driver por registrador, primeiro por polling, depois com interrupção e buffer circular, usando o que aprendeu no T05.

## Ao final você consegue
- Descrever o quadro assíncrono (start, dados, paridade e stop), o nível lógico do USART0 e o caminho até o PC pelo conversor USB-serial.
- Calcular UBRR0 nos modos normal e U2X, a taxa real e o erro percentual, e decidir se o erro é aceitável.
- Implementar transmissão e recepção por polling (UDRE0, RXC0) e ligar a saída ao printf do avr-libc.
- Implementar a recepção por interrupção com buffer circular e tratar os erros de quadro e de sobrescrita.

## Resumo
**1. O quadro.** A linha fica em **1** quando ociosa. Cada caractere: **start bit** (0), de 5 a 9 **bits de dados** começando pelo **menos significativo**, **paridade** opcional (par ou ímpar) e 1 ou 2 **stop bits** (1). Não há clock no fio: transmissor e receptor combinam a **taxa** (baud) e o receptor se sincroniza na borda de descida do start bit, amostrando cada bit no meio (o USART do AVR faz 16 amostras por bit no modo normal, 8 no U2X, e decide pela maioria das 3 do centro).
- **8N1** (8 dados, sem paridade, 1 stop) = **10 bits por byte**: a 9600 baud, 960 bytes/s; cada bit dura 1/9600 = **104,2 µs**.
- **Nível**: no Uno, 0 V e 5 V (TTL), lógica direta. O RS-232 de verdade usa ±3 a ±15 V, **invertido**: ligar direto queima o pino; use um MAX232/MAX3232. Módulos de 3,3 V (ESP-01, GPS) precisam de divisor ou conversor de nível no RX deles.
- **Ligação**: TX de um no RX do outro (cruzado) e **GND comum**.
- **Até o PC**: o TXD/RXD do ATmega328P (D1/D0) vai a um conversor USB-serial (ATmega16U2 no Uno, CH340 ou FT232 em clones), que aparece no PC como porta serial virtual (`/dev/ttyACM0` ou `/dev/ttyUSB0` no Linux, `COMx` no Windows). No PC: Monitor Serial da IDE, `screen /dev/ttyACM0 9600`, `minicom`, `picocom` ou `pyserial`.

**2. Gerador de baud.**

> Normal: UBRR0 = f_clk/(16·baud) − 1   ·   U2X (bit U2X0 = 1): UBRR0 = f_clk/(8·baud) − 1
> Taxa real = f_clk/(16·(UBRR0 + 1)) (ou 8 no U2X)   ·   erro = taxa real/taxa desejada − 1

O UBRR é inteiro: arredonde e calcule o erro. O datasheet (tabela de erro máximo recomendado do receptor, em *Asynchronous Operational Range*) recomenda, para quadros com 8 bits de dados, erro de até cerca de **±2 %** no modo normal e **±1,5 %** no U2X — e o erro que importa é a **soma** dos dois lados.

**Exemplo 1 (16 MHz).**

| Baud | Modo | UBRR exato | UBRR0 | Taxa real | Erro |
|---|---|---|---|---|---|
| 9600 | normal | 103,17 | 103 | 9615,4 | +0,16 % ✔ |
| 57 600 | normal | 16,36 | 16 | 58 823,5 | +2,12 % ✘ |
| 57 600 | U2X | 33,72 | 34 | 57 142,9 | −0,79 % ✔ |
| 115 200 | normal | 7,68 | 8 | 111 111 | −3,55 % ✘ |
| 115 200 | U2X | 16,36 | 16 | 117 647 | +2,12 % (no limite) |
| 250 000 | normal | 3 | 3 | 250 000 | 0 % ✔ |

Por isso o `HardwareSerial` do Arduino usa U2X, e 115 200 a 16 MHz "funciona quase sempre" (o conversor do outro lado costuma ter erro próximo de 0). Cristais "de UART" como **18,432 MHz** e **14,7456 MHz** dão erro zero nas taxas padrão (18,432 MHz/(16 × 115 200) = 10 → UBRR0 = 9). O RC interno do T01, com erro de alguns por cento, sozinho já pode estourar a margem.

**3. Polling.** Registradores: **UDR0** (escrever = transmitir, ler = byte recebido), **UCSR0A** (flags **RXC0** — chegou byte, **UDRE0** — pode escrever, **TXC0** — terminou de transmitir; erros **FE0**, **DOR0**, **UPE0**; **U2X0**), **UCSR0B** (habilita **RXEN0**, **TXEN0** e as interrupções **RXCIE0**, **UDRIE0**, **TXCIE0**), **UCSR0C** (formato; o valor de reset 0x06 já é 8N1).
```c
#define F_CPU 16000000UL
#include <avr/io.h>
#include <stdint.h>

static void uart_inicia(void)
{
    UCSR0A = (1 << U2X0);                    /* modo U2X */
    UBRR0  = 207;                            /* 16 MHz/(8·9600) − 1 = 207,3 → 207 */
    UCSR0C = (1 << UCSZ01) | (1 << UCSZ00);  /* 8N1 */
    UCSR0B = (1 << RXEN0) | (1 << TXEN0);
}

static void uart_poe(uint8_t c)
{
    while (!(UCSR0A & (1 << UDRE0)))         /* espera o registrador de dados vazio */
        ;
    UDR0 = c;
}

static uint8_t uart_tira(void)
{
    while (!(UCSR0A & (1 << RXC0)))          /* espera chegar um byte */
        ;
    return UDR0;
}

int main(void)
{
    uart_inicia();
    for (;;) {
        uint8_t c = uart_tira();
        if (c >= 'a' && c <= 'z')
            c = (uint8_t)(c - 'a' + 'A');    /* eco em maiúsculas */
        uart_poe(c);
    }
}
```
O `uart_tira` bloqueia: enquanto nada chega, nada mais roda. Serve para testes; um firmware real usa o buffer da seção 4.

**`setbaud.h`**: faz a conta (e a escolha do U2X) em tempo de compilação, e avisa (`#warning`) se o erro passar da tolerância `BAUD_TOL` (2 % por padrão):
```c
#define F_CPU 16000000UL
#define BAUD 57600
#include <avr/io.h>
#include <util/setbaud.h>

void uart_inicia_setbaud(void)
{
    UBRR0H = UBRRH_VALUE;
    UBRR0L = UBRRL_VALUE;
#if USE_2X
    UCSR0A |= (1 << U2X0);
#else
    UCSR0A &= ~(1 << U2X0);
#endif
    UCSR0B = (1 << RXEN0) | (1 << TXEN0);
}
```

**`printf` pela serial.** O avr-libc liga o `stdout` a qualquer função que mande um caractere:
```c
#include <avr/io.h>
#include <stdio.h>

static int uart_putchar(char c, FILE *f)
{
    if (c == '\n')
        uart_putchar('\r', f);               /* terminais esperam \r\n */
    while (!(UCSR0A & (1 << UDRE0)))
        ;
    UDR0 = (uint8_t)c;
    return 0;
}

static FILE uart_saida = FDEV_SETUP_STREAM(uart_putchar, NULL, _FDEV_SETUP_WRITE);

void printf_na_serial(void)
{
    stdout = &uart_saida;                    /* daqui em diante, printf sai pela UART */
    printf("ADC = %u, t = %lu ms\n", 512u, 1234UL);
}
```
O `printf` custa ~1,5 KB de flash; o padrão **não formata `float`** (sai `?`). Para `%f`, ligue com `-Wl,-u,vfprintf -lprintf_flt -lm` (mais ~1,5 KB) — ou imprima inteiros em milésimos, que é o costume em MCU pequeno. Conferido no simavr: a linha acima sai como `ADC = 512, t = 1234 ms`.

**4. Recepção por interrupção.** A 115 200 baud chega um byte a cada 86,8 µs. O receptor do ATmega328P guarda **2 bytes** no buffer de recepção mais um no registrador de deslocamento; se o programa demora mais que isso para ler, o próximo byte se perde e liga o **DOR0** (*data overrun*). A solução é ler cada byte na ISR `USART_RX_vect` e guardá-lo num **buffer circular** (fila) que o `main` esvazia quando puder:
- dois índices: `cabeca` (onde a ISR escreve) e `cauda` (onde o `main` lê); vazio quando são iguais; cheio quando `cabeca + 1 == cauda`;
- tamanho **potência de 2** para trocar o `%` por `& (N − 1)`;
- índices de **8 bits** (leitura atômica) e `volatile`;
- **leia UCSR0A antes de UDR0**: as flags de erro (FE0 = stop bit lido como 0, ou seja, baud errado ou *break*; DOR0; UPE0 = paridade) valem para o byte que está no topo do buffer e somem quando UDR0 é lido.
```c
#include <avr/io.h>
#include <avr/interrupt.h>
#include <stdint.h>

#define FILA_N 64u                               /* potência de 2 */
static volatile uint8_t fila[FILA_N];
static volatile uint8_t cabeca, cauda;           /* 8 bits: atômicos */
static volatile uint8_t erros_quadro, erros_sobrescrita, perdidos;

ISR(USART_RX_vect)
{
    uint8_t st = UCSR0A;                         /* flags antes do dado */
    uint8_t c  = UDR0;
    if (st & (1 << FE0))  { erros_quadro++; return; }   /* byte inválido */
    if (st & (1 << DOR0)) erros_sobrescrita++;          /* algo se perdeu antes deste */
    uint8_t prox = (uint8_t)((cabeca + 1u) & (FILA_N - 1u));
    if (prox == cauda) { perdidos++; return; }   /* fila cheia: descarta */
    fila[cabeca] = c;
    cabeca = prox;
}

int uart_le(void)                                /* −1 se vazio; não bloqueia */
{
    if (cauda == cabeca)
        return -1;
    uint8_t c = fila[cauda];
    cauda = (uint8_t)((cauda + 1u) & (FILA_N - 1u));
    return c;
}

void uart_rx_inicia(void)
{
    UCSR0B |= (1 << RXEN0) | (1 << RXCIE0);      /* recepção com interrupção */
    sei();
}
```
Só a ISR escreve `cabeca` e só o `main` escreve `cauda`: com índices de 8 bits, não é preciso seção atômica. A fila guarda até FILA_N − 1 bytes (uma posição fica vazia para distinguir cheio de vazio). A transmissão também pode ir por interrupção (UDRIE0 + fila de saída), como faz o `HardwareSerial` do Arduino com seus buffers de 64 bytes.

**No Arduino**: `Serial.begin(9600)` calcula o UBRR (com U2X), liga RX, TX e as interrupções; `Serial.available()` é `cabeca − cauda` da fila de recepção; `Serial.print` põe na fila de transmissão e só bloqueia quando ela enche.

## Pratique
1. Desenhe o quadro 8N1 do caractere 'A' (0x41), bit a bit, a partir do start bit.
2. Calcule UBRR0 e o erro para 38 400 baud a 16 MHz, nos dois modos. Qual você usaria?
3. Um ATmega328P rodando no RC interno de 8 MHz precisa de 9600 baud. Qual UBRR0? Se o RC estiver 3 % rápido, qual o erro total?
4. Quanto tempo leva para mandar `printf("%5u\n", x)` (6 caracteres mais o \r) a 9600 baud?
5. Por que ler UDR0 antes de UCSR0A perde a informação de erro?
6. Num buffer circular de 16 posições com `cabeca` = 3 e `cauda` = 9, quantos bytes há na fila?
7. Ligue um módulo GPS de 3,3 V (9600 baud) ao Uno: desenhe as ligações, incluindo o nível no RX do GPS.
8. Rode o Exemplo de eco a 115 200 baud sem U2X e com U2X. O que você vê no terminal em cada caso?

## Armadilhas comuns
- TX ligado em TX (não cruzar), ou esquecer o GND comum.
- Ligar RS-232 (±12 V) direto no pino.
- Esquecer o `F_CPU` correto (ou o U2X) e ver lixo no terminal.
- 115 200 baud a 16 MHz sem U2X (−3,5 %).
- `printf` com `%f` e receber `?`.
- Ler UDR0 antes de UCSR0A, ou não tratar o DOR0.
- Processar a linha recebida dentro da ISR.
- Esquecer que D0/D1 são a mesma UART do USB: módulos ligados ali atrapalham a gravação (T01).

## Gabarito
1. start 0; dados LSB primeiro: 1,0,0,0,0,0,1,0; stop 1.
2. Normal: 16 × 10⁶/(16 × 38 400) − 1 = 25,04 → 25 → 38 461,5 (+0,16 %). U2X: 51,08 → 51 → 38 461,5 (+0,16 %). Tanto faz; o normal é mais tolerante a ruído (16 amostras por bit).
3. 8 × 10⁶/(16 × 9600) − 1 = 51,08 → 51 (+0,16 %). Com o RC 3 % rápido, a taxa real fica ≈ 3,2 % acima: fora da margem.
4. 7 caracteres × 10 bits/9600 = 7,3 ms.
6. (3 − 9) mod 16 = 10 bytes.
7. TX do GPS → D0 (RX do Uno) direto: o V_IH mínimo do ATmega328P a 5 V é 0,6·VCC = 3,0 V, então os 3,3 V do GPS são lidos como 1, com pouca margem. D1 (TX do Uno) → divisor de 1 kΩ (em série) e 2 kΩ (ao GND) → RX do GPS (5 V × 2/3 ≈ 3,3 V). GND comum. Melhor ainda: SoftwareSerial em outros pinos, deixando D0/D1 para o USB.
8. Sem U2X (−3,55 %), caracteres trocados ou faltando; com U2X (+2,12 %), em geral funciona.

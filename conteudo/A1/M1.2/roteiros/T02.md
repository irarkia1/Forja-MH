## Resumo
**1. Três registradores por porta.** Cada porta (B, C, D) tem três registradores de 8 bits; o bit *n* de cada um controla o pino *n*:
- **DDRx** (*Data Direction*): 1 = saída, 0 = entrada.
- **PORTx**: numa saída, o nível (1 = alto); numa **entrada**, liga (1) ou desliga (0) o **pull-up** interno.
- **PINx**: leitura do nível **real** do pino (vale para entrada e para saída). Escrever 1 num bit de PINx **inverte** o bit correspondente de PORTx (recurso do ATmega328P, seção *Toggling the Pin*).

| DDxn | PORTxn | Pino |
|---|---|---|
| 0 | 0 | entrada flutuante (alta impedância) |
| 0 | 1 | entrada com pull-up (R_PU de 20 a 50 kΩ) |
| 1 | 0 | saída em nível baixo (drena corrente) |
| 1 | 1 | saída em nível alto (fornece corrente) |

O bit **PUD** do MCUCR desliga todos os pull-ups de uma vez. Depois do reset, tudo é 0: todos os pinos são entradas flutuantes. **Entrada flutuante lê lixo** (capta ruído e o dedo encostado) e aumenta o consumo: todo pino de entrada precisa de pull-up, pull-down ou de quem o acione.

A leitura de PINx passa por um **sincronizador** (dois flip-flops) para evitar metaestabilidade: o valor lido tem até ~1,5 ciclo de atraso. Se você escreve em PORTx e lê PINx logo em seguida, precisa de um `nop` no meio — exatamente o exemplo do datasheet.

**2. Máscaras: mexa só no seu bit.**
```c
#include <avr/io.h>

void exemplos_de_mascara(void)
{
    DDRB  |=  (1 << DDB5);                 /* PB5 saída; os outros bits ficam */
    PORTB |=  (1 << PORTB5);               /* liga PB5 */
    PORTB &= ~(1 << PORTB5);               /* desliga PB5 */
    PORTB ^=  (1 << PORTB5);               /* inverte PB5 (leitura-modificação-escrita) */
    PINB   =  (1 << PINB5);                /* inverte PB5 numa escrita só */

    DDRD  &= ~((1 << DDD2) | (1 << DDD3)); /* PD2 e PD3 entradas */
    PORTD |=  (1 << PORTD2) | (1 << PORTD3); /* com pull-up */

    if (!(PIND & (1 << PIND2))) {          /* botão em PD2 apertado (nível 0) */
        PORTB |= _BV(PORTB5);              /* _BV(n) é (1 << n), do avr-libc */
    }
}
```
- `PORTB = (1 << 5);` (sem o `|`) liga PB5 **e desliga os outros sete pinos** — erro clássico.
- Nas portas de E/S de endereço baixo (PORTB, DDRB, PINB etc. ficam abaixo de 0x20), o avr-gcc transforma `|=` e `&= ~` de **um bit constante** nas instruções `sbi`/`cbi`, que são **atômicas**. Mexer em vários bits gera `in`/`ori`/`out` (três instruções): se uma interrupção alterar a mesma porta no meio, a alteração dela se perde (T05). A escrita em PINx para inverter não tem esse problema.

**Tradução Arduino → registrador** (pino 13 = PB5, pino 2 = PD2):

| Arduino | Registrador |
|---|---|
| `pinMode(13, OUTPUT)` | `DDRB \|= _BV(DDB5);` |
| `pinMode(2, INPUT)` | `DDRD &= ~_BV(DDD2); PORTD &= ~_BV(PORTD2);` |
| `pinMode(2, INPUT_PULLUP)` | `DDRD &= ~_BV(DDD2); PORTD \|= _BV(PORTD2);` |
| `digitalWrite(13, HIGH)` | `PORTB \|= _BV(PORTB5);` |
| `digitalRead(2)` | `(PIND & _BV(PIND2)) != 0` |

Por dentro, `digitalWrite` consulta tabelas na flash para achar porta e bit, desliga o PWM do pino se houver e desabilita interrupções durante a escrita: dezenas de ciclos contra 2 do `sbi` (o T08 mede isso).

**Exemplo 1 (valor de registrador).** LEDs em PB0 e PB5 como saídas, o resto entrada: DDRB = (1 << 0) | (1 << 5) = 0b0010_0001 = **0x21** = 33.

**Exemplo 2 (botão e LED por registrador, completo).** Botão entre PD2 (D2) e GND, com o pull-up interno; LED em PB5:
```c
#include <avr/io.h>

int main(void)
{
    DDRB  |= (1 << DDB5);       /* LED */
    DDRD  &= ~(1 << DDD2);      /* botão: entrada */
    PORTD |= (1 << PORTD2);     /* com pull-up: solto = 1, apertado = 0 */

    for (;;) {
        if (PIND & (1 << PIND2))
            PORTB &= ~(1 << PORTB5);   /* solto: apaga */
        else
            PORTB |= (1 << PORTB5);    /* apertado: acende */
    }
}
```
Com pull-up, a lógica é **invertida** (apertado = 0). Por isso o botão vai ao GND: assim não é preciso resistor externo.

**3. Bounce.** Ao fechar ou abrir, os contatos metálicos batem e se separam várias vezes antes de assentar. Nas medições de Ganssle, a maioria das chaves quica por algumas centenas de µs a poucos ms, e algumas passam de 5 ms; **projete para ~10–20 ms**. Para o MCU, que lê o pino milhões de vezes por segundo, cada quique é um "aperto". Um contador de apertos sem debounce pula de 1 em 1, de 3 em 3, de 7 em 7.

As entradas do ATmega328P já têm **Schmitt trigger**, que limpa bordas lentas e ruído pequeno, mas **não** o bounce (são transições completas). Soluções:
- **Hardware**: RC (ex.: 10 kΩ e 1 µF, τ = 10 ms) antes da entrada com Schmitt, como no M0.4.T07. Custa componentes.
- **Software por espera** (a mais simples e a pior): ao ver a borda, espera 20 ms e lê de novo. Bloqueia a CPU.
- **Software por contador**: amostra o pino a cada *T* ms; só aceita um novo estado depois de *N* amostras iguais seguidas. Tempo de confirmação ≈ N·T.
- **Software por registrador de deslocamento** (Ganssle): a cada amostra, `estado = (estado << 1) | bruto`; o botão só está "apertado" quando todos os bits do registrador são 0 (ou "solto" quando todos são 1).

**Exemplo 3 (debounce por espera).**
```c
#define F_CPU 16000000UL
#include <avr/io.h>
#include <util/delay.h>

int main(void)
{
    DDRB |= (1 << DDB5);
    PORTD |= (1 << PORTD2);                     /* pull-up em PD2 */
    for (;;) {
        if (!(PIND & (1 << PIND2))) {           /* viu nível baixo */
            _delay_ms(20);                      /* espera o bounce acabar */
            if (!(PIND & (1 << PIND2))) {       /* continua apertado? */
                PINB = (1 << PINB5);            /* inverte o LED */
                while (!(PIND & (1 << PIND2)))  /* espera soltar */
                    ;
                _delay_ms(20);                  /* bounce da soltura */
            }
        }
    }
}
```
Funciona, mas o programa inteiro para enquanto o botão está apertado. O T06 mostra o custo disso.

**Exemplo 4 (debounce por contador, amostrando a cada 1 ms).** Cada aperto confirmado inverte o LED. O laço principal faz uma amostra por milissegundo; no T06, o mesmo código vai para uma ISR de timer de 1 ms.
```c
#define F_CPU 16000000UL
#include <avr/io.h>
#include <util/delay.h>
#include <stdint.h>

#define N_AMOSTRAS 10            /* 10 amostras de 1 ms = 10 ms estável */

int main(void)
{
    uint8_t estavel = 1;         /* estado aceito: 1 = solto (pull-up) */
    uint8_t conta = 0;

    DDRB |= (1 << DDB5);
    PORTD |= (1 << PORTD2);

    for (;;) {
        uint8_t bruto = (PIND >> PIND2) & 1;
        if (bruto == estavel) {
            conta = 0;                       /* nada mudou */
        } else if (++conta >= N_AMOSTRAS) {  /* diferente por N amostras */
            estavel = bruto;
            conta = 0;
            if (estavel == 0)
                PINB = (1 << PINB5);         /* borda de aperto confirmada */
        }
        _delay_ms(1);                        /* período de amostragem */
    }
}
```
Um quique zera a contagem; só um nível que fica **N amostras seguidas** diferente do aceito vira o novo estado. Testado no simavr com o botão simulado do Experimento 3 (arquivo VCD com 5 quiques por aperto): sem debounce, 3 apertos geram 18 bordas de descida; com os Exemplos 3, 4 e 5, exatamente 3 eventos.

**Exemplo 5 (registrador de deslocamento).** Função chamada a cada 5 ms que devolve 1 **só na borda** de aperto:
```c
#include <stdint.h>
#include <avr/io.h>

uint8_t botao_apertou(void)
{
    static uint8_t historico = 0xFF;            /* 1 = solto */
    historico = (uint8_t)((historico << 1) | ((PIND >> PIND2) & 1));
    /* 1 seguido de sete 0: estava solto e ficou 7 amostras apertado */
    return historico == 0x80;
}
```
Com amostras a cada 5 ms, a borda é aceita depois de 7 leituras baixas seguidas (35 ms). Como o padrão 0x80 só aparece uma vez por aperto, a função já entrega o evento "apertou", sem variável extra.

**Exemplo 6 (o mesmo no Arduino, sem bloquear).** O exemplo *Debounce* da IDE usa `millis()` (o relógio de 1 ms que o T06 constrói por registrador):
```cpp
const uint8_t BOTAO = 2, LED = 13;
uint8_t estado_aceito = HIGH, ultima_leitura = HIGH;
unsigned long t_mudou = 0;

void setup() {
  pinMode(BOTAO, INPUT_PULLUP);
  pinMode(LED, OUTPUT);
}

void loop() {
  uint8_t leitura = digitalRead(BOTAO);
  if (leitura != ultima_leitura) t_mudou = millis();      // quicou: reinicia o prazo
  if (millis() - t_mudou > 20 && leitura != estado_aceito) {
    estado_aceito = leitura;
    if (estado_aceito == LOW) digitalWrite(LED, !digitalRead(LED));
  }
  ultima_leitura = leitura;
}
```

**4. Correntes e resistores.**
- **Limites absolutos** (*Absolute Maximum Ratings*): 40 mA por pino de E/S e 200 mA pelos pinos VCC e GND. "Absoluto" é o limite de dano, não de uso: projete para **≤ 20 mA** por pino, a corrente em que o datasheet garante V_OL ≤ 0,9 V e V_OH ≥ 4,2 V (a 5 V). As notas da tabela *DC Characteristics* limitam ainda a **soma por grupo de portas** (ordem de 100 mA por grupo).
- **Resistor de LED**: R = (V_OH − V_F)/I. Com 5 V, LED vermelho (V_F ≈ 2,0 V) e 10 mA: R = 3,0/0,010 = **300 Ω** (use 330 Ω). A saída tem resistência interna de algumas dezenas de ohms, então a corrente real fica um pouco abaixo da calculada.
- **Cargas maiores** (relé, motor, fita de LED): sempre por transistor ou MOSFET (M0.4), com diodo de roda livre em cargas indutivas. O pino nunca alimenta a carga.
- **Pull-up**: o interno (20–50 kΩ) basta para botões com fio curto. Com o botão apertado, ele drena só 5 V/R_PU ≈ 0,1–0,25 mA. Para fios longos ou ambientes ruidosos, use pull-up externo de 4,7–10 kΩ: mais corrente, mais imunidade a ruído.

## Armadilhas comuns
- Atribuir (`=`) em vez de fazer OU (`|=`) e mudar os outros pinos da porta.
- Ler PORTx achando que lê o pino: quem lê o pino é PINx.
- Esquecer o pull-up e deixar a entrada flutuando.
- Esquecer que com pull-up o botão apertado lê 0.
- Debounce por `delay` que trava o resto do programa.
- Amostrar rápido demais com N pequeno: o tempo de confirmação fica menor que o bounce.
- Ligar LED sem resistor ou tirar corrente de relé direto do pino.
- Ler PINx na instrução seguinte à escrita em PORTx sem o `nop` do sincronizador.

## Gabarito
1. DDRD = 0b1100_0000; PORTD = 0b1100_0100.
2. A atribuição escreve 0 em todos os outros bits de PORTB: PB0 apaga.
3. A0 = PC0, 12 = PB4: `DDRC &= ~_BV(DDC0); PORTC |= _BV(PORTC0); DDRB |= _BV(DDB4); if (!(PINC & _BV(PINC0))) PORTB |= _BV(PORTB4);` (o `pinMode(12, OUTPUT)` precisa existir em algum lugar).
4. Escrever 1 em PINxn inverte PORTxn no hardware, numa única escrita: não há leitura-modificação-escrita que uma ISR possa interromper. `PORTB ^=` lê, inverte e escreve (in/eor/out).
5. 8 × 2 ms = 16 ms.
6. (5 − 2,2)/0,008 = 350 Ω → 390 Ω (ou 330 Ω, com ~8,5 mA).
7. 120 mA na porta D: passa da soma permitida por grupo nas notas da *DC Characteristics* e encosta no limite de 200 mA do chip. Use transistores ou um driver (ULN2803, registrador de deslocamento com corrente maior).
8. 0x00 é "apertado há 8 amostras" e continuaria verdadeiro em todas as chamadas enquanto o botão estiver apertado; 0x80 só acontece na transição (um 1 antigo seguido de sete 0), ou seja, uma vez por aperto.

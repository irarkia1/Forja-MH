# M1.2.T03 — PWM

> Tópico de **elite** (laboratório). Tempo previsto: ~18,5 h — ≈ 4,5 h de estudo (datasheet, Williams, "Secrets of Arduino PWM"), ≈ 3,5 h de cálculos e exemplos resolvidos, ≈ 8 h de laboratório, ≈ 2,5 h de relatório e revisão. O ATmega328P não tem saída analógica: o `analogWrite` é **PWM**, uma onda quadrada de largura variável gerada pelos timers do T06. Com ela você controla o brilho de LEDs, a posição de servos e a velocidade de motores, e gera tensões médias com um filtro RC — o mesmo PWM filtrado que você mediu no M0.5.T03 e no laboratório de osciloscópio (M0.5.T08).

## Ao final você consegue
- Explicar o PWM (período, ciclo de trabalho e valor médio) e os modos Fast PWM e Phase Correct PWM dos timers do ATmega328P.
- Calcular a frequência e o ciclo de trabalho a partir de f_clk, prescaler, TOP e OCRnx, e escolher esses valores para uma frequência alvo.
- Configurar o PWM por registradores (bits WGM, COM e CS, ICR1) e relacionar analogWrite aos timers e pinos do Arduino Uno.
- Aplicar o PWM a LEDs, servos e motores com transistor, considerando resolução, frequência audível e filtragem RC.

## Resumo
**1. PWM.** Uma onda retangular de **período** T (frequência f = 1/T) que fica em nível alto durante t_on. **Ciclo de trabalho** D = t_on/T. Uma carga "lenta" — o olho, um motor com sua indutância e inércia, um filtro RC — responde ao **valor médio**: V_média = D·V_alto. **Exemplo 1.** 5 V com D = 30 % → média de 1,5 V; com RC, uma tensão contínua de 1,5 V com ondulação.

**2. Como o timer gera PWM.** O contador anda e o comparador liga ou desliga o pino OCnx sozinho, sem CPU:
- **Fast PWM** (rampa simples): conta de 0 a TOP e recomeça. No modo **não invertido** (COMnx1:0 = 10), o pino vai a 1 no início (BOTTOM) e a 0 quando TCNTn = OCRnx. f = f_clk/(N·(1 + TOP)); D = (OCRnx + 1)/(TOP + 1). Casos extremos do datasheet: OCRnx = TOP → pino sempre em 1; OCRnx = 0 → um pulso estreito de 1 contagem por período (não é 0 %!). Para 0 % real, desligue a saída (COM = 00 e pino em 0).
- **Phase Correct PWM** (rampa dupla): conta 0 → TOP → 0. O pino muda na comparação ao subir e de novo ao descer: pulso **centrado** no período. f = f_clk/(2·N·TOP); D = OCRnx/TOP (0 e TOP dão 0 % e 100 % exatos). Metade da frequência do Fast PWM com o mesmo TOP; bom para motores (os pulsos de vários canais ficam simétricos).
- **Modo invertido** (COMnx1:0 = 11): o complemento — D_invertido = 1 − D.
- **Atualização sem glitch**: em modo PWM, OCRnx é **duplamente bufferizado**: o valor escrito só vale no próximo TOP (Fast) ou TOP do período (Phase Correct). Mudar o ciclo de trabalho no meio do período não gera pulso torto.
- **TOP**: nos timers 0 e 2, 0xFF ou OCRnA (modos 7 e 5; aí o canal A vira referência e só o OCnB sai como PWM). No Timer1, 0x00FF/0x01FF/0x03FF (8, 9 e 10 bits fixos), **ICR1** (modos 14 Fast e 10/8 Phase Correct) ou OCR1A. Com TOP em ICR1, os dois canais OC1A e OC1B continuam livres: é o jeito de ter frequência qualquer **e** dois PWM.

Bits de modo mais usados:

| Timer | Modo | WGM | TOP |
|---|---|---|---|
| 0 e 2 | Phase Correct 8 bits | 1 (WGMn0) | 0xFF |
| 0 e 2 | Fast PWM 8 bits | 3 (WGMn1 + WGMn0) | 0xFF |
| 0 e 2 | Fast PWM, TOP = OCRnA | 7 (WGMn2 + WGMn1 + WGMn0) | OCRnA |
| 1 | Phase Correct 8 bits | 1 (WGM10) | 0x00FF |
| 1 | Fast PWM com ICR1 | 14 (WGM13 + WGM12 + WGM11) | ICR1 |
| 1 | Phase and Freq. Correct com ICR1 | 8 (WGM13) | ICR1 |

(WGMn0 e WGMn1 ficam em TCCRnA; WGMn2/WGM12 e WGM13 em TCCRnB.)

**3. Frequência × resolução.** Com N = 1, f = f_clk/(TOP + 1): a frequência máxima cai pela metade a cada bit de resolução. A 16 MHz em Fast PWM: 8 bits → **62,5 kHz**; 10 bits → 15,6 kHz; 16 bits → 244 Hz. Resolução efetiva com TOP qualquer: log₂(TOP + 1) bits.

**Exemplo 2 (frequências do Arduino).** O `init()` do núcleo deixa: Timer0 em Fast PWM, N = 64 → 16 × 10⁶/(64 × 256) = **976,56 Hz** (D5 e D6); Timer1 e Timer2 em Phase Correct 8 bits, N = 64 → 16 × 10⁶/(2 × 64 × 255) = **490,20 Hz** (D9, D10, D3 e D11). `analogWrite(pino, 0)` e `analogWrite(pino, 255)` viram `digitalWrite` (0 % e 100 % reais); entre 1 e 254, o núcleo liga o COM do canal e escreve o OCR. Em D5/D6 (Fast PWM), `analogWrite(6, 127)` dá D = 128/256 = 50,0 %; em D9 (Phase Correct), 127/255 = 49,8 %.

**Exemplo 3 (fade de LED no D6, Fast PWM do Timer0).**
```c
#define F_CPU 16000000UL
#include <avr/io.h>
#include <util/delay.h>

int main(void)
{
    DDRD  |= (1 << DDD6);                              /* OC0A */
    TCCR0A = (1 << COM0A1) | (1 << WGM01) | (1 << WGM00); /* não invertido, Fast PWM */
    TCCR0B = (1 << CS01) | (1 << CS00);                /* N = 64: 976,56 Hz */
    for (;;) {
        for (uint8_t v = 0; v < 255; v++) { OCR0A = v; _delay_ms(4); }
        for (uint8_t v = 255; v > 0; v--) { OCR0A = v; _delay_ms(4); }
    }
}
```
O olho percebe brilho de forma aproximadamente logarítmica: a rampa linear parece "rápida no começo, parada no fim". Uma tabela de correção gama (`brilho = 255·(v/255)^2,2`) deixa o fade uniforme.

**Exemplo 4 (servo no D9: 50 Hz, Timer1 modo 14).** Servos de modelismo esperam um pulso de ~1 ms a ~2 ms (1,5 ms = centro) a cada 20 ms. Com N = 8, cada contagem dura 0,5 µs: TOP = 16 × 10⁶/(8 × 50) − 1 = **39 999**. Pulso = (OCR1A + 1) × 0,5 µs → 1,5 ms ↔ OCR1A = **2999**; 1 ms ↔ 1999; 2 ms ↔ 3999. Resolução: 2000 passos entre os extremos.
```c
#include <avr/io.h>

static void servo_inicia(void)
{
    DDRB  |= (1 << DDB1);                     /* OC1A = D9 */
    TCCR1A = (1 << COM1A1) | (1 << WGM11);    /* não invertido; WGM11 */
    TCCR1B = (1 << WGM13) | (1 << WGM12)      /* modo 14: Fast PWM, TOP = ICR1 */
           | (1 << CS11);                     /* N = 8 → 0,5 µs por contagem */
    ICR1   = 39999;                           /* 20 ms */
    OCR1A  = 2999;                            /* 1,5 ms: centro */
}

static void servo_angulo(uint8_t graus)       /* 0..180 → 1..2 ms */
{
    OCR1A = 1999 + (uint16_t)((uint32_t)graus * 2000u / 180u);
}

int main(void)
{
    servo_inicia();
    servo_angulo(90);
    for (;;) {
    }
}
```
(Muitos servos aceitam de 0,5 a 2,5 ms; confira a folha do seu e não force o batente mecânico.)

**Exemplo 5 (motor DC a 20 kHz, inaudível).** PWM de motor em 490 Hz ou 976 Hz "canta" — a bobina vibra na frequência do PWM. Acima de ~20 kHz o som sai da faixa audível. Timer1 modo 14, N = 1: TOP = 16 × 10⁶/20 000 − 1 = **799** (resolução de log₂ 800 ≈ 9,6 bits):
```c
#include <avr/io.h>

void motor_inicia(void)
{
    DDRB  |= (1 << DDB2);                     /* OC1B = D10 → porta do MOSFET */
    TCCR1A = (1 << COM1B1) | (1 << WGM11);
    TCCR1B = (1 << WGM13) | (1 << WGM12) | (1 << CS10); /* modo 14, N = 1 */
    ICR1   = 799;                             /* 16 MHz/800 = 20 kHz */
    OCR1B  = 0;
}

void motor_velocidade(uint8_t porcento)      /* 0..100 */
{
    if (porcento > 100) porcento = 100;
    /* 100 % → 800 > TOP: nunca compara, pino sempre em 1;
       0 % → pulso de 1 contagem (62,5 ns), desprezível para o motor */
    OCR1B = (uint16_t)((uint32_t)porcento * 800u / 100u);
}
```

**Exemplo 6 (Phase Correct no D3, Timer2).**
```c
#include <avr/io.h>

void pwm_d3_inicia(uint8_t duty)
{
    DDRD  |= (1 << DDD3);                     /* OC2B = D3 */
    TCCR2A = (1 << COM2B1) | (1 << WGM20);    /* Phase Correct 8 bits */
    TCCR2B = (1 << CS22);                     /* Timer2: CS22 = /64 → 490,2 Hz */
    OCR2B  = duty;                            /* D = duty/255 */
}
```
Atenção: no Timer2, `CS22` sozinho é /64; no Timer0 o mesmo padrão de bits (CS02) seria /256.

**No Arduino**, dá para mudar a frequência de D9/D10 sem abandonar o `analogWrite`, mexendo só no prescaler do Timer1 (Shirriff mostra a mesma ideia):
```cpp
void setup() {
  pinMode(9, OUTPUT);
  TCCR1B = (TCCR1B & 0xF8) | 0x01;   // Timer1 com N = 1: 16 MHz/(2·255) = 31,37 kHz
  analogWrite(9, 128);               // continua funcionando, agora acima da faixa audível
}
void loop() {}
```
Não faça isso com o Timer0: o `millis()` e o `delay()` passam a contar 64 vezes mais rápido (T08).

**4. Aplicações.**
- **LED**: resistor como no T02; o PWM só liga e desliga a corrente já limitada. Acima de ~100 Hz não há cintilação visível de frente (em movimento ou numa câmera, às vezes há).
- **Motor DC**: **nunca** direto no pino. MOSFET de nível lógico (V_GS(th) baixo, R_DS(on) especificado a 4,5 V) ou transistor NPN com resistor de base, **diodo de roda livre** em paralelo com o motor e capacitor de 100 nF nos terminais do motor. Para inverter o sentido, ponte H (M2.2).
- **Servo**: o sinal é de nível lógico (corrente mínima), mas a **alimentação** do servo deve vir de uma fonte capaz de picos de centenas de mA, com GND comum ao Arduino.
- **"DAC" com RC**: média = D·V; ondulação de pico a pico ΔV ≈ V·D·(1 − D)/(f·R·C) quando f ≫ 1/(2πRC) (M0.5.T03). **Exemplo 7.** Fast PWM de 8 bits a 62,5 kHz, D = 50 %, R = 10 kΩ, C = 1 µF: ΔV ≈ 5 × 0,25/(62 500 × 0,01) = **2 mV**, com constante de tempo de 10 ms. A 490 Hz, a mesma ondulação pediria um C 128 vezes maior (e uma resposta 128 vezes mais lenta).

## Laboratório

### Material
- **Placa Arduino Uno ou Nano** e cabo USB. **Alternativas sem placa:** (a) **Wokwi** (wokwi.com): Uno, LED, servo (componente *Servo*, que mostra o ângulo) e o *Logic Analyzer* para medir frequência e ciclo de trabalho no PulseView; (b) **simavr**: o simulador executa o `.elf` e mostra os registradores do timer, as flags e as interrupções (com `AVR_MCU_VCD_FILE` do cabeçalho `avr_mcu_section.h` e o GTKWave). Limitações medidas ao preparar este roteiro com o simavr 1.6 (o pacote das distribuições Linux): a mudança do pino OCnx não aparece no traço, então meça **a frequência pelas flags** (conte os estouros em 1 s usando outro timer como referência); o Fast PWM de 8 bits sai certo (976 estouros/s no Timer0 com N = 64), mas o Phase Correct e o Fast PWM com TOP em ICR1 dão taxas absurdas. Para os Experimentos 3 a 5, use o Wokwi ou a placa, e registre a limitação no relatório.
- Protoboard, LEDs, resistores de 330 Ω e 10 kΩ, capacitores de 1 µF e 10 µF (filtro RC).
- Micro servo de 9 g (tipo SG90) e, se possível, uma fonte de 5 V separada para ele.
- Motor DC pequeno (3–6 V), MOSFET de nível lógico (IRLZ44N, IRLB8721 ou similar) ou transistor TIP120/BC337 com resistor de base, diodo 1N4007 (ou 1N5819), capacitor de 100 nF, fonte para o motor.
- Osciloscópio ou analisador lógico (bancada básica) e multímetro.

> **Segurança.** O motor e o servo puxam correntes que a USB do computador pode não aguentar: use fonte separada com GND comum. Diodo de roda livre sempre no motor.

### Passo a passo
**Experimento 1 — `analogWrite` medido (≈ 1,5 h).**
1. No sketch, faça `analogWrite` com 0, 1, 64, 127, 128, 254 e 255 nos pinos 6 e 9. Para cada valor, meça no osciloscópio ou no analisador: frequência, ciclo de trabalho e, com o multímetro em DC, a tensão média.
2. Compare com as fórmulas do Fast PWM (pino 6) e do Phase Correct (pino 9). Explique o que acontece com 0, 1, 254 e 255 (procure no `wiring_analog.c`).

**Experimento 2 — Fast PWM por registrador e o fade (≈ 1,5 h).**
1. Compile o Exemplo 3 com avr-gcc (ou na IDE com `main()` próprio). Meça a frequência.
2. Mude N para 1, 8, 256 e 1024: anote a frequência de cada um e a partir de qual o LED começa a cintilar a olho nu (e filmando com o celular).
3. Implemente a correção gama com uma tabela de 256 bytes em `PROGMEM` (M1.3.T04) e compare os dois fades a olho.

**Experimento 3 — Servo (≈ 1,5 h).**
1. Monte o servo no D9 (sinal), com alimentação de 5 V separada e GND comum. Rode o Exemplo 4 com 0°, 45°, 90°, 135° e 180°.
2. Meça a largura do pulso e o período no osciloscópio para cada ângulo. Confira com (OCR1A + 1) × 0,5 µs.
3. Descubra, com cuidado (passos pequenos, sem forçar o batente), a faixa de pulso que o seu servo aceita.
4. Faça o servo seguir um botão: cada aperto (com o debounce do T02) avança 30°.

**Experimento 4 — Motor: audível × inaudível (≈ 2 h).**
1. Monte o motor com MOSFET, diodo e capacitor. Com o `analogWrite` no D10 (490 Hz), varie a velocidade: escute o motor e anote a menor porcentagem em que ele começa a girar.
2. Troque para o Exemplo 5 (20 kHz). O ruído mudou? A menor velocidade mudou? Meça a tensão no dreno do MOSFET com o osciloscópio e observe o pico de comutação com e sem o diodo de roda livre (sem o diodo, por poucos segundos e com o motor pequeno).

**Experimento 5 — PWM vira tensão (≈ 1,5 h).**
1. No D9 com o Timer1 em Fast PWM de 8 bits e N = 1 (62,5 kHz), ligue um RC de 10 kΩ e 1 µF. Meça a média e a ondulação (acoplamento AC) para D = 25 %, 50 % e 75 %.
2. Repita com o `analogWrite` padrão (490 Hz). Compare as ondulações com a fórmula.
3. Meça o tempo de subida da saída quando D salta de 20 % para 80 %.

## Pratique
1. Fast PWM de 8 bits no Timer2, N = 8, a 16 MHz: qual a frequência? E em Phase Correct?
2. Que OCR0A dá D = 25 % em Fast PWM não invertido de 8 bits? E em Phase Correct?
3. Você precisa de 25 kHz (ventoinha de 4 fios) no D10. Calcule ICR1 e o OCR1B para 40 %.
4. Por que `OCR0A = 0` em Fast PWM não dá 0 %? Como obter 0 % de verdade?
5. Calcule a resolução em bits de um PWM de 20 kHz a 16 MHz em Fast PWM com N = 1.
6. No servo do Exemplo 4, qual OCR1A dá 1,25 ms?
7. Um RC de 4,7 kΩ e 10 µF filtra um PWM de 490 Hz com D = 50 % em 5 V. Estime a ondulação.
8. Por que o Timer1 em modo 14 é preferível ao modo 15 (TOP = OCR1A) quando você quer dois canais de PWM?

## Armadilhas comuns
- Esquecer o `DDRx` do pino OCnx: o timer gera o PWM, mas o pino continua entrada.
- Usar a fórmula do Fast PWM no Phase Correct (ou vice-versa): erro de 2×.
- Achar que OCR = 0 em Fast PWM é 0 %.
- Copiar os bits CS de um timer para outro (o Timer2 tem outra tabela).
- Mexer no Timer0 num sketch Arduino e estragar `millis`/`delay`.
- Ligar motor direto no pino, ou sem diodo de roda livre.
- Alimentar o servo pela USB e ver o Arduino reiniciar a cada movimento.
- Escolher frequência alta demais e ficar sem resolução (ou baixa demais e ouvir o motor).

## Gabarito
1. 16 × 10⁶/(8 × 256) = 7812,5 Hz; Phase Correct: 16 × 10⁶/(2 × 8 × 255) = 3921,6 Hz.
2. Fast: (OCR + 1)/256 = 0,25 → OCR0A = 63. Phase Correct: OCR/255 = 0,25 → 63,75 → 64 (25,1 %).
3. N = 1: ICR1 = 16 × 10⁶/25 000 − 1 = 639; OCR1B = 0,4 × 640 − 1 = 255 (D = 256/640 = 40 %).
4. Em Fast PWM o pino vai a 1 no BOTTOM e só cai na comparação; com OCR = 0 fica um pulso de 1 contagem. Para 0 %, desligue o COM e deixe o pino em 0 (é o que o `analogWrite(pino, 0)` faz) ou use o modo invertido com OCR = TOP.
5. 16 × 10⁶/20 000 = 800 contagens → log₂ 800 ≈ 9,6 bits.
6. 1,25 ms/0,5 µs = 2500 contagens → OCR1A = 2499.
7. 5 × 0,25/(490 × 4700 × 10 × 10⁻⁶) ≈ 54 mV.
8. No modo 15, OCR1A guarda o TOP, e o OC1A só pode fazer toggle (50 %); sobra um canal de PWM. No modo 14, o TOP fica em ICR1 e OC1A e OC1B ficam livres.

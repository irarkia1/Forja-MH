# M1.2.T09 — ATmega328 sem Arduino (bare metal, avrdude)

> Tópico de **elite** (laboratório). Tempo previsto: ~18,5 h — ≈ 4 h de estudo (datasheet, manuais do avrdude e do avr-libc, Williams), ≈ 3 h montando o Makefile e calculando fuses, ≈ 9 h de laboratório (chip sozinho na protoboard, gravação por ISP e pelo bootloader), ≈ 2,5 h de relatório e revisão. É o fechamento do módulo: o mesmo ATmega328P, agora **sem placa e sem IDE**. Você compila com avr-gcc, gera o `.hex`, grava com avrdude, escolhe o clock pelos fuses e monta o circuito mínimo do chip. Tudo o que a IDE fazia escondido (T01) passa a ser seu — e é exatamente assim que se trabalha num produto, com placa própria (M2) e integração contínua.

## Ao final você consegue
- Compilar, ligar e converter um programa com avr-gcc, avr-objcopy e avr-size e automatizar o processo com um Makefile.
- Gravar a flash com avrdude pelo bootloader (programador arduino) e por ISP (usbasp, ArduinoISP), escolhendo programador, porta e velocidade.
- Ler e gravar os fuses com segurança, calculando os valores de lfuse, hfuse e efuse para o clock e o bootloader desejados.
- Montar o ATmega328P mínimo em protoboard (alimentação, desacoplamento, reset, cristal e ICSP) e diagnosticar falhas de gravação.

## Estude
- Microchip — datasheet do ATmega328P: *Memory Programming* (*Fuse Bits*: tabelas *Extended Fuse Byte*, *Fuse High Byte*, *Fuse Low Byte* e os valores de fábrica; *Serial Downloading*, a gravação por SPI/ISP, com a exigência de clock de SCK); *Boot Loader Support – Read-While-Write Self-Programming* (tabela *Boot Size Configuration*); *System Clock and Clock Options* (tabelas de CKSEL e SUT); *System Control and Reset* (*Brown-out Detection*, tabela de BODLEVEL); *Pin Configurations*. Também: *AVR042: AVR Hardware Design Considerations* (nota de aplicação: desacoplamento, reset, cristal, conector ISP).
- AVRDUDE — manual oficial (documentação do projeto no GitHub): opções `-p`, `-c`, `-P`, `-b`, `-B`, `-U memória:op:arquivo:formato`, `-v`, `-e`, `-F`, `-t` (modo terminal) e a lista de programadores (`avrdude -c ?`).
- avr-libc — manual, *A simple project* (o fluxo avr-gcc → avr-objcopy → avrdude, com Makefile), *Using the GNU tools*, *Memory Sections* (`.text`, `.data`, `.bss`, `.eeprom`, `.fuse`), *<avr/eeprom.h>: EEPROM handling* e *<avr/fuse.h>: Fuse Support*.
- Elliot Williams — *Make: AVR Programming*: capítulo *Programming AVRs* (programadores, ISP, Makefile do livro, fuses) e o apêndice/seções sobre o circuito mínimo na protoboard.
- Arduino — tutoriais *Arduino as ISP and Arduino Bootloaders* e *From Arduino to a Microcontroller on a Breadboard* (o "Arduino na protoboard").
- Revise o T01 (clock, fuses, bootloader), o M1.3.T09 (startup, `.data`/`.bss`, vetor de reset) e o M0.7 (Make, terminal, Git).

## Resumo
**1. Do C ao `.hex`.**
```
avr-gcc -mmcu=atmega328p -DF_CPU=16000000UL -Os -Wall -Wextra -std=gnu11 \
        -ffunction-sections -fdata-sections -c main.c -o main.o     # compila
avr-gcc -mmcu=atmega328p -Wl,--gc-sections main.o -o main.elf        # liga (com o startup do avr-libc)
avr-objcopy -O ihex -R .eeprom main.elf main.hex                     # só a flash, em Intel HEX
avr-objcopy -j .eeprom --change-section-lma .eeprom=0 -O ihex main.elf main.eep   # a EEPROM
avr-size --format=avr --mcu=atmega328p main.elf                      # % de flash e SRAM usados
avr-objdump -d main.elf > main.lst                                   # para conferir o código (M1.3.T08)
```
- `-mmcu` escolhe o chip: define os registradores do `<avr/io.h>`, o mapa de memória e o startup (`crtatmega328p.o`) que copia `.data` e zera `.bss` (M1.3.T09).
- `-ffunction-sections -fdata-sections` + `--gc-sections` jogam fora funções não usadas.
- O **Intel HEX** é texto: cada linha `:LLAAAATT DD… CC` traz o número de bytes (LL), o endereço (AAAA), o tipo (00 dados, 01 fim) e um *checksum* (complemento de dois da soma). É o formato que o avrdude e o Wokwi aceitam.

**Exemplo 1 (o programa do laboratório).** Pisca o LED, conta os boots na EEPROM e se apresenta pela serial:
```c
#define F_CPU 16000000UL
#define BAUD 9600
#include <avr/io.h>
#include <avr/eeprom.h>
#include <util/delay.h>
#include <util/setbaud.h>
#include <stdint.h>

static uint16_t EEMEM boots_ee = 0;              /* vai para a seção .eeprom */

static void uart_inicia(void)
{
    UBRR0H = UBRRH_VALUE;
    UBRR0L = UBRRL_VALUE;
#if USE_2X
    UCSR0A |= (1 << U2X0);
#endif
    UCSR0B = (1 << TXEN0);
}

static void uart_texto(const char *s)
{
    while (*s) {
        while (!(UCSR0A & (1 << UDRE0)))
            ;
        UDR0 = (uint8_t)*s++;
    }
}

static void uart_numero(uint16_t n)
{
    char buf[6];
    uint8_t i = 0;
    do { buf[i++] = (char)('0' + n % 10); n /= 10; } while (n);
    while (i) {
        while (!(UCSR0A & (1 << UDRE0)))
            ;
        UDR0 = (uint8_t)buf[--i];
    }
}

int main(void)
{
    uint16_t boots = eeprom_read_word(&boots_ee);
    if (boots == 0xFFFF)                         /* EEPROM apagada lê 0xFFFF */
        boots = 0;
    eeprom_update_word(&boots_ee, ++boots);      /* só grava se mudou */

    uart_inicia();
    uart_texto("Forja M&H: maquina acordada, boot ");
    uart_numero(boots);
    uart_texto("\r\n");

    DDRB |= (1 << DDB5);                         /* LED em PB5 (pino 19 do DIP) */
    for (;;) {
        PINB = (1 << PINB5);
        _delay_ms(500);
    }
}
```
Rodado no simavr: imprime `boot 1`; numa variante de teste que reinicia o chip pelo watchdog depois de cada mensagem, sai `boot 1`, `boot 2`, `boot 3` — a EEPROM sobrevive ao reset. Repare no `0xFFFF`: o `.eep` gravado põe 0, mas uma gravação só da flash com o chip apagado (e EESAVE desligado) deixa a EEPROM em 0xFF.

**2. O Makefile.** Automatiza o fluxo e documenta as decisões (chip, clock, programador, fuses). As linhas de comando começam com **tabulação**.
```make
MCU      = atmega328p
F_CPU    = 16000000UL
# PROG: usbasp, arduino (bootloader) ou stk500v1 (ArduinoISP)
PROG     = usbasp
# PORTA: usb para o usbasp; /dev/ttyACM0 (ou ttyUSB0) para arduino e stk500v1
PORTA    = usb
# BAUD_UP: 115200 (Optiboot), 57600 (Nano antigo), 19200 (ArduinoISP)
BAUD_UP  = 115200
LFUSE    = 0xFF
HFUSE    = 0xDE
EFUSE    = 0xFD

CC       = avr-gcc
CFLAGS   = -mmcu=$(MCU) -DF_CPU=$(F_CPU) -Os -Wall -Wextra -std=gnu11 \
           -ffunction-sections -fdata-sections
LDFLAGS  = -mmcu=$(MCU) -Wl,--gc-sections
AVRDUDE  = avrdude -p m328p -c $(PROG) -P $(PORTA) -b $(BAUD_UP)

all: main.hex main.eep size

main.elf: main.o
	$(CC) $(LDFLAGS) $^ -o $@
%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@
main.hex: main.elf
	avr-objcopy -O ihex -R .eeprom $< $@
main.eep: main.elf
	avr-objcopy -j .eeprom --change-section-lma .eeprom=0 -O ihex $< $@
size: main.elf
	avr-size --format=avr --mcu=$(MCU) $<
flash: main.hex
	$(AVRDUDE) -U flash:w:main.hex:i
eeprom: main.eep
	$(AVRDUDE) -U eeprom:w:main.eep:i
fuses:
	$(AVRDUDE) -U lfuse:w:$(LFUSE):m -U hfuse:w:$(HFUSE):m -U efuse:w:$(EFUSE):m
le-fuses:
	$(AVRDUDE) -U lfuse:r:-:h -U hfuse:r:-:h -U efuse:r:-:h
clean:
	rm -f *.o *.elf *.hex *.eep

.PHONY: all size flash eeprom fuses le-fuses clean
```
`make` compila; `make flash` grava; `make le-fuses` lê os fuses sem mudar nada. Coloque o projeto no Git (M0.7) com o Makefile: qualquer pessoa reproduz o firmware com um comando.

**3. avrdude.**

| Caminho | Programador (`-c`) | Porta (`-P`) | Velocidade (`-b`) | Observações |
|---|---|---|---|---|
| Bootloader do Uno (Optiboot) | `arduino` | `/dev/ttyACM0` | 115200 | não mexe em fuses nem no bootloader |
| Bootloader de Nano antigo | `arduino` | `/dev/ttyUSB0` | 57600 | idem |
| USBasp (gravador ISP barato) | `usbasp` | `usb` | — | `-B` ajusta o clock de SCK |
| Arduino como ISP (sketch *ArduinoISP*) | `stk500v1` (ou `avrisp`) | `/dev/ttyACM0` | 19200 | capacitor de 10 µF entre RESET e GND do Arduino gravador |

`-U memória:operação:arquivo:formato`: memória = `flash`, `eeprom`, `lfuse`, `hfuse`, `efuse`, `lock`, `signature`; operação = `w` (grava e verifica), `r` (lê), `v` (só verifica); formato = `i` (Intel HEX), `m` (valor imediato, como `0xFF`), `h` (saída em hexa), `e` (ELF). Toda gravação **por ISP** começa com *chip erase* (flash inteira, inclusive o bootloader, e a EEPROM se EESAVE não estiver programado).

- **Clock de gravação**: pelo datasheet (*Serial Downloading*), o SCK do ISP precisa ser **menor que 1/4 do clock do chip**. Um ATmega328P novo roda a 1 MHz: SCK < 250 kHz. Gravadores rápidos falham ("*initialization failed*"); use `-B` maior (no USBasp, `-B 10` ou mais) até ajustar os fuses.
- **Assinatura**: o avrdude lê a assinatura e compara com a do `-p`. ATmega328P = **1E 95 0F**; ATmega328 (sem P) = 1E 95 14.
- **Linux**: o usuário precisa estar no grupo `dialout` (portas seriais) e o USBasp precisa de uma regra udev; senão, só funciona como root.

**4. Fuses (0 = programado).**

| Byte | Bit 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
|---|---|---|---|---|---|---|---|---|
| **lfuse** | CKDIV8 | CKOUT | SUT1 | SUT0 | CKSEL3 | CKSEL2 | CKSEL1 | CKSEL0 |
| **hfuse** | RSTDISBL | DWEN | SPIEN | WDTON | EESAVE | BOOTSZ1 | BOOTSZ0 | BOOTRST |
| **efuse** | — | — | — | — | — | BODLEVEL2 | BODLEVEL1 | BODLEVEL0 |

- **lfuse**: CKSEL3..0 = 0010 → RC interno de 8 MHz; 1111 a 1000 → cristal de baixo consumo (faixas por frequência; 111x = 8–16 MHz); 0111/0110 → cristal *full swing*; 0000 → clock externo no XTAL1. SUT escolhe o tempo de partida. CKDIV8 = 0 divide por 8. CKOUT = 0 põe o clock no PB0.
- **hfuse**: BOOTSZ1:0 = 11/10/01/00 → seção de boot de 256/512/1024/2048 palavras (512 B, 1 KB, 2 KB, 4 KB), BOOTRST = 0 → o reset vai para o bootloader; EESAVE = 0 → o chip erase preserva a EEPROM; SPIEN = 0 → ISP ligado (não muda por ISP); DWEN = 0 → debugWIRE (desliga o ISP!); RSTDISBL = 0 → RESET vira GPIO (o ISP morre; só gravador de alta tensão recupera).
- **efuse**: BODLEVEL = 111 desliga o brown-out; 110 = 1,8 V; 101 = 2,7 V; 100 = 4,3 V. Os bits não usados leem 1 (por isso aparece 0xFD) ou 0 (0x05), conforme a versão do avrdude: só os 3 bits de baixo importam.

**Exemplo 2 (decodificar e calcular).**
- Fábrica: lfuse **0x62** = 0110 0010 → CKDIV8 = 0 (÷8), CKOUT = 1, SUT = 10, CKSEL = 0010 (RC 8 MHz) → **1 MHz**. Tirar só o ÷8: CKDIV8 = 1 → 1110 0010 = **0xE2** → 8 MHz sem cristal.
- Uno: lfuse **0xFF** (cristal/ressonador de baixo consumo, partida mais longa, sem ÷8); hfuse **0xDE** = 1101 1110 → SPIEN = 0, EESAVE = 1, BOOTSZ = 11 (512 B), BOOTRST = 0; efuse **0xFD** → BODLEVEL = 101 (2,7 V).
- Chip sem bootloader, cristal de 16 MHz, EEPROM preservada: lfuse 0xFF; hfuse = 1101 0111 = **0xD7** (EESAVE = 0, BOOTSZ = 11, BOOTRST = 1: o reset vai ao endereço 0); efuse 0xFD.
- Nano antigo: hfuse **0xDA** = 1101 1010 → BOOTSZ = 01 (1024 palavras = 2 KB), BOOTRST = 0.

**Fuses perigosos** — antes de gravar, leia (`make le-fuses`), confira numa calculadora de fuses e repita a conta à mão:
- CKSEL para cristal ou clock externo **sem** o cristal montado: o chip "morre" (não responde ao ISP). Recupera-se injetando um clock no XTAL1 (por exemplo, um PWM ou o CLKO de outro Arduino) e regravando.
- RSTDISBL e DWEN: o ISP para de funcionar. Não grave sem um gravador de alta tensão à mão.
- Também dá para declarar os fuses no próprio código, numa seção `.fuse` do ELF (o avrdude grava a partir do ELF com o formato `e`):
```c
#include <avr/io.h>

FUSES = {
    .low      = 0xFF,   /* cristal de 16 MHz, sem ÷8 */
    .high     = 0xD7,   /* SPIEN, EESAVE, sem bootloader */
    .extended = 0xFD,   /* brown-out em 2,7 V */
};

int main(void)
{
    for (;;) {
    }
}
```

**5. O circuito mínimo** (AVR042 e o tutorial *Arduino on a Breadboard*):
- **Alimentação**: VCC (pino 7) e AVCC (pino 20) no 5 V; GND nos pinos 8 e 22. Um capacitor de **100 nF** cerâmico em cada par VCC/GND, **colado** aos pinos; um eletrolítico de 10 µF na entrada da protoboard. AVCC precisa estar ligado mesmo sem usar o ADC (alimenta a porta C).
- **Reset**: 10 kΩ do pino 1 ao VCC (pull-up) e, se quiser o reset automático pelo adaptador serial, 100 nF do DTR ao pino 1.
- **Clock**: cristal de 16 MHz entre os pinos 9 e 10 com dois capacitores de **22 pF** ao GND (ou nada, se usar o RC interno de 8 MHz).
- **AREF** (pino 21): 100 nF ao GND se usar AVCC como referência do ADC.
- **ICSP** (conector de 2 × 3): 1 = MISO (pino 18, PB4), 2 = VCC, 3 = SCK (19, PB5), 4 = MOSI (17, PB3), 5 = RESET (1), 6 = GND. Com o ArduinoISP: D10 → RESET, D11 → MOSI, D12 → MISO, D13 → SCK.
- **Serial**: adaptador USB-serial de 5 V (TX → pino 2 RXD, RX ← pino 3 TXD, GND).

**Diagnóstico**:

| Sintoma | Causa provável |
|---|---|
| assinatura 0x000000 ou 0xFFFFFF, *initialization failed* | fio do ISP errado, chip sem alimentação, sem clock (fuse de cristal sem cristal) ou SCK rápido demais para 1 MHz (`-B`) |
| *Invalid device signature* com 1E 95 14 | é um ATmega328 (sem P): use `-p m328`, não `-F` |
| *not in sync* / *programmer is not responding* | sem bootloader, taxa errada, porta errada, D0 ocupado, sem reset automático |
| grava, mas o LED pisca 16× mais devagar | lfuse ainda de fábrica (1 MHz) com `F_CPU` de 16 MHz |
| serial com lixo | `F_CPU` errado, fuse de clock errado ou RC interno com erro alto |
| reinicia sozinho | falta desacoplamento, brown-out com fonte fraca, ISR sem handler (T05) |
| *permission denied* na porta | usuário fora do grupo `dialout` ou sem regra udev |

## Laboratório

### Material
- **ATmega328P DIP-28** (de preferência dois: um virgem e um com bootloader), **cristal de 16 MHz**, 2 capacitores de 22 pF, 3 capacitores de 100 nF, 1 eletrolítico de 10 µF, resistor de 10 kΩ, LED com 330 Ω, protoboard e jumpers.
- **Gravador ISP**: USBasp (barato) **ou** um Arduino Uno/Nano com o sketch *ArduinoISP* (mais 1 capacitor de 10 µF).
- **Adaptador USB-serial de 5 V** (CH340, CP2102 ou FT232) ou um Uno sem o chip, para a serial; fonte de 5 V (a do próprio USB serve); multímetro.
- PC com avr-gcc, avr-libc, avrdude e make (`sudo apt install gcc-avr avr-libc avrdude make` no Debian/Ubuntu; no Windows, o pacote da Microchip ou o avr-gcc da instalação da IDE).
- **Alternativas, se não houver chip avulso ou gravador:** (a) **só a placa Uno/Nano**: grave o seu `.hex` pela USB com `avrdude -c arduino` (sem IDE) — cobre o Makefile, o avrdude pelo bootloader e a leitura da assinatura (Experimentos 1 e 2); a gravação por ISP e os fuses podem ser feitos no próprio Uno pelo conector ICSP com um segundo Arduino como gravador (apaga o bootloader: regrave-o no fim com "Burn Bootloader" da IDE); (b) **Wokwi**: aceita o `.hex` ou o `.elf` gerado pelo seu Makefile (no editor, F1 → *Upload Firmware and Start Simulation*) — confere o firmware sem placa, mas não simula avrdude nem fuses; (c) **simavr**: `simavr -m atmega328p -f 16000000 main.elf` roda o firmware e mostra a saída da UART no terminal (a seção `.eeprom` do ELF é carregada junto; reinícios pelo watchdog preservam a EEPROM simulada). Registre o que foi feito em simulação.

> **Segurança do chip.** Leia os fuses antes de gravar e **nunca** grave RSTDISBL nem DWEN. Desligue a alimentação antes de mexer no circuito. Confira o pino 1 do DIP (marca em U) antes de energizar.

### Passo a passo
**Experimento 1 — Makefile e avrdude pelo bootloader (≈ 2 h).**
1. Crie o projeto (`main.c` do Exemplo 1 e o Makefile), rode `make` e anote a saída do `avr-size`. Abra o `main.hex` e decodifique a primeira linha à mão (contagem, endereço, tipo, checksum).
2. Ligue o Uno e grave **sem a IDE**: `make flash PROG=arduino PORTA=/dev/ttyACM0 BAUD_UP=115200`. Abra a serial (`picocom -b 9600 /dev/ttyACM0` ou o Monitor Serial) e aperte o reset algumas vezes: o número de boots sobe.
3. Rode `avrdude -p m328p -c arduino -P /dev/ttyACM0 -b 115200 -v` e anote assinatura, versão do bootloader e o que o bootloader **não** deixa fazer (fuses).
4. Compare com a IDE: ative a saída verbosa (T01) e compare a linha do avrdude dela com a sua.

**Experimento 2 — O chip sozinho na protoboard (≈ 3 h).**
1. Monte o circuito mínimo **com** cristal, ICSP e LED no pino 19. Antes de ligar, confira com o multímetro: VCC–GND sem curto, VCC nos pinos 7 e 20, GND nos 8 e 22.
2. Ligue o gravador (USBasp ou ArduinoISP). Com um **chip virgem** (1 MHz), rode `make le-fuses PROG=usbasp` com `-B 10` (ou `PROG=stk500v1 PORTA=/dev/ttyACM0 BAUD_UP=19200`). Anote a assinatura e os três fuses; decodifique-os bit a bit.
3. Grave o firmware com os fuses de fábrica e meça o período do LED (cronômetro ou osciloscópio). Explique o resultado com o `F_CPU`.
4. Calcule e grave os fuses para cristal de 16 MHz, sem bootloader e com EESAVE (Exemplo 2). Grave de novo o firmware e meça o período do LED.
5. Ligue o adaptador USB-serial nos pinos 2 e 3 e veja a mensagem de boot.

**Experimento 3 — Bootloader no chip avulso (≈ 1,5 h).**
1. Com o gravador, grave o Optiboot (`optiboot_atmega328.hex`, que vem na pasta `bootloaders` do núcleo Arduino AVR) e os fuses do Uno (0xFF, 0xDE, 0xFD) — é o que a IDE faz em "Burn Bootloader". Use o seu Makefile ou o avrdude direto.
2. Ligue o reset automático (100 nF do DTR do adaptador ao pino 1) e grave o firmware **pela serial**, com `-c arduino`. Agora o chip na protoboard é um "Arduino".
3. Responda: quanto de flash você perdeu para o bootloader, e o que ganhou?

**Experimento 4 — Diagnóstico provocado (≈ 1,5 h).** Provoque cada falha, anote a mensagem exata do avrdude e a correção:
1. Fio do MISO solto.
2. Chip sem alimentação.
3. `-p m328` num ATmega328P (ou o contrário).
4. Chip a 1 MHz com o USBasp sem `-B` (se o seu gravador falhar).
5. Gravação pela serial sem bootloader no chip.
6. (Opcional, com cuidado e só se tiver como injetar clock no XTAL1) fuses de cristal com o cristal removido; recupere o chip injetando um clock de alguns MHz (por exemplo, o PWM de outro Arduino) no pino 9.

## Pratique
1. Escreva o lfuse para o RC interno de 8 MHz sem ÷8, com CKOUT ligado (clock no PB0) e os SUT de fábrica.
2. Qual hfuse dá bootloader de 1 KB, reset no bootloader e EEPROM preservada no chip erase?
3. Um efuse lido como 0x05 e outro como 0xFD: qual a diferença?
4. Com o chip a 1 MHz, qual a maior frequência de SCK permitida no ISP?
5. Decodifique a linha `:0400000000C000003C`. Os bytes fecham o checksum?
6. Seu programa usa 31 000 bytes de flash. Ele cabe num chip com Optiboot? E com o bootloader antigo de 2 KB?
7. Por que um chip com fuses de cristal externo "morre" na protoboard sem cristal? Como recuperá-lo?
8. Escreva no Makefile um alvo `bootloader` que grava o Optiboot e os fuses do Uno.

## Armadilhas comuns
- Esquecer o desacoplamento de 100 nF ou o AVCC desligado: o chip reinicia ou nem responde.
- RESET sem pull-up: o chip fica em reset por ruído.
- ISP rápido demais para um chip a 1 MHz.
- Fuse de cristal sem cristal; RSTDISBL; DWEN.
- Confundir `-c arduino` (bootloader) com `-c avrisp`/`stk500v1` (Arduino como gravador).
- Achar que a gravação por ISP preserva o bootloader (o chip erase apaga tudo).
- Usar `-F` para ignorar a assinatura sem entender por que ela não bate.
- Comandos do Makefile com espaços no lugar de tabulação.
- `F_CPU` do Makefile diferente do clock real definido pelos fuses.

## Gabarito
1. CKDIV8 = 1, CKOUT = 0, SUT = 10, CKSEL = 0010 → 1010 0010 = 0xA2.
2. RSTDISBL 1, DWEN 1, SPIEN 0, WDTON 1, EESAVE 0, BOOTSZ = 10 (512 palavras = 1 KB), BOOTRST 0 → 1101 0100 = 0xD4.
3. Nenhuma: os 3 bits de baixo (101 = BOD 2,7 V) são iguais; os bits não usados aparecem como 1 ou 0 conforme a versão do avrdude.
4. 1 MHz/4 = 250 kHz (use menos, por margem).
5. 04 bytes, endereço 0x0000, tipo 00 (dados): 00 C0 00 00 — a palavra 0xC000 (os bytes vêm em *little endian*), que é um `rjmp` para a instrução seguinte, e mais dois bytes 0. Soma: 04 + 00 + 00 + 00 + 00 + C0 + 00 + 00 = 0xC4; complemento de dois de 0xC4 = 0x3C ✔.
6. Optiboot: 32 256 disponíveis → cabe. Bootloader de 2 KB: 30 720 → não cabe.
7. Com CKSEL de cristal, o chip espera oscilação nos pinos 9 e 10; sem cristal não há clock, e sem clock nem o ISP funciona. Injete um clock externo no XTAL1, grave lfuse de volta (por exemplo, 0x62 ou 0xE2) e remova o clock.

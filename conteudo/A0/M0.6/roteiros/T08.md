# M0.6.T08 — C++ para embarcados (classes, RAII, templates leves, o que evitar)

> O Arduino é C++, o ESP-IDF aceita C++ e muitos firmwares de STM32 também usam. Este tópico não ensina "todo o C++": ensina o subconjunto que vale a pena num microcontrolador — o que dá segurança e organização **sem custo** em tempo de execução — e o que deixar de fora.

## Ao final você consegue
- Escrever classes com construtor, destrutor, membros privados e métodos const, e usar referências no lugar de ponteiros quando o objeto sempre existe.
- Aplicar RAII para garantir a liberação de recursos e prever a ordem de construção e destruição de objetos.
- Usar constexpr, enum class, std::array e templates simples para obter verificação em tempo de compilação sem custo em tempo de execução.
- Justificar o que evitar em microcontroladores (exceções, RTTI, alocação dinâmica, iostream) e as flags que desligam esses recursos.

## Estude
Tempo previsto: ~15 h (≈ 4 h de leitura, ≈ 8 h programando e comparando assembly, ≈ 3 h de exercícios e revisão).

- *C++ Core Guidelines* (isocpp.github.io/CppCoreGuidelines): R.1 (*Manage resources automatically using RAII*), Enum.3 (*Prefer class enums over "plain" enums*), Con.5 (*Use constexpr for values that can be computed at compile time*) e F.16 (*For "in" parameters, pass cheaply-copied types by value and others by reference to const*).
- Elecia White — *Making Embedded Systems* (1ª ed., 2011; na 2ª ed. os capítulos mudam de número): cap. 2 (*Creating a System Architecture*), sobre encapsular o hardware em módulos com interface — a mesma ideia que uma classe expressa.

## Resumo
**1. Classes.** Uma classe junta dados e as funções que os manipulam e esconde o que é detalhe (`private`).
```cpp
#include <cstdint>

class Led {
public:
    explicit Led(std::uint8_t pino) : pino_(pino) {}   // lista de inicialização
    void liga()    { aceso_ = true;  /* escreveria no registrador */ }
    void desliga() { aceso_ = false; }
    bool aceso() const { return aceso_; }               // const: não altera o objeto
private:
    std::uint8_t pino_;
    bool aceso_ = false;                                // inicializador padrão do membro
};

Led verde(5);
verde.liga();
```
- `struct` e `class` são iguais, exceto o acesso padrão (`public` × `private`). Convenção: `struct` para dados simples, `class` quando há invariantes a proteger.
- `explicit` impede conversões implícitas (`Led l = 5;` não compila). Métodos `const` podem ser chamados em objetos `const`; os outros, não.
- Prefira inicializar na lista do construtor (`: pino_(pino)`), não com atribuição no corpo.

**2. Referências.** `int& r = x;` é outro nome para `x`: precisa ser inicializada, nunca é nula e não pode passar a se referir a outro objeto. Use referência quando o objeto **sempre existe**; use ponteiro quando "nenhum objeto" é um valor válido.
```cpp
void dobra(int& v) { v *= 2; }                    // altera o argumento de quem chamou
void imprime(const Leitura& l);                   // só lê, sem copiar a struct
```

**3. RAII** (*Resource Acquisition Is Initialization*). O construtor adquire o recurso e o destrutor o libera; o destrutor roda **automaticamente** quando o objeto sai do escopo — no fim do bloco, num `return` antecipado, num `break`. Não há como esquecer.
```cpp
class SecaoCritica {          // desliga interrupções enquanto existir
public:
    SecaoCritica()  { /* salva o estado e desliga as interrupções */ }
    ~SecaoCritica() { /* restaura o estado anterior */ }
    SecaoCritica(const SecaoCritica&) = delete;              // não copiável
    SecaoCritica& operator=(const SecaoCritica&) = delete;
};

void incrementa() {
    SecaoCritica sc;          // interrupções desligadas a partir daqui
    contador++;
}                             // ~SecaoCritica: religadas, mesmo com return no meio
```
**Ordem**: objetos locais são destruídos na ordem **inversa** da construção. Os membros de uma classe são construídos na ordem em que estão **declarados** — não na ordem da lista de inicialização (o `-Wall` avisa com `-Wreorder`) — e destruídos na ordem inversa.

**4. Verificação em tempo de compilação.**
- `constexpr`: a função ou o valor pode ser calculado pelo compilador. Combine com `static_assert` para recusar configurações inválidas **antes** de gravar o firmware:
```cpp
constexpr std::uint32_t divisor_uart(std::uint32_t clk, std::uint32_t baud) {
    return (clk + baud / 2) / baud;               // arredonda
}
constexpr std::uint32_t UBRR = divisor_uart(16'000'000, 115'200);   // 139, calculado na compilação
static_assert(UBRR > 0 && UBRR < 4096, "divisor fora da faixa do registrador");
```
- `enum class`: enumeradores com escopo (`Modo::Rapido`), sem conversão implícita para `int` e com tipo subjacente escolhido (`enum class Modo : std::uint8_t { Lento, Rapido };`). Para obter o número: `static_cast<std::uint8_t>(m)`.
- `std::array<T, N>` (`<array>`): um array C com `size()`, que não decai para ponteiro, pode ser copiado e atribuído, funciona com `for (auto v : a)` e não usa heap. `a[i]` não confere o índice; `a.at(i)` confere, mas lança exceção (indisponível com `-fno-exceptions`).
- **Templates leves**: código genérico resolvido na compilação. Um buffer circular com tipo e tamanho como parâmetros não usa heap e cada instância tem o tamanho exato:
```cpp
template <typename T, std::size_t N>
class BufferCircular {
    std::array<T, N> dados_{};
    std::size_t ini_ = 0, qtd_ = 0;
public:
    bool coloca(const T& v);
    bool retira(T& saida);
    constexpr std::size_t capacidade() const { return N; }
};
BufferCircular<std::uint8_t, 64> rx_uart;
```
Cuidado: cada combinação de parâmetros gera uma cópia do código (*code bloat*) — use poucos tipos.
- Outros: `nullptr` (em vez de `NULL`), `auto`, `static_cast` (conversão explícita e visível), `for` com intervalo.

**5. Custo zero.** "O que você não usa, você não paga; o que você usa, não daria para escrever melhor à mão" (Stroustrup). Métodos comuns são funções com um parâmetro escondido (`this`); com `-O2`, `verde.liga()` gera o mesmo código que `led_liga(&verde)` em C. Confira com `g++ -O2 -S`. Tem custo: **funções virtuais** (cada objeto ganha um ponteiro para a tabela virtual — 8 bytes no x86-64, 4 num Cortex-M — e a chamada é indireta), templates usados com muitos tipos e construtores de objetos globais (rodam antes do `main`, em ordem não especificada entre arquivos).

**6. O que evitar num microcontrolador.**

| Recurso | Problema | Como desligar / substituir |
|---|---|---|
| Exceções (`throw`/`try`) | tabelas de desempilhamento e código de suporte (dezenas de KB), tempo imprevisível | `-fno-exceptions`; retorne códigos de erro (ou `std::optional`/`std::expected`) |
| RTTI (`dynamic_cast`, `typeid`) | informação de tipo em cada classe polimórfica | `-fno-rtti` |
| Alocação dinâmica (`new`, `std::vector`, `std::string`, `std::function`, `std::map`) | heap: fragmentação e falha em campo (T03) | `std::array`, buffers estáticos, templates com tamanho fixo |
| `<iostream>` (`std::cout`) | puxa locales e muito código (centenas de KB), usa heap | `printf` mínimo ou um log próprio pela UART |
| Inicialização de `static` local thread-safe | o gcc gera chamadas de trava | `-fno-threadsafe-statics` (sem RTOS com threads) |

Para usar C a partir de C++ (as bibliotecas dos fabricantes são em C), os headers usam:
```cpp
#ifdef __cplusplus
extern "C" {
#endif
void HAL_GPIO_TogglePin(GPIO_TypeDef *port, uint16_t pin);
#ifdef __cplusplus
}
#endif
```
`extern "C"` desliga a "decoração" de nomes do C++ (*name mangling*), para que o linker encontre a função compilada em C.

## Pratique
Use `~/treino-c/t08/`, compile com `g++ -std=c++17 -Wall -Wextra -g` e imprima com `std::printf` (`<cstdio>`).
1. Escreva a classe `Led` e teste `liga`, `desliga` e `aceso`. Tente `Led l = 5;` e chamar `liga()` num `const Led`. Leia os erros.
2. Escreva `void dobra(int& v)` e `void dobra_p(int* v)` e compare as chamadas.
3. Escreva uma classe `Log` que imprime `+nome` no construtor e `-nome` no destrutor. Crie objetos em blocos aninhados e preveja a saída.
4. Escreva uma função com dois `return` antecipados e um objeto `Log` no início. Confira que o destrutor roda em todos os caminhos.
5. Crie uma classe com dois membros do tipo `Log` e inicialize-os na lista do construtor em ordem **inversa** à da declaração. O que imprime? Que aviso o `-Wall` dá?
6. Escreva `divisor_uart` como `constexpr` com `static_assert`. Mude o baud para um valor que viole o `static_assert`.
7. Troque um `enum` C de modos por `enum class Modo : std::uint8_t`. Quais linhas antigas param de compilar?
8. Implemente `BufferCircular<T, N>` com `coloca`, `retira`, `vazio` e `cheio`. Teste com `uint8_t` e com uma struct.
9. Compare, com `g++ -O2 -S`, uma função C `led_liga(struct led *l)` e o método `Led::liga()`. O assembly difere?
10. Imprima `sizeof` de uma classe com um `int` e de outra com um `int` e um método `virtual`.
11. Compile um programa com `#include <iostream>` e `std::cout << "oi"`, e outro com `std::printf("oi")`, com `-O2 -static`. Compare os tamanhos com `size`.
12. Compile um programa com `throw` usando `-fno-exceptions`. Qual erro aparece?

## Armadilhas comuns
- Esquecer `const` nos métodos que só leem (e não conseguir usá-los com objetos `const`).
- Inicializar membros na lista em ordem diferente da declaração, contando com a ordem da lista.
- Copiar sem querer um objeto que gerencia recurso (dois destrutores liberam a mesma coisa): apague a cópia com `= delete`.
- Usar `std::vector`, `std::string` ou `std::function` "porque é C++" num MCU sem heap planejada.
- Incluir `<iostream>` para um único `cout`.
- `virtual` em tudo "por precaução".
- Objetos globais cujos construtores dependem de outros globais em outros arquivos (ordem de inicialização não especificada).
- Esquecer `extern "C"` ao chamar código C (erro `undefined reference` com nome "decorado", como `_Z10le_sensorv`).
- Usar `a.at(i)` com `-fno-exceptions` achando que há verificação (ela aborta o programa).

## Gabarito
1. `Led l = 5;` → erro de conversão (o construtor é `explicit`). `liga()` num `const Led` → `passing 'const Led' as 'this' argument discards qualifiers`.
2. `dobra(x)` × `dobra_p(&x)`: a referência dispensa o `&` e o teste de nulo.
3. Ex.: `Log a("A"); { Log b("B"); } Log c("C");` → `+A +B -B +C -C -A`.
4. O `-nome` aparece em todos os caminhos de saída.
5. Imprime na ordem da **declaração**; aviso `-Wreorder`: `'X::b' will be initialized after` / `'M X::a'` / `when initialized here`.
6. `static_assert` falha com a sua mensagem, na compilação (o firmware nem chega a ser gerado).
7. `int x = Modo::Rapido;` e comparações com inteiros (`m == 1`) deixam de compilar; use `static_cast`.
8. `cheio()` é `qtd_ == N`; `coloca` grava em `(ini_ + qtd_) % N`.
9. Com `-O2`, o mesmo código (o `this` é o primeiro argumento, no registrador `rdi` no x86-64).
10. 4 e 16 no x86-64 (8 bytes do ponteiro para a tabela virtual + 4 do `int` + 4 de padding).
11. A versão com `iostream` fica muito maior: no x86-64 com ligação estática, cerca de 1,9 MB de `text` contra 0,7 MB da versão com `printf`. Num MCU a proporção é parecida — e a flash tem centenas de KB.
12. `error: exception handling disabled, use '-fexceptions' to enable`.

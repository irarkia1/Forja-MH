# M0.6.T04 — Structs, unions, enums

## Ao final você consegue
- Definir e usar structs, typedef, inicializadores designados e ponteiros para struct (operador ->).
- Calcular o tamanho, o alinhamento e o padding de uma struct e reordenar campos para reduzi-los.
- Usar unions para ver os mesmos bytes de formas diferentes e determinar a endianness de uma plataforma.
- Usar enums para estados e códigos de erro e modelar uma máquina de estados com switch.

## Resumo
**1. Structs e typedef.**
```c
#include <stdint.h>

typedef struct {
    uint32_t t_ms;      /* instante da leitura          */
    int16_t  temp_dC;   /* temperatura em décimos de °C */
    uint8_t  umid;      /* umidade relativa, %           */
    uint8_t  flags;
} leitura_t;

leitura_t a = { .t_ms = 1000, .temp_dC = 235, .umid = 61 };   /* flags = 0 */
leitura_t *p = &a;
p->umid = 62;           /* p->umid é (*p).umid */
```
- Inicializadores designados (`.campo = valor`, C99) deixam claro o que é o quê; campos não citados são **zerados**. `leitura_t z = {0};` zera tudo.
- Atribuir uma struct (`b = a;`) **copia todos os campos**; passar struct por valor também copia. Para structs grandes, passe `const leitura_t *` (só leitura) ou `leitura_t *` (a função altera).
- Structs não se comparam com `==`; compare campo a campo (`memcmp` falha por causa do padding, veja abaixo).
- O sufixo `_t` é convenção comum em firmware (mas o POSIX o reserva; em código de PC, evite conflitos).

**2. Alinhamento e padding.** Cada tipo tem um **alinhamento**: num x86-64 Linux (e num Cortex-M), `uint16_t` fica em endereços múltiplos de 2, `uint32_t` de 4, `double` de 8 (`_Alignof(tipo)` mostra). O compilador insere bytes de **padding** entre campos para respeitar isso, e no fim, para que num array cada elemento continue alinhado. A ordem dos campos é mantida.
```c
struct ruim { uint8_t a; uint32_t b; uint8_t c; };   /* a@0, pad 1–3, b@4, c@8, pad 9–11 → 12 bytes */
struct boa  { uint32_t b; uint8_t a; uint8_t c; };   /* b@0, a@4, c@5, pad 6–7          →  8 bytes */
```
Regra prática: **ordene do maior para o menor alinhamento**. O tamanho da struct é múltiplo do maior alinhamento entre os campos. `offsetof(tipo, campo)` (de `<stddef.h>`) dá a posição em bytes. Arrays de structs multiplicam o padding: `struct { uint32_t id; uint8_t flag; }` tem 8 bytes, e 10 delas, 80 — não 50.

`__attribute__((packed))` (extensão do gcc) remove o padding (a struct `{uint8_t; uint32_t;}` cai de 8 para 5 bytes), mas campos desalinhados custam caro: num Cortex-M0, um acesso de 32 bits desalinhado gera *HardFault*; nos outros, fica mais lento. Use `packed` só para descrever formatos de dados fixos (cabeçalho de protocolo) e, de preferência, serialize campo a campo (item 4).

**3. Unions.** Todos os membros começam no mesmo endereço; o tamanho é o do maior membro (mais padding de alinhamento). Servem para guardar **um** de vários tipos (com um campo que diz qual — *tagged union*) ou para ver os mesmos bytes de outra forma:
```c
union palavra {
    uint32_t u32;
    uint8_t  b[4];
};
union palavra w = { .u32 = 0x11223344u };
/* little-endian (x86, ARM Cortex-M, ESP32): w.b[0] == 0x44 ... w.b[3] == 0x11 */
```
Ler um membro diferente do último escrito é permitido em C (o gcc documenta o resultado: os bytes são reinterpretados); em **C++** isso é comportamento indefinido — lá use `memcpy` ou `std::bit_cast` (C++20).

**4. Endianness.** *Little-endian*: o byte menos significativo fica no menor endereço (x86, ARM Cortex-M na configuração normal, ESP32, RISC-V). *Big-endian*: o mais significativo primeiro (a "ordem de rede" de TCP/IP e de muitos protocolos e sensores, como o Modbus). Para montar ou desmontar um valor numa ordem definida **independentemente da CPU**, use deslocamentos (T05):
```c
buf[0] = (uint8_t)(v >> 8);      /* big-endian: byte alto primeiro */
buf[1] = (uint8_t)(v & 0xFFu);
uint16_t lido = (uint16_t)((buf[0] << 8) | buf[1]);
```
`memcpy(buf, &v, 2)` ou `*(uint16_t *)buf = v` dependem da endianness da CPU (e o segundo também do alinhamento de `buf`).

**5. Enums.** Dão nome a constantes inteiras: começam em 0 e cada um vale o anterior + 1, a menos que você atribua um valor.
```c
typedef enum { ERR_OK = 0, ERR_TIMEOUT, ERR_CRC, ERR_CHEIO = 10, ERR_VAZIO } erro_t;
/* ERR_TIMEOUT = 1, ERR_CRC = 2, ERR_VAZIO = 11 */
```
As constantes são do tipo `int` e servem como rótulos de `case` (ao contrário de uma `const int`). O tamanho do tipo enum é definido pela implementação: em structs que precisam de layout fixo (protocolo, registrador), guarde o valor num `uint8_t`. O C não impede atribuir a um enum um valor fora da lista (o `enum class` do C++, T08, impede).

**6. Máquina de estados.** O modelo mais usado em firmware: um enum para os estados, um para os eventos e uma função de transição.
```c
typedef enum { DESLIGADO, LIGANDO, LIGADO, FALHA } estado_t;
typedef enum { EV_BOTAO, EV_PRONTO, EV_ERRO } evento_t;

estado_t transicao(estado_t s, evento_t e)
{
    switch (s) {
    case DESLIGADO: return (e == EV_BOTAO) ? LIGANDO : DESLIGADO;
    case LIGANDO:   return (e == EV_PRONTO) ? LIGADO : (e == EV_ERRO) ? FALHA : LIGANDO;
    case LIGADO:    return (e == EV_BOTAO) ? DESLIGADO : (e == EV_ERRO) ? FALHA : LIGADO;
    case FALHA:     return (e == EV_BOTAO) ? DESLIGADO : FALHA;
    default:        return FALHA;   /* valor inválido: estado seguro */
    }
}
```
Com `-Wall`, o gcc avisa (`-Wswitch`) se faltar um `case` de algum enumerador — e é por isso que um `switch` sobre enum deve listar todos. Desenhe o diagrama de estados antes de escrever (no M0.7.T04 você aprendeu Mermaid: `stateDiagram-v2`).

## Armadilhas comuns
- Estimar o tamanho de uma struct somando os campos (esquecendo o padding interno e o do fim).
- Enviar uma struct "crua" por UART/rádio entre CPUs diferentes: padding, tamanho do enum e endianness podem não bater.
- Comparar structs com `memcmp` (os bytes de padding têm valor qualquer).
- Usar `packed` à toa e cair em acessos desalinhados.
- Passar structs grandes por valor (cópia na pilha) quando um ponteiro `const` bastaria.
- Esquecer que campos não citados num inicializador designado viram zero (às vezes é o que você quer; às vezes esconde um campo esquecido).
- Supor que todo processador é little-endian, ou usar a union para conversão de bytes em C++.
- `switch` sobre enum sem tratar todos os valores nem ter `default`.

## Gabarito
1. `void imprime(const leitura_t *l) { printf("%u ms: %d.%d C\n", (unsigned)l->t_ms, l->temp_dC / 10, l->temp_dC % 10); }` (cuidado com temperaturas negativas no `% 10`).
2. Só `ajusta_p`: `ajusta` recebe uma cópia.
3. `ruim`: 12 bytes (a@0, b@4, c@8); `boa`: 8 bytes (b@0, a@4, c@5).
4. 24 bytes (tipo@0, valor@8, id@16, padding até 24). Reordenado (`double`, `uint16_t`, `char`): 16 bytes.
5. 80 bytes (cada struct tem 8: 5 de dados + 3 de padding no fim).
6. 8 e 5.
7. `44 33 22 11`.
8. `uint16_t x = 1; return *(uint8_t *)&x == 1;` (acessar qualquer objeto como bytes por `uint8_t *`/`unsigned char *` é permitido).
9. `buf[0] = v >> 8; buf[1] = v & 0xFF;` → `{0x12, 0x34}`; `de_be16` → `(buf[0] << 8) | buf[1]` = 0x1234.
10. 0, 1, 2, 10, 11.
11. DESLIGADO (PRONTO é ignorado), LIGANDO, FALHA, DESLIGADO, LIGANDO, LIGADO.
12. `warning: enumeration value 'FALHA' not handled in switch [-Wswitch]` — mas só se **não** houver `default` (o `default` silencia o aviso; o `-Wswitch-enum` avisa mesmo com `default`).

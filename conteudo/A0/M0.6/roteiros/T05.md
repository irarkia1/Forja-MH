# M0.6.T05 — Operações bit a bit e máscaras

## Ao final você consegue
- Calcular o resultado de &, |, ^, ~, << e >> em binário e hexadecimal.
- Ligar, desligar, inverter e testar bits de um registrador com máscaras (x |= 1u << n, x &= ~(1u << n)).
- Extrair e escrever campos de vários bits num registrador com deslocamento e máscara (read-modify-write).
- Evitar as armadilhas de deslocamento (largura, sinal, promoção) e justificar por que não usar bitfields para mapear registradores.

## Resumo
**1. Binário e hexadecimal.** Cada dígito hexadecimal são 4 bits: `0xA5` = `1010 0101`. Decore 0–F em binário (8 = 1000, A = 1010, C = 1100, F = 1111). O bit *n* vale 2ⁿ; o bit 0 é o menos significativo. `printf("%02X", v)` imprime 2 dígitos hexadecimais; o gcc aceita literais `0b1010` (extensão; padrão a partir do C23).

**2. Os operadores.**

| Operador | Efeito | Exemplo (8 bits) |
|---|---|---|
| `a & b` | E: 1 só onde os dois são 1 | `0xA5 & 0x0F` = `0x05` |
| `a \| b` | OU: 1 onde algum é 1 | `0xA5 \| 0x0F` = `0xAF` |
| `a ^ b` | OU exclusivo: 1 onde são diferentes | `0xA5 ^ 0xFF` = `0x5A` |
| `~a` | inverte todos os bits | `~0x0F` = `0xF0` (em 8 bits — veja a armadilha da promoção) |
| `a << n` | desloca à esquerda (× 2ⁿ), entra 0 | `0x03 << 4` = `0x30` |
| `a >> n` | desloca à direita (÷ 2ⁿ) | `0xA5 >> 4` = `0x0A` |

Não confunda `&` (bit a bit) com `&&` (lógico: resultado 0 ou 1): `6 & 3` = 2, `6 && 3` = 1. **Precedência**: `==` e `!=` vêm **antes** de `&`, `^` e `|`. `reg & 0x80 == 0x80` é lido como `reg & (0x80 == 0x80)` = `reg & 1`. Use parênteses sempre (o `-Wall` avisa).

**3. As quatro operações básicas** (bit `n` do registrador `reg`):
```c
reg |=  (1u << n);          /* liga    (set)    */
reg &= ~(1u << n);          /* desliga (clear)  */
reg ^=  (1u << n);          /* inverte (toggle) */
if (reg & (1u << n)) { }    /* testa: diferente de zero se o bit está em 1 */
bool on = (reg >> n) & 1u;  /* lê o bit como 0 ou 1 */
```
Dê nome às máscaras: `#define LED_VERDE (1u << 5)` e depois `GPIOA_ODR |= LED_VERDE;`.

**4. Campos de vários bits.** Registradores juntam campos: no STM32, `GPIOx_MODER` tem **2 bits por pino** (00 entrada, 01 saída, 10 função alternativa, 11 analógico); o pino *p* ocupa os bits `2p` e `2p+1`.
```c
#define CAMPO_POS  4u
#define CAMPO_MSK  (0x7u << CAMPO_POS)                     /* bits 4..6 */

uint32_t valor = (reg & CAMPO_MSK) >> CAMPO_POS;           /* ler       */
reg = (reg & ~CAMPO_MSK) | ((novo << CAMPO_POS) & CAMPO_MSK);  /* escrever: read-modify-write */
```
Para escrever um campo, **primeiro zere** os bits do campo e **depois** faça o OU com o valor novo. Só fazer `reg |= (1u << 10)` para colocar o pino 5 em modo saída (01) falha se o campo já valia 10 ou 11. É exatamente assim que a CMSIS e os cabeçalhos dos fabricantes trabalham (`GPIO_MODER_MODER5_Pos`, `GPIO_MODER_MODER5_Msk`).

**Read-modify-write e interrupções**: `reg |= m` é ler, modificar e escrever. Se uma interrupção alterar o mesmo registrador no meio, a alteração dela se perde. Por isso há registradores de *set/reset* atômicos: no STM32, escrever `1u << n` em `GPIOx_BSRR` liga o pino *n*, e `1u << (n + 16)` o desliga, sem ler nada.

**5. Armadilhas.**
- **Promoção**: operandos menores que `int` viram `int` antes da operação. Com `uint8_t x = 0x0F;`, `~x` vale `0xFFFFFFF0` (o `int` −16), e `~x == 0xF0` é **falso**. Converta de volta: `(uint8_t)~x == 0xF0`. O mesmo vale para `x << 4`, que pode ultrapassar 8 bits.
- **Largura do deslocamento**: deslocar por um valor ≥ à largura do tipo (já promovido) é **UB**. No AVR, `int` tem 16 bits: `1 << 20` é UB e `1u << 20` também; use `1UL << 20` ou `(uint32_t)1 << 20`. Num STM32, `1 << 31` com `int` de 32 bits é UB em C (o resultado não cabe no `int`); `1u << 31` é correto. Regra: **máscaras sempre sem sinal**, com sufixo `u`/`UL`.
- **Sinal**: `>>` num número negativo é definido pela implementação (o gcc replica o bit de sinal); `<<` num negativo é UB. Trabalhe com tipos sem sinal.
- Truques úteis (com sem sinal): `x & (x - 1)` apaga o bit 1 mais baixo (zero ⇒ `x` é potência de 2, se `x ≠ 0`); `x & -x` isola o bit 1 mais baixo; `__builtin_popcount(x)` conta bits (extensão do gcc).

**6. Bitfields — e por que não usá-los em registradores.**
```c
struct status {
    unsigned pronto : 1;
    unsigned erro   : 1;
    unsigned modo   : 3;
};
```
Parecem perfeitos para registradores, mas a norma deixa **definido pela implementação**: a ordem dos bits (do menos ou do mais significativo primeiro), se um campo pode atravessar a fronteira de uma unidade, o alinhamento e o tipo da unidade de armazenamento — e o compilador pode acessar o registrador com uma largura diferente da exigida (um acesso de 8 bits num registrador que só aceita 32), além de fazer read-modify-write escondido em registradores com bits "escreva 1 para limpar". O resultado muda de compilador para compilador. Bitfields são aceitáveis para economizar memória em dados internos; para registradores e formatos de protocolo, use **máscaras e deslocamentos**, cujo resultado é definido pela norma.

## Pratique
Use `~/treino-c/t05/`. Faça cada conta **à mão** antes de rodar.
1. Converta para binário e hexadecimal: 5, 10, 15, 16, 100, 200, 255. E de volta: `0x3C`, `0xA5`, `0x80`, `0x7F`.
2. Calcule em hexadecimal: `0xA5 & 0x0F`, `0xA5 | 0x0F`, `0xA5 ^ 0xFF`, `0xA5 >> 4`, `0x03 << 4`, `(uint8_t)~0x3C`.
3. Escreva as macros `BIT_SET(reg, n)`, `BIT_CLR(reg, n)`, `BIT_TGL(reg, n)` e `BIT_GET(reg, n)` (com parênteses corretos — T06) e teste-as num `uint8_t`.
4. Escreva `void imprime_bin(uint32_t v, int bits)` que imprime os bits do mais para o menos significativo.
5. Escreva `int conta_bits(uint32_t v)` de duas formas: testando cada bit e com o truque `v &= v - 1`. Compare com `__builtin_popcount`.
6. Com `uint8_t reg = 0xB5;`, extraia o campo dos bits 4..6 e depois escreva 5 nesse campo, sem alterar os outros bits. Imprima em binário.
7. Simule o `MODER` do STM32 num `uint32_t moder = 0xA8000000;` (valor de reset do GPIOA no STM32F4) e coloque os pinos 5 e 6 em modo saída (01).
8. Simule o `BSRR`: escreva `uint32_t bsrr_liga(int pino)` e `bsrr_desliga(int pino)` que devolvem o valor a escrever.
9. Com `uint8_t x = 0x0F;`, imprima `~x` com `%X` e compare `~x == 0xF0` com `(uint8_t)~x == 0xF0`.
10. Compile `uint32_t m = 1 << 31;` e `int s = -8 >> 1;` com `-fsanitize=undefined` e rode. O que o UBSan diz de cada um?
11. Declare a `struct status` com bitfields, ponha `pronto = 1` e `modo = 5`, e examine o byte com `x/1tb &s` no GDB. Em que bits ficou cada campo?
12. Escreva `bool potencia_de_2(uint32_t x)`.

## Armadilhas comuns
- Confundir `&` com `&&` ou `|` com `||`.
- `reg & MASK == MASK` sem parênteses (precedência).
- `reg = 1u << n` (apaga todos os outros bits) quando a intenção era `reg |= 1u << n`.
- Escrever um campo só com `|=`, sem zerar os bits antes.
- Máscara com sinal (`1 << 31`) ou estreita demais para o AVR (`1 << 20` com `int` de 16 bits).
- Comparar `~x` de um `uint8_t` com uma constante de 8 bits (promoção para `int`).
- Deslocar por uma quantidade negativa ou ≥ à largura do tipo.
- Mapear registradores com bitfields.
- Esquecer que `reg |= m` é read-modify-write e pode ser interrompido.

## Gabarito
1. 5 = `0101` = 0x05; 10 = 0x0A; 15 = 0x0F; 16 = `0001 0000` = 0x10; 100 = `0110 0100` = 0x64; 200 = `1100 1000` = 0xC8; 255 = 0xFF. `0x3C` = 60, `0xA5` = 165, `0x80` = 128, `0x7F` = 127.
2. `0x05`, `0xAF`, `0x5A`, `0x0A`, `0x30`, `0xC3`.
3. `#define BIT_SET(reg, n) ((reg) |= (1u << (n)))`, `BIT_CLR` com `&= ~(1u << (n))`, `BIT_TGL` com `^=`, `#define BIT_GET(reg, n) (((reg) >> (n)) & 1u)`.
4. `for (int i = bits - 1; i >= 0; i--) putchar((v >> i) & 1u ? '1' : '0');`.
5. `while (v) { v &= v - 1; n++; }` — cada volta apaga um bit 1.
6. `(reg >> 4) & 0x7` = 3 (`011`); depois de escrever 5: `(0xB5 & ~0x70) | (5u << 4)` = `0x85 | 0x50` = `0xD5` = `1101 0101`.
7. `moder = (moder & ~((3u << 10) | (3u << 12))) | (1u << 10) | (1u << 12);` → `0xA8001400`.
8. `return 1u << pino;` e `return 1u << (pino + 16);`.
9. `~x` = `FFFFFFF0`; a primeira comparação é falsa e a segunda verdadeira.
10. `1 << 31`: `left shift of 1 by 31 places cannot be represented in type 'int'`. `-8 >> 1` não é UB (é definido pela implementação: o gcc dá −4) e o UBSan não reclama.
11. No x86-64 com gcc, `pronto` no bit 0, `erro` no bit 1, `modo` nos bits 2..4: o byte vale `00010101`. Outro compilador poderia fazer diferente — é o argumento contra bitfields em registradores.
12. `return x != 0 && (x & (x - 1)) == 0;`.

# M0.6.T06 — Pré-processador, compilação e link

## Ao final você consegue
- Descrever as etapas de pré-processamento, compilação, montagem e link e gerar a saída de cada uma com gcc (-E, -S, -c).
- Escrever macros com parênteses corretos, include guards e compilação condicional, e escolher entre macro, função inline e constante.
- Organizar um programa em várias unidades de tradução com .h e .c, controlando linkage com static e extern.
- Interpretar erros do linker (undefined reference, multiple definition) e escolher flags de compilação (-Wall -Wextra -Werror -O2 -g -fsanitize).

## Resumo
**1. As quatro etapas.** `gcc` é um "maestro" que chama outros programas:
```
sensor.c ──(pré-processador, cpp)──▶ sensor.i ──(compilador, cc1)──▶ sensor.s ──(montador, as)──▶ sensor.o ─┐
main.c   ─────────────────────────────────────────────────────────────────────────────────────▶ main.o ───┼─(linker, ld)──▶ app
                                                                                   libm.a / libc ──────────┘
```
| Etapa | Faz | Para ver |
|---|---|---|
| Pré-processamento | troca `#include` pelo conteúdo do arquivo, expande macros, resolve `#if`, remove comentários | `gcc -E sensor.c -o sensor.i` |
| Compilação | analisa o C (sintaxe, tipos), otimiza e gera assembly | `gcc -S sensor.c` → `sensor.s` |
| Montagem | traduz assembly em código de máquina: **arquivo objeto** com seções e tabela de símbolos | `gcc -c sensor.c` → `sensor.o` |
| Link | junta os `.o` e as bibliotecas, **resolve** cada símbolo usado num arquivo e definido em outro, decide os endereços finais e acrescenta o código de partida | `gcc main.o sensor.o -o app` |

`gcc -save-temps` deixa os arquivos intermediários. `nm sensor.o` lista os símbolos: `T` função definida aqui, `D`/`B` variável definida em `.data`/`.bss`, `U` usada aqui e **não definida** (o linker precisa achá-la em outro lugar); letra minúscula (`t`, `d`, `b`) = símbolo local (`static`). `objdump -d sensor.o` desmonta o código. Num microcontrolador, o linker usa um *linker script* que diz onde ficam a flash e a RAM, e gera o mapa de memória (`-Wl,-Map=app.map`).

**2. Unidades de tradução e headers.** Cada `.c`, com tudo o que ele inclui, é compilado **sozinho** — o compilador não enxerga os outros `.c`. Por isso existem os headers: o `.h` é a **interface** (o que outros arquivos podem usar), o `.c` é a **implementação**.
```c
/* sensor.h */
#ifndef SENSOR_H            /* include guard: se já foi incluído nesta unidade, pula tudo */
#define SENSOR_H
#include <stdint.h>

#define SENSOR_CANAIS 4u
typedef struct { uint16_t bruto[SENSOR_CANAIS]; } sensor_leitura_t;

void     sensor_inicia(void);
int      sensor_le(sensor_leitura_t *saida);   /* protótipos: declarações */
extern uint32_t sensor_erros;                  /* declaração de variável (não reserva memória) */
#endif

/* sensor.c */
#include "sensor.h"         /* inclua o próprio .h: o compilador confere protótipo × definição */
uint32_t sensor_erros = 0;  /* a ÚNICA definição */
static uint8_t canal_atual; /* privada deste arquivo */
static int le_canal(uint8_t c) { ... }   /* função privada */
```
**Declaração** diz que algo existe e qual é o tipo; **definição** reserva memória (variável) ou fornece o corpo (função). Pode haver várias declarações, mas só **uma definição** de cada objeto ou função no programa inteiro.
- Nunca **defina** variáveis num `.h` (`int erros = 0;` ou mesmo `int erros;`): cada `.c` que o inclui ganha uma definição e o linker acusa *multiple definition*. O include guard **não** resolve isso — ele só evita a repetição dentro da mesma unidade de tradução.
- `static` no escopo de arquivo dá **linkage interna**: o nome só existe naquele `.c`. Dois arquivos podem ter cada um o seu `static int contador;` sem conflito. Em firmware, tudo o que não está no `.h` deve ser `static`.
- `extern` declara um objeto definido em outro lugar (linkage externa). Funções já têm linkage externa por padrão.
- `#include "x.h"` procura primeiro na pasta do arquivo; `#include <x.h>` só nas pastas do sistema e nas passadas com `-I`.

**3. Macros.** O pré-processador faz substituição de **texto**, sem saber nada de C.
```c
#define QUAD_RUIM(x) x * x           /* QUAD_RUIM(1 + 2) → 1 + 2 * 1 + 2 = 5          */
#define QUAD(x)      ((x) * (x))     /* QUAD(1 + 2) → ((1 + 2) * (1 + 2)) = 9          */
#define MAX(a, b)    ((a) > (b) ? (a) : (b))   /* MAX(i++, j) incrementa i duas vezes */
#define LED_LIGA()   do { GPIOA_ODR |= LED; contador++; } while (0)   /* várias instruções */
```
Regras: parênteses em **cada** parâmetro e na expressão inteira; `do { … } while (0)` para macros com várias instruções (funcionam dentro de `if` sem chaves); nunca passe argumentos com efeito colateral (`i++`, chamadas de função). Recursos: `#x` vira a string `"x"`, `a##b` cola tokens, `__FILE__` e `__LINE__` dão o arquivo e a linha (úteis em `assert` e logs).

**Macro × inline × constante.** Prefira:
- **constantes**: `enum { TAM_BUF = 64 };` (serve para tamanho de array e `case`) ou `static const uint32_t BAUD = 115200u;` (tem tipo, aparece no GDB); `#define` com sufixo e parênteses quando precisar no pré-processador (`#if`);
- **funções `static inline`** no `.h` em vez de macros com parâmetros: têm verificação de tipos, avaliam cada argumento uma vez, aparecem no depurador e, com otimização, custam o mesmo que a macro;
- **macros** só para o que só o pré-processador faz: compilação condicional, `__FILE__`/`__LINE__`, `#`/`##`.

**4. Compilação condicional.**
```c
#ifdef DEBUG
#  define LOG(msg) printf("%s:%d %s\n", __FILE__, __LINE__, msg)
#else
#  define LOG(msg) do { } while (0)
#endif

#if SENSOR_CANAIS > 8
#  error "o ADC só tem 8 canais"
#endif
```
`gcc -DDEBUG` define `DEBUG` na linha de comando; `-DNDEBUG` desliga os `assert`. É assim que o mesmo código compila para placas diferentes (`-DPLACA_V2`).

**5. Erros do linker.** Eles aparecem depois que todos os arquivos compilaram; vêm do `ld` (`collect2: error: ld returned 1 exit status`).
- `undefined reference to 'sensor_le'`: algum `.o` usa o símbolo e ninguém o define. Causas: esqueceu `sensor.c` no comando; nome digitado diferente na definição; função declarada `static` em outro arquivo; falta uma biblioteca (`sqrt` → `-lm`, sempre **depois** dos arquivos que a usam).
- `multiple definition of 'erros'`: duas unidades definem o mesmo símbolo (variável definida no `.h`, função não-`static` com o mesmo nome em dois `.c`). Desde o GCC 10 (`-fno-common` por padrão), até `int erros;` repetido em dois arquivos dá esse erro.
- Bibliotecas estáticas: `ar rcs libsensor.a sensor.o filtro.o`; uso: `gcc main.o -L. -lsensor -o app`.

**6. Flags que você vai usar sempre.**

| Flag | Para quê |
|---|---|
| `-std=c11` (ou `c17`) | fixa a versão da linguagem |
| `-Wall -Wextra` | liga os avisos mais úteis; `-Wpedantic` cobra o C padrão; `-Wshadow`, `-Wconversion` são boas adições |
| `-Werror` | todo aviso vira erro (não deixa avisos se acumularem) |
| `-O0` / `-Og` / `-O2` / `-Os` | sem otimização / para depurar / velocidade / **tamanho** (comum em MCU) |
| `-g` | informação de depuração (não muda o código gerado; só ocupa espaço no arquivo) |
| `-fsanitize=address,undefined` | detecta erros de memória e UB em tempo de execução — **só no PC** |
| `-I inc/`, `-D NOME=valor` | pastas de headers e macros pela linha de comando |
| `-ffunction-sections -fdata-sections -Wl,--gc-sections` | cada função numa seção; o linker descarta as não usadas (firmware menor) |
| `-MMD -MP` | gera arquivos `.d` com as dependências de headers (T07) |

## Pratique
Use `~/treino-c/t06/`.
1. Com um `ola.c`, gere `ola.i`, `ola.s`, `ola.o` e `ola` com `-E`, `-S`, `-c` e o link. Quantas linhas tem o `.i`? Por quê?
2. Rode `nm` no `.o` e no executável. Onde aparece `printf`? Com que letra?
3. Divida um programa em `main.c`, `sensor.c` e `sensor.h` (com include guard). Compile cada `.c` com `-c` e ligue os `.o`.
4. Compile só `gcc main.c -o app` (sem `sensor.c`) e leia o erro. Depois defina `int erros = 0;` no `sensor.h` e veja o novo erro.
5. Crie `static int contador;` em dois arquivos diferentes, cada um com uma função que o incrementa. Os dois são a mesma variável? Confira com `nm`.
6. Teste `QUAD_RUIM(1 + 2)` e `QUAD(1 + 2)`; depois `MAX(i++, j)` com `i = 5`, `j = 3`. Olhe a expansão com `gcc -E`.
7. Reescreva `QUAD` e `MAX` como funções `static inline` e repita o teste com `i++`.
8. Escreva a macro `LOG` acima e compile com e sem `-DDEBUG`.
9. Use `#if` e `#error` para impedir a compilação se `SENSOR_CANAIS` passar de 8.
10. Compile um programa com `sqrt` sem `-lm` e com `-lm`.
11. Crie `libsensor.a` com `ar` e ligue o `main.c` com ela.
12. Compare `size` do mesmo programa com `-O0`, `-O2` e `-Os`. Depois acrescente `-ffunction-sections -fdata-sections -Wl,--gc-sections` com uma função que nunca é chamada.

## Armadilhas comuns
- Definir variáveis (ou funções não `inline`) em headers.
- Achar que o include guard evita *multiple definition* entre arquivos diferentes.
- Esquecer `static` em funções e variáveis internas (poluem o espaço de nomes global e colidem).
- Macro sem parênteses; macro com `;` no fim da definição; argumentos com efeito colateral.
- `#define TAMANHO 10;` (com ponto e vírgula) — vira `int v[10;];`.
- Esquecer um `.c` no comando de link, ou pôr `-lm` antes dos arquivos.
- Ler só o último erro: o primeiro erro de compilação costuma causar os seguintes.
- Distribuir firmware compilado com `-fsanitize` (não funciona no MCU) ou depurar em `-O2` sem saber.
- Não incluir o próprio `.h` no `.c`: o compilador deixa de conferir se o protótipo bate com a definição.

## Gabarito
1. O `.i` tem centenas de linhas: o `#include <stdio.h>` foi substituído pelo conteúdo do header (e dos que ele inclui).
2. No `.o`: `U printf` (indefinido; vem da libc). No executável: `U printf@GLIBC_…` (ligação dinâmica, resolvida ao carregar o programa).
3. `gcc -c main.c`, `gcc -c sensor.c`, `gcc main.o sensor.o -o app`.
4. `undefined reference to 'sensor_le'`; depois, `multiple definition of 'erros'`.
5. Não: são duas variáveis independentes, cada uma marcada com `b` ou `d` minúsculo (local) no `nm`.
6. 5 e 9. `MAX(i++, j)` → `((i++) > (j) ? (i++) : (j))`: devolve 6 e deixa `i` = 7.
7. Com funções, `i++` é avaliado uma vez: resultado 5 e `i` = 6.
8. Sem `-DDEBUG`, `LOG` some (vira um `do { } while (0)` vazio).
9. `#if SENSOR_CANAIS > 8` / `#error "…"` / `#endif`.
10. Sem `-lm`: `undefined reference to 'sqrt'`. Com `gcc m.c -o m -lm`, liga.
11. `gcc -c sensor.c && ar rcs libsensor.a sensor.o && gcc main.c -L. -lsensor -o app`.
12. Em geral `-Os` dá o menor `text` e `-O0` um dos maiores (em programas muito pequenos a diferença é de poucos bytes, porque a maior parte é código de partida); com `--gc-sections`, a função não usada sai do executável (confira com `nm`).

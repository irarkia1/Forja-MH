## Resumo
**1. Do arquivo ao executável.** No Ubuntu: `sudo apt install build-essential gdb`. Um programa mínimo:
```c
#include <stdio.h>

int main(void)
{
    printf("Ola, forja!\n");
    return 0;               /* 0 = sucesso para o shell ($?) */
}
```
```bash
gcc -std=c11 -Wall -Wextra -g ola.c -o ola   # -o dá o nome; sem ele sai a.out
./ola
echo $?                                      # código de retorno do main
```
**Erro** (*error*) impede a geração do executável; **aviso** (*warning*) não impede, mas quase sempre aponta um defeito real. Trate avisos como erros desde o primeiro dia (no T06 você liga `-Werror`). Leia a **primeira** mensagem: ela traz `arquivo:linha:coluna`, e os erros seguintes costumam ser consequência dela.

**2. Tipos inteiros e por que `<stdint.h>`.** O C só garante tamanhos **mínimos**: `char` ≥ 8 bits, `short` e `int` ≥ 16, `long` ≥ 32, `long long` ≥ 64. Na prática, `int` tem **16 bits no AVR** (Arduino Uno) e 32 bits no STM32, no ESP32 e no seu PC. Por isso, em firmware, use os tipos de largura fixa:

| Tipo | Bits | Faixa |
|---|---|---|
| `uint8_t` / `int8_t` | 8 | 0…255 / −128…127 |
| `uint16_t` / `int16_t` | 16 | 0…65 535 / −32 768…32 767 |
| `uint32_t` / `int32_t` | 32 | 0…4 294 967 295 / ≈ ±2,1·10⁹ |
| `size_t` | (plataforma) | tamanhos e índices; resultado de `sizeof` |

O sinal do `char` "puro" depende da plataforma (com sinal no x86, sem sinal no ARM): use `char` só para texto e `uint8_t`/`int8_t` para números. Para imprimir: `%d` (int), `%u` (unsigned), `%ld`, `%zu` (size_t), `%x` (hexadecimal), `%f` (double); para `uint32_t` portável, `printf("%" PRIu32 "\n", v)` com `<inttypes.h>`. Constantes: `10` é `int`, `10u` é `unsigned`, `10UL` é `unsigned long`, `0x1F` é hexadecimal, `'A'` é um `int` com o código 65.

**3. Aritmética que engana.**
- **Divisão inteira trunca em direção ao zero**: `7 / 2` → 3, `-7 / 2` → −3, `-7 % 2` → −1 (o resto tem o sinal do dividendo). `1 / 2` → 0, mas `1.0 / 2` → 0.5.
- **Promoção de inteiros**: em qualquer conta, tipos menores que `int` (`uint8_t`, `int16_t`, `char`…) viram `int` antes. `uint8_t a = 200, b = 100;` → `a + b` vale **300** (um `int`); só ao guardar em `uint8_t` o valor é reduzido módulo 256 → 44.
- **Conversões usuais**: se um operando é `unsigned int` e o outro `int`, o `int` é convertido para `unsigned`. Logo `-1 < 1u` é **falso**: −1 vira 4 294 967 295. O `-Wextra` avisa (`-Wsign-compare`).
- **Conversão para tipo sem sinal é sempre definida** (módulo 2ⁿ): `(uint8_t)300` → 44, `(uint8_t)-1` → 255. Conversão de um valor fora da faixa para tipo **com** sinal é definida pela implementação.
- `x = x + 1` com `float` não tem "estouro" silencioso de inteiro, mas tem arredondamento: em MCU sem FPU (AVR, Cortex-M0), `float` é emulado em software e custa caro.

**4. Estouro: sem sinal × com sinal.**
```c
uint8_t  u = 255;  u = u + 1;   /* definido: 0 (aritmética módulo 256)           */
uint32_t t = 0;    t = t - 1;   /* definido: 4294967295                           */
int32_t  s = INT32_MAX; s = s + 1; /* COMPORTAMENTO INDEFINIDO (UB)               */
```
Estouro de inteiro **sem sinal** é definido pela norma: o resultado "dá a volta". Estouro de inteiro **com sinal** é *undefined behavior* (UB): a norma não diz nada sobre o que acontece, e o otimizador pode assumir que nunca ocorre (ex.: transformar `if (x + 1 > x)` em `if (1)`). A volta do sem sinal é útil em firmware: com um contador de milissegundos `uint32_t`, `agora - antes` dá o intervalo certo mesmo depois que o contador volta a zero.

**5. Controle de fluxo.**
```c
for (int i = 0; i < 10; i++) { ... }    /* i só existe dentro do laço (C99+) */
while (cond) { ... }                    /* testa antes: pode executar 0 vezes  */
do { ... } while (cond);                /* testa depois: executa pelo menos 1  */
```
`break` sai do laço (ou do `switch`) mais interno; `continue` pula para a próxima volta (no `for`, executa o incremento). No `switch`, cada `case` **continua no seguinte** até um `break` (*fall-through*): esquecer o `break` é um defeito clássico — o `-Wextra` avisa (`-Wimplicit-fallthrough`). Sempre ponha um `default`. Em C, qualquer valor diferente de zero é verdadeiro; `if (x = 5)` **atribui** 5 e é sempre verdadeiro (o `-Wall` avisa: *suggest parentheses around assignment used as truth value*). Operadores lógicos `&&` e `||` param na primeira resposta (curto-circuito).

**6. Funções.**
```c
#include <stdint.h>

uint16_t media(uint16_t a, uint16_t b);        /* protótipo: vem antes do uso */

int main(void) { return media(10, 20) == 15 ? 0 : 1; }

uint16_t media(uint16_t a, uint16_t b)
{
    return (uint16_t)(((uint32_t)a + b) / 2u);  /* soma em 32 bits: não estoura */
}
```
- **Passagem por valor**: a função recebe uma **cópia** do argumento; alterar o parâmetro não altera a variável de quem chamou (para isso, ponteiros — T02).
- `int f(void)` declara "sem parâmetros"; `int f()` em C (antes do C23) significa "parâmetros não especificados" — prefira `(void)`.
- Chamar uma função sem declaração prévia é erro no C99+ (o GCC 14 recusa por padrão). Protótipos ficam nos arquivos `.h` (T06).
- Variável local sem inicialização tem valor **indeterminado**: lê-la antes de atribuir é um defeito (o GDB do T09 mostra "lixo"; `-Wall` às vezes avisa com `-Wmaybe-uninitialized` quando há otimização).

## Pratique
Crie `~/treino-c/t01/` com um `.gitignore` (executáveis e `*.o`). Compile sempre com `gcc -std=c11 -Wall -Wextra -g`.
1. Escreva, compile e rode o "Olá". Depois apague o `;` do `printf` e leia a mensagem de erro. Depois troque `return 0` por `return 3` e confira com `echo $?`.
2. Imprima `sizeof` de `char`, `short`, `int`, `long`, `long long`, `float`, `double`, `size_t` e `void *` no seu PC (use `%zu`).
3. Preveja e depois confira: `7 / 2`, `-7 / 2`, `7 % 3`, `-7 % 3`, `1 / 2 * 4`, `1.0 / 2 * 4`.
4. Com `uint8_t a = 200, b = 100;`, imprima `a + b` (com `%d`) e depois `(uint8_t)(a + b)`. Explique a diferença.
5. Preveja: `int a = -1; unsigned b = 1; printf("%d\n", a < b);`. Compile com e sem `-Wextra` e compare os avisos.
6. Escreva `uint32_t intervalo(uint32_t agora, uint32_t antes)` e teste com `agora = 5`, `antes = 4294967290`.
7. Escreva um programa que conta de 1 a 20 e imprime "Fizz" para múltiplos de 3, "Buzz" de 5, "FizzBuzz" dos dois.
8. Escreva um `switch` que traduz um código de erro (0–3) em texto; esqueça um `break` de propósito e veja o aviso do `-Wextra`.
9. Escreva `int clamp(int v, int min, int max)` e teste com valores abaixo, dentro e acima da faixa.
10. Escreva `void troca(int a, int b)` que tenta trocar os valores e mostre, com `printf` dentro e fora dela, por que não funciona.
11. Calcule a média de `uint16_t a = 60000, b = 60000` somando em `uint16_t` e depois em `uint32_t`. Qual está certa?
12. (K&R, exercício 1-15) Reescreva o conversor de temperatura Fahrenheit–Celsius usando uma função.

## Armadilhas comuns
- Usar `int` achando que ele tem 32 bits — no AVR são 16, e `int x = 40000;` não cabe.
- Esperar `0.5` de `1 / 2` (divisão inteira) ou esquecer que `-7 / 2` é −3, não −4 (C trunca em direção a zero; o Python arredonda para baixo).
- Comparar `int` com `unsigned`: `-1 < 1u` é falso.
- Achar que `uint8_t a + b` estoura em 8 bits durante a conta — a promoção para `int` faz a conta em pelo menos 16 bits; a redução acontece só na atribuição.
- Confiar que estouro com sinal "dá a volta": é UB, e o otimizador pode remover seus testes.
- `if (x = 5)` no lugar de `if (x == 5)`; `switch` sem `break`; `;` logo depois do `if (...)` ou do `for (...)`.
- Ignorar avisos porque "o executável saiu".
- `printf` com especificador errado (`%d` para `size_t`, `%u` para `uint64_t`).

## Gabarito
1. Sem `;`: `ola.c:5:28: error: expected ';' before 'return'` — o gcc aponta o fim do `printf` e diz que encontrou o `return` onde esperava o `;` (em outros erros, a linha indicada pode ser a seguinte à do defeito: olhe também a linha anterior). `echo $?` mostra 3.
2. No x86-64 Linux: 1, 2, 4, 8, 8, 4, 8, 8, 8.
3. 3, −3, 1, −1, 0 (1 / 2 = 0, vezes 4 = 0), 2.0.
4. `a + b` = 300 (promoção para `int`); `(uint8_t)(a + b)` = 44 (300 − 256).
5. Imprime 0: `a` é convertido para `unsigned` (4294967295), que não é menor que 1. Só com `-Wextra` aparece `comparison of integer expressions of different signedness`.
6. `return agora - antes;` → 11 (a subtração sem sinal dá a volta módulo 2³²).
7. Teste `i % 15 == 0` primeiro (ou teste 3 e 5 juntos), senão o "FizzBuzz" nunca aparece.
8. `warning: this statement may fall through [-Wimplicit-fallthrough=]`.
9. `if (v < min) return min; if (v > max) return max; return v;`.
10. Dentro, os valores aparecem trocados; fora, não mudam: a função trocou as cópias. A solução (ponteiros) está no T02.
11. Em `uint16_t`: 60000 + 60000 = 120000, reduzido a 54464, dividido por 2 → 27232 (errado). Em `uint32_t`: 60000 (certo). Repare que `a + b` em si é feito em `int` (32 bits no PC); o erro aparece quando você guarda a soma numa variável `uint16_t` antes de dividir — ou no AVR, onde `int` tem 16 bits.
12. `float celsius(float f) { return (5.0f / 9.0f) * (f - 32.0f); }` — cuidado com `5 / 9`, que dá 0.

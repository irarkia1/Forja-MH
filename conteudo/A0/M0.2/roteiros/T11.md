# M0.2.T11 — Sistemas de numeração (binário, hexadecimal, complemento de 2)

- Converter números inteiros e frações simples entre decimal, binário, octal e hexadecimal.

## Resumo
**1. Sistema posicional.** Num número na base b, cada dígito vale *dígito × bᵖᵒˢⁱçãᵒ*, com posição 0 à direita. Decimal: 347 = 3·10² + 4·10¹ + 7·10⁰. Binário (base 2, dígitos 0 e 1): 1011₂ = 8 + 0 + 2 + 1 = **11**. Hexadecimal (base 16, dígitos 0–9 e A–F, A = 10 … F = 15): 0x2F = 2·16 + 15 = **47**.

Pesos binários que você deve saber de cor: 1, 2, 4, 8, 16, 32, 64, 128, 256, 512, 1024 (2¹⁰ ≈ 10³), 4096 (2¹²), 65 536 (2¹⁶).

**2. Conversões.**
- **Binário → decimal:** some os pesos dos bits em 1. 1011 0110₂ = 128 + 32 + 16 + 4 + 2 = **182**.
- **Decimal → binário:** divisões sucessivas por 2; os restos, lidos **de baixo para cima**, são os bits. 45: 45/2 = 22 r1; 22/2 = 11 r0; 11/2 = 5 r1; 5/2 = 2 r1; 2/2 = 1 r0; 1/2 = 0 r1 ⇒ **101101₂**. Alternativa: subtraia o maior peso que cabe (45 − 32 = 13; 13 − 8 = 5; 5 − 4 = 1; 1 − 1 = 0 ⇒ bits 32, 8, 4, 1).
- **Binário ↔ hexadecimal:** cada dígito hex é exatamente **4 bits** (um *nibble*). Agrupe da direita: 1011 0110₂ = **0xB6**; 0x3C = 0011 1100₂. É por isso que registradores são escritos em hex.
- **Octal** (base 8): grupos de 3 bits. 101 101₂ = 55₈ = 45. Aparece em permissões do Linux (`chmod 755`, M0.7).
- **Hex → decimal:** 0x2A7 = 2·256 + 10·16 + 7 = **679**.

**3. Frações binárias.** À direita da vírgula, os pesos são 2⁻¹ = 0,5; 2⁻² = 0,25; 2⁻³ = 0,125; 2⁻⁴ = 0,0625. 101,011₂ = 4 + 1 + 0,25 + 0,125 = **5,375**. Para converter 0,625 para binário, multiplique por 2 sucessivamente e anote a parte inteira: 0,625 × 2 = **1**,25; 0,25 × 2 = **0**,5; 0,5 × 2 = **1**,0 ⇒ 0,101₂. Já 0,1 decimal **não tem representação binária finita** (0,000110011…₂) — é por isso que `0.1 + 0.2 != 0.3` em `float`.

**4. Sem sinal.** n bits representam 0 … 2ⁿ − 1: `uint8_t` 0…255; `uint16_t` 0…65 535; `uint32_t` 0…4 294 967 295.

**5. Complemento de 2.** É como o processador guarda inteiros com sinal. Num número de n bits, o bit mais significativo (MSB) tem **peso negativo**, −2ⁿ⁻¹:

> valor = −b₇·128 + b₆·64 + … + b₀·1   (para 8 bits)

Faixas: `int8_t` **−128 … 127**; `int16_t` −32 768 … 32 767; `int32_t` −2 147 483 648 … 2 147 483 647. Há um negativo a mais que positivos, porque o zero ocupa um lugar no lado "positivo".
- **Para obter −x:** inverta todos os bits e some 1. **Exemplo 1:** −45 em 8 bits. 45 = 0010 1101; invertido: 1101 0010; +1: **1101 0011 = 0xD3**. Conferindo pelo peso negativo: −128 + 64 + 16 + 2 + 1 = −45 ✔.
- **Ler um byte com sinal:** se o MSB é 0, é o valor normal; se é 1, valor = (sem sinal) − 256. **Exemplo 2:** 0xF6 = 246 sem sinal ⇒ 246 − 256 = **−10** como `int8_t`. Para 16 bits, subtraia 65 536: 0xFF38 = 65 336 − 65 536 = **−200**.
- **O mesmo byte, dois significados:** 0xFF é 255 em `uint8_t` e −1 em `int8_t`. Os bits não sabem o tipo — quem decide é o seu código (lembre o M0.6.T01: `(uint8_t)-1` vale 255).
- **Extensão de sinal:** para levar um `int8_t` a 16 bits, copie o MSB para os bits novos: 0xF6 (−10) vira 0xFFF6 (ainda −10). Preencher com zeros daria 0x00F6 = 246 — defeito clássico ao montar um `int16_t` a partir de dois bytes de um sensor.
- Outras representações (só para reconhecer): sinal-magnitude (MSB é o sinal, resto é o módulo: −45 = 1010 1101) e complemento de 1 (só inverter: −45 = 1101 0010). Ambas têm dois zeros; por isso o complemento de 2 venceu.

**6. Soma, subtração, carry e overflow.** Some coluna a coluna, com vai-um: 1 + 1 = 10₂ (escreve 0, vai 1). Subtração em complemento de 2 é **somar o negativo**: a − b = a + (~b + 1). Dois indicadores (os *flags* C e V do processador):
- **Carry (C):** saiu um vai-um do MSB. Para números **sem sinal**, significa que o resultado não coube (estouro sem sinal).
- **Overflow (V):** o resultado **com sinal** está errado. Acontece só quando se somam dois números de mesmo sinal e o resultado tem o sinal oposto.

**Exemplo 3:** 100 + 50 em 8 bits: 0110 0100 + 0011 0010 = **1001 0110 = 0x96**. Sem sinal: 150, correto, C = 0. Com sinal: dois positivos deram MSB = 1 (−106): **V = 1**, overflow.
**Exemplo 4:** 0xF0 + 0x20 = 1 0001 0000: o resultado de 8 bits é 0x10, C = 1. Sem sinal: 240 + 32 = 272 não cabe (estouro). Com sinal: −16 + 32 = 16, correto, V = 0.

**7. Do número cru à grandeza física.**
- **ADC de n bits:** V = N · Vref / 2ⁿ (convenção mais comum nos datasheets; alguns usam 2ⁿ − 1, e a diferença é de 1 LSB). A resolução (1 LSB) é Vref/2ⁿ. **Exemplo 5:** ADC de 12 bits, Vref = 3,3 V: 1 LSB = 3,3/4096 = 0,806 mV; leitura 1000 ⇒ 1000 × 0,806 mV = **0,806 V**.
- **Campos de registrador:** extraia o campo com deslocamento e máscara (M0.6.T05) e aplique a escala do datasheet. Ex.: um sensor que entrega temperatura em `int16_t` com 1 LSB = 0,01 °C: o valor 0xFF38 = −200 ⇒ **−2,00 °C**.
- **Ponto fixo (formato Q):** inteiro com uma vírgula "imaginária". Num Qm.n, valor = inteiro / 2ⁿ. Q8.8 (16 bits): 0x0180 = 384/256 = **1,5**. Q15 (Q1.15, `int16_t` de −1 a quase +1, usado em DSP e áudio): 0x4000 = 16 384/32 768 = **0,5**; 0x8000 = −1. Permite contas "com fração" num MCU sem FPU usando só inteiros.
- **BCD** (*binary-coded decimal*): cada dígito decimal num nibble. Relógios RTC guardam segundos assim: o registrador 0x59 significa **59 segundos** (e não 89). Conversão: dezena = valor >> 4, unidade = valor & 0x0F, resultado = 10·dezena + unidade.

## Pratique
Confira tudo em Python: `bin(45)`, `hex(182)`, `int('b6', 16)`, `int('10110110', 2)`, e para com sinal `(x ^ 0x80) - 0x80`.
1. Converta para decimal: 1110₂, 1000 0001₂, 0xFF, 0x1F4, 0o17.
2. Converta 200 e 1023 para binário e para hexadecimal.
3. Converta 0,375 e 2,8125 para binário.
4. Quantos bits são necessários para contar de 0 a 1000? E para um ADC distinguir 1 mV numa faixa de 0 a 3,3 V?
5. Escreva −1, −2, −100 e −128 em complemento de 2 de 8 bits (binário e hex).
6. Interprete como `int8_t`: 0x7F, 0x80, 0x9C, 0xFE.
7. Faça a extensão de sinal de 0x9C para 16 bits e confira que o valor não mudou.
8. Some em 8 bits e dê os flags C e V: 0x7F + 0x01; 0xFF + 0x01; 0x80 + 0x80; 0x40 + 0x30.
9. Calcule 0x25 − 0x40 em 8 bits (como soma do complemento de 2). Qual o resultado sem sinal e com sinal?
10. Um ADC de 10 bits com Vref = 5 V leu 512. Qual a tensão? Qual o tamanho de 1 LSB?
11. Um acelerômetro entrega `int16_t` com 1 LSB = 1/16 384 g. Que aceleração corresponde a 0xC000?
12. Converta 0x2400 em Q8.8 e 0xE000 em Q15.
13. Um RTC devolve 0x23 no registrador de horas (BCD, formato 24 h). Que horas são? Escreva a função em C que converte BCD para binário.

## Armadilhas comuns
- Ler os restos das divisões sucessivas de cima para baixo (inverte o número).
- Agrupar os bits em hex a partir da esquerda quando o total não é múltiplo de 4 (sempre a partir da direita).
- Achar que o MSB é "só o sinal" e ler o resto como módulo (isso é sinal-magnitude, não complemento de 2): 0xF6 não é −118, é −10.
- Esquecer o "+1" do complemento de 2 (−45 vira 0xD2 em vez de 0xD3).
- Montar um `int16_t` de dois bytes sem extensão de sinal, ou guardando o resultado num `uint16_t`, e transformar −2 °C em 653 °C.
- Confundir carry com overflow: carry é estouro **sem sinal**; overflow é estouro **com sinal**.
- Tratar um registrador BCD como binário puro (0x59 → 89 s).
- Usar 2ⁿ − 1 ou 2ⁿ na conversão do ADC sem olhar o datasheet.
